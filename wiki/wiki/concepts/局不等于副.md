# 局 ≠ 副（数据口径核心）

## 核心结论

> **数据解读的核心口径问题，已定音但需持续强调。**

### 一局 = 8 条 record

```
1 局（game）
├── 甲方玩家1 (1 副)
├── 甲方玩家2 (1 副)
├── 乙方玩家1 (1 副)
└── 乙方玩家2 (1 副)
    [共计 4 玩家 × 2 副 = 8 条 record]（双上计分王特有结构）
```

## 各字段含义

| 字段 | 含义 | 单位 |
|------|------|------|
| `game_records` 中每条 JSON | 1 副 | 副 |
| `completed_games` | 总局数 | 局 |
| `victoryNum[0]` | 主队本局累计升级 | 级 |
| `victoryNum[1]` | 客队本局累计升级 | 级 |

⚠️ **陷阱**：`victoryNum[0] + victoryNum[1]` **不是**胜局数，是本局升级总数（A 打过 3、J、Q 升 3 级）。

## 常见误读

❌ 把 `victoryNum[0] == 3` 当作"主队赢 3 局"
✅ `victoryNum[0] == 3` 表示主队**从 2 升到 A**（即升 3 级），仅 1 局

❌ 8 条 record 当 8 局
✅ 8 条 record 是 1 局的全部视角（4 玩家 × 2 副）

## P1 校验

```
[0] + [1] == batch_games     // 两队升级总和 = 总局数（双方各升则为升级抵消）
[0] == [2]                  // L1 L3 一致
[1] == [3]                  // L2 L4 一致
```

详见 [[batch-evaluation]] 的 L1-L4 校验层级。

## 双上计分王特有结构

- 比赛名「双上」= 双方各升 / 互相制衡
- 因此 `victoryNum[0]` 与 `victoryNum[1]` 不互斥（可以同时非零）
- 一局可能**无胜方**（双方都未升 A）
```
