# 手牌 还贡/进贡后的变化

## 一、Wiki 中的相关线索

用户问"手牌在**还贡/进贡后**的变化"，Wiki 中没有专门讨论"进贡/还贡"机制对手牌影响的页面，但有两条相关线索：

### 线索 1：HandCardOrganizer（手牌整理器）[2]

进/还贡本质上是**手牌集合的增减**（从对手处获得一张牌 / 向对手交出一张牌）。HandCardOrganizer 在每次拿牌后调用：

| 职责 | 进/还贡后 |
|------|-----------|
| 区域划分 | 27 张重划（+1 进贡所得或 -1 还贡给出） |
| 物理重排序 | 输出有序 27 张 |
| 区域索引 | 每张牌生成区域 ID |
| 区域大小 | 各区域牌数变化 |

> 设计动机：模拟"人类整理手牌"——进/还贡改变了手牌构成，必须**重新分组**才能给下游模块（GroupingEngine、MemoryTracker）正确输入。

### 线索 2：记牌/进贡回贡 [10]

记牌维度 §十五 提到：

> **进贡/回贡**：首局前需特别记忆大王级牌归属

但这是**记牌层面**的要求——AI 需知道大王等关键牌在谁手里，而非讨论手牌本身的变化机制。

## 三、间接推断（需源码验证）

基于现有 Wiki 内容可以推测：

1. **进贡（收到牌）**：手牌 27 → 27（-1 +1），需重新走 `HandCardOrganizer` → `GroupingEngine`
2. **还贡（交出牌）**：手牌 27 → 26（同上需重新组牌评估）
3. **进/还贡后的牌力**：`_score_power()` 5 维（炸弹 0.3 / 手数 0.3 / 回收 0.1 / 灵活 0.1 / 去单化 0.2）[1][7] 需重新计算
4. **进/还贡后的手数定义**：仍为"27 张拆分完后形成的牌型组数"[1]，但此时实际可能不足 27 张
