# 掼蛋AI算法对抗平台使用说明 · 进贡还贡与手牌变化

## 一、进贡 / 还贡 / 抗贡 规则

| 环节 | 触发条件 | 操作方 | 牌 |
|------|----------|--------|------|
| **进贡** | 双下（对家分获 3/4 名）| 末游→头游、三游→二游 | 进贡方**最大牌**（逢人配可跳） |
| **还贡** | 受贡者出牌前 | 受贡者→进贡方 | **≤10 任意牌**（不得大于进贡牌），**得还回不同牌型类别** |
| **抗贡** | 进贡方持双王 | — | 本圈无进无还 |

**进/还贡发生在下副发牌之前**[{3}][{7}]。

## 二、平台 stage 序列

```
beginning
  └─ [tribute]?        ← 进贡
  └─ [anti-tribute]?   ← 抗贡
  └─ [back]?           ← 还贡
  └─ play              ← 出牌阶段
  └─ episodeOver       ← 一副结束
```

## 三、领出规则（与进贡耦合）

| 场景 | 领出者 |
|------|--------|
| 第一副 | 服务器决定 |
| 第二副起（普通进贡）| **进贡给上游者**领出 |
| 双下 | 三游领出 |
| 抗贡 | 上游（头游）领出 |
| 普通升级 | 上游（头游）领出 |

## 四、手牌在进/还贡后的变化

进/还贡本质是**手牌集合的增减**（−1 给出 / +1 收到），从 27 张变为 27 张（或 26 张还贡未补时）。需要重走组牌流程：

| 步骤 | 处理 |
|------|------|
| 1. HandCardOrganizer | 重新物理重排序、划分区域 |
| 2. GroupingEngine | 重新枚举组法 |
| 3. _score_power() | 重算 5 维牌力（炸弹 0.3 / 手数 0.3 / 回收 0.1 / 灵活 0.1 / 去单化 0.2）[{1}] |

## 五、首出高压线（进贡方约束）[{2}][{4}]

进贡方领出后**最易踩坑**，3 条 P0 高压线：

| 原则 | 含义 |
|------|------|
| **P-H01 / P-G04** | **进贡慎出单**（避免打小单送牌权）|
| **P-H02** | **火不打四**（4 头炸慎首发）|
| **P-H05** | **顺子慎始发** |

> ⚠️ P-H01 ≡ P-G04：双编号冗余备份。

## 六、平台消息（v1006 protocol）

- **进贡通知**：S→C 方向，触发进/还/抗贡
- **actIndex 协议**：客户端回传 actIndex 而非牌型字符串（PASS 为独立项）
- ⚠️ 字段契约仍**未文档化为正式 RFC**（TENSION-5）——平台层系统性风险

**一句话总结**：进/还贡改变手牌集合（27 张微调）→ 触发 HandCardOrganizer 重排 → 重算 5 维牌力 → 进贡方领出受 3 条 P0 高压线约束（进贡慎出单 / 火不打四 / 顺子慎始发）。
