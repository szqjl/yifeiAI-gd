# 还贡服务器消息 / 进贡 protocol / 贡牌

## 一、进贡流程概览（06 完整对局流程）[{2}]

平台 stage 序列中的进贡/还贡环节：

```
beginning
  └─ [tribute]?        ← 进贡阶段
  └─ [anti-tribute]?   ← 抗贡阶段
  └─ [back]?           ← 还贡阶段
  └─ play              ← 出牌阶段
```

## 二、进贡 / 还贡 / 抗贡 规则[{2}][{6}]

| 环节 | 触发条件 | 进贡方 | 贡牌 |
|------|----------|--------|------|
| **进贡** | 双下（对家分别 3/4 名）| 末游→头游、三游→二游 | 进贡方**最大牌**（逢人配可跳） |
| **还贡** | 受贡者出牌前 | 受贡者→进贡方 | **≤10 的任意牌**（不得大于进贡牌），**得还回不同的牌型类别** |
| **抗贡** | 进贡方持有双王 | — | 抗贡成功，本圈无进贡无还贡 |

**进/还贡发生在下副发牌之前**[{6}]。

## 三、领出规则（与进贡紧密耦合）[{3}][{5}]

| 场景 | 领出者 |
|------|--------|
| 第一副 | 服务器决定 |
| 第二副起（普通进贡）| **进贡给上游者（受贡者）**领出 |
| 双下 | 三游领出 |
| 抗贡 | 上游（头游）领出 |
| 普通升级 | 上游（头游）领出 |

## 四、平台消息格式（v1006 protocol）[{7}][{9}]

### 关键消息类型

| 消息 | 方向 | 说明 |
|------|------|------|
| **进贡通知** | S→C | 进贡 / 还贡 / 抗贡 |

### actIndex 协议（核心）
- 服务端下发 `actionList`（合法动作 JSON 数组）
- 客户端**回传 actIndex（下标）**而非牌型字符串
- PASS 是 actionList 中的独立项

### 字段契约（lalala 标杆）[{7}]
- ✅ `actIndex` — 出牌动作索引（**全客户端必须一致**）
- ❌ ~~`actionIndex`~~ — 已被 GUA-062 fix 弃用

> ⚠️ 字段名不一致 → server 端 `KeyError` → 客户端失联。**未文档化为正式 RFC**——是系统性风险（TENSION-5）。

## 五、首出 P0 高压线（进贡方的策略约束）[{1}][{3}][{8}]

进贡方领出后打什么牌，受三条 P0 高压线约束：

| 原则 | 含义 | M3 状态 |
|------|------|---------|
| **P-H01 / P-G04** | **进贡慎出单**（避免打小单送牌权）| ✅ P0 实施 |
| **P-H02** | 火不打四（4 头炸慎首发）| ✅ P0 实施 |
| **P-H05** | 顺子慎始发 | ✅ P0 实施 |

> ⚠️ **P-H01 ≡ P-G04**：H（高压线）与 G（进贡）维度的**双编号冗余备份**——确保从任一入口都能追溯。

## 六、V7 引擎对进贡的处理差异[{1}][{8}]

| 维度 | M3 | V7 |
|------|-----|-----|
| P-H01/02/05 | ✅ 已实施 | ⚠️ 融入 `_score_power()` 5 维评分，非显式列出 |
| 首发 +1 分 | 未纳入 | **未实现**（口诀建议但评分函数未纳入）|
| 进贡 Guard | 内置决策引擎 | R10 领出不炸（GUA-066）/ R07~09 队友保护（GUA-065）|
