## 2. 双重数据通道架构

```
┌──────────────────────────────────────────────────────────┐
│              掼蛋服务器 guandan_offline_v1006.exe         │
│                                                          │
│  ┌─────────────────┐       ┌─────────────────────────┐   │
│  │ WebSocket 通知   │       │ stdout (PIPE)           │   │
│  │ gameResult:      │       │ "达到设定场次,          │   │
│  │ final/victoryNum │       │  其中0号位胜利X次..."   │   │
│  └────────┬────────┘       └───────────┬─────────────┘   │
└───────────┼────────────────────────────┼─────────────────┘
            │                            │
   ┌────────▼────────┐          ┌────────▼──────────────┐
   │ 通道 A (客户端)   │          │ 通道 B (executor)      │
   │ yf1_m3.py       │          │ executor.py            │
   │                 │          │                        │
   │ process_message │          │ read_stdout() 后台线程  │
   │ → gameResult    │          │ → output_queue         │
   │ → extract_vn()  │          │ → self.logger.info(    │
   │ → validate_vn() │          │     "[服务器] {line}") │
   │                 │          │ → server_output 列表   │
   └───┬────────┬────┘          └───────────┬────────────┘
       │        │                           │
       ▼        ▼                           ▼
  ┌────────┐ ┌──────────┐    ┌──────────────────────────┐
  │latest_ │ │game_     │    │ logs/m3_vs_lalala_*.log  │
  │victory │ │records/  │    │ (所有 stdout 行逐行落盘) │
  │_num    │ │*.json    │    │                          │
  │.json   │ │← 被误清!  │    │ game_scores.json         │
  │(覆盖)  │ │          │    │ (score tracker, 覆盖)    │
  └────────┘ └──────────┘    └──────────────────────────┘
```

### 通道对比

| 维度 | 通道 A (WebSocket) | 通道 B (stdout) |
|------|-------------------|-----------------|
| 数据源 | 客户端收到的 `gameResult` 通知 | 服务端进程 stdout |
| 写入者 | `yf1_m3.py`（Player 0） | `executor.py`（主线） |
| 落盘文件 | `latest_victory_num.json` + `game_records/` | `logs/m3_vs_lalala_*.log` |
| 写入模式 | json: 覆盖；records: 追加 | 追加（FileHandler） |
| 粒度 | json: 最后一批；records: 每副 | 每行 stdout |
| 生命周期绑定 | 与客户端进程同生命周期 | 与 executor 进程同生命周期（独立于客户端） |
| 丢失风险 | `game_records/` 可被误删 | `logs/` 可被误删（但通常不会） |

## 4. victoryNum 四层写入清单

| 序号 | 文件 | 写入者 | 粒度 | 覆盖/追加 | 丢失风险 |
|------|------|--------|------|-----------|----------|
| 1 | `latest_victory_num.json` | `yf1_m3.py` | 最后一批 | **覆盖** | 低（单文件） |
| 2 | `logs/m3_vs_lalala_*.log` | `executor.py`（stdout 镜像） | 全部批次 | **追加** | 极低 |
| 3 | `game_scores.json` | `executor.py`（score tracker） | 全部批次 | **覆盖** | 低 |
| 4 | `game_records/*.json` | `yf1_m3.py`（game_recorder） | 每副 | **追加** | **中**（文件多，易被误清） |

**冗余度**：即使第 4 层全丢（如本次事件），从第 2 层日志用 `grep` 搜关键行即可完整恢复。

## 5. 恢复操作步骤（标准流程）

### 5.1 快速自检：数据还在不在

```powershell
# 检查 game_records 数量
(Get-ChildItem game_records -File).Count

# 检查最新 vitctoryNum 快照
Get-Content batch_executor/latest_victory_num.json | python -c "import sys,json; d=json.load(sys.stdin); print(d.get('victoryNum'), d.get('vn_source'))"

# 检查日志文件
Get-ChildItem logs -Name -Filter "m3_vs_lalala_*.log" | Sort-Object -Descending
```

### 5.2 三步恢复 victoryNum

**第 1 步**：读最后一批快照

```powershell
Get-Content batch_executor/latest_victory_num.json
```

得到最后一批的 `victoryNum` + `server_vn_raw`。

**第 2 步**：搜日志中全部批末 vn

```powershell
Select-String -Path "logs/m3_vs_lalala_*.log" -Pattern "批末 victoryNum 校验通过|批末对账" | ForEach-Object { $_.Line }
```

日志中每批结束都会输出类似：
```
批末 victoryNum 校验通过: vn=[3, 0, 3, 0], batch_games=3, Team0=3 Team1=0
批末对账：采用 vn=[3, 0, 3, 0] (vn_source=server)，服务器 RAW=[3, 0, 3, 0]
```

**第 3 步**：交叉计算队胜率

```
M3 队胜 = sum(各批 victoryNum[0])  // 注意：M3 队 = pos 0 + pos 2
对手队胜 = sum(各批 victoryNum[1])
队胜率 = M3 队胜 / 总局数
```

### 5.3 备选路径

如果第 2 步搜不到 `批末` 日志行，用服务端 stdout 原文：

```powershell
Select-String -Path "logs/m3_vs_lalala_*.log" -Pattern "达到设定场次" | ForEach-Object { $_.Line }
```

从 `0号位胜利X次，1号位胜利Y次，2号位胜利Z次，3号位胜利W次` 手动拼出 `victoryNum = [X, Y, Z, W]`。

## 6. 为什么这个设计是安全的

1. **stdout 是服务端的唯一输出口**：服务端只能通过 stdout 报告战绩，这条路径不可绕过。
2. **日志是 executor 的副作用**：`self.logger.info()` 不是为「数据恢复」设计的，但 FileHandler 的持久化使 stdout 完整留痕。
3. **通道 A 和 B 互相独立**：即使客户端 WebSocket 断连（通道 A 断），stdout 照常输出（通道 B 不断）。
4. **追加模式杜绝覆盖**：日志用 `FileHandler` 追加写入，不会像 `latest_victory_num.json` 被每批覆盖。

**唯一真正的数据丢失场景**：`game_records/` 和 `logs/` 同时被删——但这几乎不会发生，因为 `logs/` 通常不被视为「临时数据」。

| 建议 | 优先级 | 说明 |
|------|--------|------|
