## 3. 根因 A 三子根因拆解

### 3.1 A1：`_game_save` 非原子写（**主因**）

**代码**：
```python
# batch_executor/client_ready.py:231
def _game_save(data: Dict[str, dict]) -> None:
    GAME_READY_FILE.parent.mkdir(parents=True, exist_ok=True)
    GAME_READY_FILE.write_text(
        json.dumps(data, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )
```

**问题**：
- `Path.write_text` = `open(WRITE) + write + close` —— **Windows 下非原子**
- 4 进程并发 `_game_save` 会产生 **中间态 JSON 损坏**
- 4 进程并发 `_game_load` + `_game_save`（非 read-modify-write 原子）—— **read 后被其他进程覆盖**

**Linux/WSL 复现**（50 次循环放大 race）：
```
[c2] error: Expecting ',' delimiter: line 1 column 112 (char 111)
result keys: ['c1', 'c2', 'c4', 'c3']
total entries: 4
```

**4 进程并发，1 进程 JSON 解析错误**（说明中间态确实存在）。**Windows 下更严重**——文件锁、AV 扫描、索引服务都可能打断写入。

**真实 1 次调用下，4 席中 1 席丢失 entry 的概率** ≈ 25%（4 选 1 输 race condition）。

### 3.2 A2：`mark_game_ready` 无 try/except

**代码**：
```python
# batch_executor/client_ready.py:52
def mark_game_ready(client_id: str) -> None:
    """客户端收到首条游戏消息后登记（游戏已开局，客户端可正常决策）。"""
    data = _game_load()
    data[client_id] = {"ready": True, "timestamp": _now_iso()}
    _game_save(data)  # ← 无 try/except
```

**问题**：
- `_game_save` 抛错（如 OSError 文件锁拒绝、PermissionError、JSON 序列化错）会**冒泡到 `asyncio.to_thread` 任务**
- Python asyncio 默认**不打印未捕获异常**（task exception never retrieved）
- **失败完全静默，无任何日志**

**websocket_manager.py:271-285 调用上下文**：
```python
try:
    data = json.loads(message)
    if not self._game_ready_marked:
        self._game_ready_marked = True
        await asyncio.to_thread(mark_game_ready, self.user_info)  # ← 异常逃逸
        self.logger.info(f"✓ 首条消息到达，game_ready: {self.user_info}")
    ...
except json.JSONDecodeError as e:
    ...
except Exception as e:
    ...
```

`mark_game_ready` 在 try 块内，但 try 块只 catch `json.JSONDecodeError` 和外层 `Exception` —— **`OSError`/`PermissionError` 应该会被外层 Exception catch 到**。但 `asyncio.to_thread` 的异常**默认不传播到调用方任务**（除非用 `await task`）。

### 3.3 A3：`wait_for_all_clients_game_ready` 期望 4 entry

**代码**：
```python
# batch_executor/client_ready.py:180
def wait_for_all_clients_game_ready(
    expected_ids: Iterable[str],
    *,
    timeout: float = 90.0,
    poll_interval: float = 1.0,
) -> bool:
    expected = set(expected_ids)
    deadline = time.monotonic() + timeout
    while time.monotonic() < deadline:
        ready = _game_load()  # 读 game_ready.json
        if expected.issubset(ready.keys()):  # ← 必须 4 entry 全到
            return True
        time.sleep(poll_interval)
    return False
```

**`executor.py:514` 调 `timeout=60`**：4 entry 缺 1 → 60s 超时

**3 子根因链**：
- A1 写盘 race condition → 1 席 entry 丢失
- A2 异常静默 → 不知道哪席丢
- A3 期望 4 entry → 差 1 等 60s

## 5. 修复方向

### 5.1 修 A1（主因）：原子写

**方案 1**：用 `temp + rename`（Linux 原子，Windows 也基本原子）：
```python
def _game_save(data: Dict[str, dict]) -> None:
    GAME_READY_FILE.parent.mkdir(parents=True, exist_ok=True)
    tmp = GAME_READY_FILE.with_suffix('.tmp')
    tmp.write_text(json.dumps(data, ensure_ascii=False, indent=2), encoding="utf-8")
    tmp.replace(GAME_READY_FILE)  # ← 原子
```

**方案 2**：用 `fcntl`/`msvcrt` 文件锁（跨平台，但增加复杂度）

**方案 3**：改用 SQLite 替代 JSON（4 进程并发写，SQLite 支持）

**推荐方案 1**（最小改动，向后兼容）

### 5.2 修 A2：异常日志

```python
def mark_game_ready(client_id: str) -> None:
    """客户端收到首条游戏消息后登记（游戏已开局，客户端可正常决策）。"""
    try:
        data = _game_load()
        data[client_id] = {"ready": True, "timestamp": _now_iso()}
        _game_save(data)
    except Exception as e:
        # 至少让异常可见
        import logging
        logging.getLogger("client_ready").error(
            f"mark_game_ready({client_id}) 失败: {e}", exc_info=True
        )
        raise
```

**配套**：在 `asyncio.to_thread` 改成 `await asyncio.to_thread(...)` 然后 `except Exception`。

**可选**：
- `wait_for_all_clients_game_ready` 改为"3/4 entry 也放行"（降级 25% 概率误关单）
- **不推荐**：会掩盖真实 1 席失联问题
- **推荐**：还是等 4 entry，但 A1+A2 修好后基本 100% 4 entry 都在

## 6. 教训（V 系列教训 V5 复发）

### 6.1 "无 try/except + asyncio 静默异常" 模式

之前 GUA-045 修过 `[None, None]` 问题，但**没修"异常被 asyncio 吞掉"**这个更深层 bug。  
V5 时代教训："**训练有'准确率'无'队胜率'**"——**只看 pass 不看 silent failure**。  
**V7 护栏**：**任何 `asyncio.to_thread` 调用必须有显式异常处理**——要么 caller `await + try/except`，要么被调函数内 try/except + logger。

### 6.2 "4 进程共享文件" 模式

`game_ready.json` 是 4 进程共享状态。**任何跨进程共享状态必须有原子写保护**——这是分布式系统基本要求。  
**V7 护栏**：**跨进程共享 JSON file 必须用 temp+rename 原子写**——任何 `Path.write_text` 直写都要 review。

### 6.3 "实测验证" 不可省

Trae 在 GUA-048 误关单（pytest pass 就 closed），**没实测 dump 延迟**。  
**V7 护栏**：**pytest pass ≠ 端到端 pass**——任何关单必须有**实测基线**对照（dump 延迟 / 队胜率 / decision 分布 / 关键文件 mtime）。

## 7. 复现实验记录

### 7.1 Linux/WSL 多线程 race 复现

**脚本**（已跑通）：
```python
import json, time, threading
from pathlib import Path

test_file = Path('/tmp/race_test/test.json')
test_file.write_text('{}')

def write_entry(client_id, delay=0):
    time.sleep(delay)
    for _ in range(50):
        try:
            data = json.loads(test_file.read_text())
            data[client_id] = {'ready': True, 'timestamp': time.time()}
            test_file.write_text(json.dumps(data, ensure_ascii=False))
        except Exception as e:
            print(f'[{client_id}] error: {e}')
            return

threads = [threading.Thread(target=write_entry, args=(f'c{i}', i*0.001)) for i in range(4)]
for t in threads: t.start()
for t in threads: t.join()
```

**结果**：
```
[c2] error: Expecting ',' delimiter: line 1 column 112 (char 111)
result keys: ['c1', 'c2', 'c4', 'c3']
total entries: 4
```

**结论**：**Linux 下 race condition 也会产生 JSON 损坏 + 解析错误**。Windows 下因文件锁/AV/索引服务更严重。
