# 掼蛋 AI 对基本规则（一）牌张 的体现情况

## 规则条文摘要

| 条文 | 内容 |
|------|------|
| 使用牌数 | 两副扑克牌，共 **108 张** |
| 牌面构成 | 每副 52 张（黑桃、红心、方块、梅花）+ 大小王各 2 张 = 108 张 |
| 分配方式 | 四位牌手，**每人 27 张** |
| 一副牌 | 从抓牌开始，到一方打完所有牌并决定胜负结束 |
| 一手牌 | 牌手一次打出的一组牌，可以是一张或多张 |
| 一圈牌 | 四位牌手依次出牌，直到无人出牌为止 |

---

## 代码中的体现

### 1. 使用牌数（108 张）、分配方式（每人 27 张）

**有体现，且被多处使用。**

- **27 张/人**：在通信、决策、训练中作为常量或默认值广泛出现。
  - 通信层：`len(hand_cards) == 27` 用于判断“是否收到完整初始手牌”（M1）；`public_info[i].get("rest", 27)`、`opponent_rest_cards = 27`、`teammate_rest_cards = 27` 等作为默认剩余牌数。
  - 决策层：`opponent_rest_cards_list = [27, 27, 27]`、`game_state.get("...", 27)` 等。
  - 记录/回放：`game_recorder` 中 `player_cards = {0: 27, 1: 27, 2: 27, 3: 27}`；`replay_game_interactive.py` 注释“每人 27 张，两副牌共 108 张”；`1312_replay_converter.py` 中 `expected_count = 27  # 掼蛋游戏每个玩家27张牌（108张/4人）`。
- **108 张**：在 RL/训练相关代码中有明确注释，例如 `rl_decision_engine.py`：“在掼蛋中，两副牌108张，每个玩家27张，可能拿到重复的卡牌（如两个D5）”。

结论：**“两副牌 108 张、每人 27 张”在代码中有共识并被使用**；108 更多在注释和语义里，27 是硬编码的默认/校验值。

---

### 2. 牌面构成（花色 + 大小王）

**有体现，但未集中写成“规则文档常量”。**

- **花色与牌面**：牌面用字符串表示，如 `S2`（黑桃2）、`H2`（红桃2）、`D2`、`C2`；`game_recorder` 中有 `suits = {'H': '红桃', 'S': '黑桃', 'C': '梅花', 'D': '方块', 'B': '小王', 'R': '大王'}`，用于展示/排序。
- **大小王**：通过 `RJ`/`BJ` 或 `R`/`B` 等标识在卡牌识别与决策逻辑中使用；级牌/红桃配（如 `H2`）在策略中单独处理。

结论：**牌面构成（四花色 + 大小王）在表示和策略里是具备的**，但没有单独一份“108 张 = 52×2 + 4 王”的常量定义。

---

### 3. 一副牌（从抓牌到一方打完决定胜负）

**有体现，以“一局”的生命周期存在。**

- `game_recorder.start_game()`：抓牌/发牌结束后开始记录，对应“一副牌开始”。
- `game_recorder.end_game(result)` / `gameResult`：一方打完并产生胜负后结束，对应“一副牌结束”。
- `current_game`、`game_count` 等用于区分“当前这一副”与多局。

结论：**“一副牌”对应代码里的一局 game（start_game → end_game）**，概念一致，未用“一副牌”三字命名。

---

### 4. 一手牌（一次打出的一组牌）

**有体现，对应 actionList 中的一个元素。**

- 服务器下发的 `actionList` 中，每个元素即“一手牌”：如 `['PASS', 'PASS', 'PASS']` 或 `['Single', 'R', ['HR']]`、`['Bomb', '8', ['S8','H8','C8','H2']]` 等。
- 决策引擎选一个下标即“选一手牌”；`curAction` 表示“当前轮中领先的一手牌”。

结论：**“一手牌” = actionList 的一项 = 一次出牌动作**，在协议与代码中一致，未单独写“一手牌”注释。

---

### 5. 一圈牌（四人依次出牌直到无人出牌）

**有体现，但未抽象成单独术语。**

- `curAction` + `greater_pos`：表示当前圈内“谁出的、出了什么”，即“当前圈的最大一手”。
- 决策请求的语义：轮到自己时，可选 PASS 或出一手牌；若四人皆 PASS，则一圈结束，下一轮由上一圈最大者或规则决定先出。
- 代码通过“收到 act 请求 → 选 PASS 或非 PASS”参与一圈，**一圈的起止主要由服务器驱动**，客户端没有显式变量“一圈”或“trick”。

结论：**“一圈牌”在逻辑上对应“从某人出牌到四人依次决策直至都 PASS”的一轮**，由 `curAction`/`greater_pos` 和 act 流程体现，未命名为“一圈”。

---

## 小结表

| 规则概念       | 代码中是否体现       | 说明 |
|----------------|----------------------|------|
| 108 张         | 是（注释与语义）     | 27×4 被广泛使用；108 在 RL/转换等处有注释。 |
| 每人 27 张     | 是（常量/默认值）    | 初始手牌校验、剩余牌数默认值、回放校验等。 |
| 牌面构成       | 是（牌面与花色映射） | S/H/C/D + 王，有展示用花色名；无集中“108=52×2+4 王”常量。 |
| 一副牌         | 是（一局生命周期）   | start_game → end_game / gameResult。 |
| 一手牌         | 是（actionList 元素）| 每次出牌 = 一个 action。 |
| 一圈牌         | 是（语义层面）       | curAction、greater_pos、act 流程；无“一圈”命名。 |

**总体结论**：掼蛋 AI（M 系列与 V 系列）在实现上**已经按这些基本规则在用**：牌数、每人 27 张、牌面与花色、一局起止、一手牌与一圈的语义都有对应。

- **常量模块**：`src/game_logic/guandan_constants.py`（`TOTAL_CARDS`、`CARDS_PER_PLAYER`、`DEFAULT_REST_CARDS`、花色常量等）。
