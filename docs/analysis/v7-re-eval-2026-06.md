## 0. 核心结论

**原方案对"随机应变"的核心问题覆盖不足。** 套路文档诊断了 6 个难点（随机应变/组牌/配合/残局/基本规律/出炸时机），原方案仅覆盖其中约 **25%**（6 个套路中 BC 起步部分有、LSTM 记忆部分有，局面信念、多模块、稠密 Reward、对手多样性四个完全缺失）。

最致命的缺口是**局面信念建模**——原方案从 Phase 0 到 Phase 3，所有 GUA 都在优化"更好的特征 + 更复杂的模型"，但从未引入"信念"这个中间变量。而套路文档 §1 明确指出：这才是标准 RL 在掼蛋上失败的根本原因。

## 1. 覆盖度对比：6 个"套路" vs 原方案 9 条 GUA

| 套路 | 原方案对应 | 覆盖度 | 缺口说明 |
|------|-----------|--------|---------|
| **① 局面信念建模** | ❌ 无任何 GUA 涉及 | **0%** | V7 四头网络（action_logits/WR/AV/LTR）假定 `P(action\|state)`；真正需要 `P(action\|state, belief)` |
| **② 多模块 specialized 评估** | ❌ 无（仅 NN + 规则 fallback） | **0%** | 套路文档建议拆为级牌/炸弹/对家配合/局面风险/贡牌判断 5 个专业模块 |

**总体覆盖度估计：~25%**（6 套路中有 1.5 个被部分覆盖）

## 2. 最关键缺口：局面信念建模（套路一）

### 2.1 问题诊断

套路文档 §1 核心诊断：

> 标准 RL：`特征 → 动作`（没有信念中间变量）
> 人类高手：`特征 + 局面信念 → 动作`

V7 当前的 `action_logits` + 后续的 DMC/PPO 都属于标准 RL —— 学的是 `P(action|state)`，而不是 `P(action|state, belief)`。

### 2.2 建议增补：局面信念向量

在 GUA-037a 静态特征（124 维）基础上，增建一个 8 维局面信念向量：

```python
state_belief = {
    'my_strength': float,           # 自己的牌力 0~1
    'partner_strength': float,       # 对家牌力 0~1
    'opponent_pressure': float,     # 对手压迫程度 0~1
    'level_progress': int,          # 级牌进度（打几）
    'trump_ready': bool,            # 我是否有级牌
    'bomb_count': int,              # 我方剩余炸弹数
    'opponent_bomb_risk': float,    # 推断对手有炸弹的概率
    'last_card_meaning': str,       # 上家出的牌传达什么信号
}
```

**位置**：叠加在 037a 静态特征之后（124 + 8 = 132 维），作为模型输入的一部分。

**理由**：只要 V7 仍然走 `P(action|state)` 路线，无论换什么模型架构（LSTM/Transformer/PPO），都逃不出套路文档诊断的"没有信念中间变量"问题。

## 3. 其他增补建议

### 3.1 稠密 Reward 信号（GUA-039a/039b 扩展）

在原方案 reward.py 基础上，增加 9 种中间 reward 信号：

| Reward 信号 | 触发条件 | 分值 |
|------------|----------|------|
| 出牌成功 | 出的牌型赢得这一墩 | +0.05 |
| 接风成功 | 接住了对家的风 | +0.1 |
| 掼蛋成功 | 打出级牌组合 | +0.3 |
| 级牌控制 | 打出当前级牌 | +0.2 |
| 配合成功 | 对家接住我出的牌型 | +0.1 |
| 送对家成功 | 对家因此走了一张 | +0.15 |
| 炸弹得失 | 放炸弹赢 / 被炸输 | ±0.5 |
| 本方升级 | 完成升级 | +2.0 |
| 对方升级 | 对方完成升级 | -1.0 |

**理由**：纯输赢 reward 太稀疏，导致信用分配困难（套路文档§4）。这 9 种信号覆盖了套路文档提出的全部中间信号。

### 3.2 记忆模块：108 张牌全量追踪（新 GUA 或 GUA-037b 扩展）

原方案 GUA-037b 的 LSTM 只编码出牌历史序列，没有真正的"记忆"：

```
记忆的内容（108 张牌全量追踪）：
├─ 已经出了什么牌（各花色、各点数）
├─ 对手出了哪些牌型（单张/对子/顺子/三带二/炸弹）
├─ 队友出了哪些牌型
├─ 各家还剩多少张牌
├─ 级牌还有哪些没出
```

排除法推断对手手牌（套路文档§3）：没出过的牌 + 对家没进贡的 ≈ 对手手牌。

### 3.3 对手多样性（GUA-039b 扩展）

- 保留历史 checkpoint 对手池
- 每次 self-play 从对手池随机选
- 用 lalala 硬编码 bot 当固定训练对手

**理由**：套路文档§5 指出，self-play 的策略多样性崩溃是 RL 第二轮开始退化的直接原因。

| 优先级 | 增补内容 | 对应 GUA | 工作量估 | 归属 phase |
|--------|---------|---------|---------|-----------|
| **P0** | 局面信念向量 8 维（my_strength/partner_strength/opponent_pressure 等） | GUA-037a 扩展 | +0.3 迭代 | Phase 1 |
| P1 | 稠密 Reward 信号（9 种中间 reward） | GUA-039a 扩展 | +0.2 迭代 | Phase 3 |

| **合计增补** | — | — | **+1.3 迭代** | 关键路径 +0.5 |

## 5. 增补后的关键路径变化

```
原关键路径（4–5 迭代）：
Phase 0 → GUA-037a(124维静态) → GUA-038(BC) → GUA-039a(DMC) → GUA-039b(PPO)

增补关键路径（~5.5 迭代）：
Phase 0 → GUA-037a(124维静态 + 8维信念) → GUA-037b/LSTM + 记忆追踪 → GUA-038(BC) → GUA-039a(DMC+稠密Reward) → GUA-039b(PPO+对手池)
```

增补后关键路径增加约 **0.5 迭代**（信念向量 + 记忆追踪），稠密 Reward 和对手池与现有 GUA 并行。

## 6. 风险补充

除了原方案 §5 已有的 10 条风险，增补以下 2 条：

| 风险 | 触发条件 | 预案 |
|------|---------|------|
| **局面信念向量无法收敛** | 8 维信念在训练中震荡/不收敛 | 降为 4 维核心信念（my_strength + partner_strength + level_progress + bomb_count） |
| **108 张牌追踪 Q 不够** | 完整追踪导致推理延迟 > 50ms | 降为仅追踪剩余牌数 + 已出炸弹数 + 级牌状态，不做精确手牌推断 |

---

## 7. 一句话总结

> **原方案做好了"特征工程 + 模型训练 + 评估"的基建，但缺少"信念 + 配合 + 多样化"这三个让 AI 学会随机应变的要素。新增 4 条建议（P0 信念向量 + P1 稠密 Reward + P1 记忆追踪 + P2 对手池）在 +1.3 迭代的总代价下，把覆盖度从 25% 提升到 ~70%。**
