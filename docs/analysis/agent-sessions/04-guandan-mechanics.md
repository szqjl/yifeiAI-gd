## 掼蛋的本质规则

### 三层游戏结构

| 层级 | 定义 | 升级条件 |
|------|------|---------|
| **一圈出牌** | 一人首发，三家跟压/过；连续三人过则结束 | 接风者下一圈首发；**一副内含多圈** |
| **一副牌** | 108 张发完、每人 27 张 →（第二副起：进贡→还贡或抗贡）→ 多圈出牌 → 四人完牌顺序确定 | 按名次（头游→二游→三游→末游）升级；决定下副进贡 |
| **一局** | 从 2 级打到 A 级 + 在 A 级双上 | 赢=升 3 级回 2；输=留在 2 |
| **队伍胜负** | 0+2 vs 1+3（座位绑定） | 取决于每一副的名次组合 |

### 升级规则（最关键）

```
本队名次组合        升级级数
双上(头+二)    →  升3级  (2→5)
头+三         →  升2级  (2→4)
头+末         →  升1级  (2→3)
无头游        →  不升   (保持)
```

**关键启示**：
- 不是"我赢就升"，而是"**我队双上才升**"
- 一副里，我是头游但队友末游 = **无升级，反而落后**
- A 级平局规则：连续 2 副未双上 → 降回 2 级重来

## M3 诊断中的 5 个致命 Bug

### Bug 1（致命）：action 下标错误 — 残局崩溃

```python
# lalala 正确
card_value_s2v[actionList[acti][1]]  # [1] = rank 字符串 '4'

# M3 错误
card_val[actionList[acti][-1]]        # [-1] = cards 列表 ['S4'] → TypeError!
```

**后果**：异常被静默捕获 → 默认 PASS → 残局关键机会被放弃

**启示**：hard-coded 的 index 错误可能比逻辑错误更致命

---

### Bug 2（策略缺失）：残局两手牌组合分析

**lalala 的绝招**（≤12 张时）：
```python
# 枚举所有"两手出完"的配对
for i in range(len(actionList)):
    for j in range(i+1, len(actionList)):
        if len(actionList[i][-1]) + len(actionList[j][-1]) == len(handcards):
            # 如果某两个动作合并后恰好等于现有手牌 → 记录
            twohand_candidatelist.append((i, j))
```

**M3 缺失**：完全没有这个逻辑 → 残局只会逐张出小牌 → 对手轻易压住 → 送牌给对方

**启示**：掼蛋的"残局"不是随机出牌，而是**规划两手如何恰好出完**。这是赢/输的分界。

---

### Bug 4（配合缺失）：无队友协作策略

**M3 的"配合"**：
```python
if (myPos+2)%4 == greaterPos:  # 仅判断：队友在控场吗？
    # 管队友的牌
else:
    # 不管
```

**缺失的**：
- ❌ 主动传牌给队友（分析队友可能有什么牌，主动出他能接的牌型）
- ❌ 压制对手为队友创造机会
- ❌ 队友 PASS 时的接管策略
- ❌ 针对对手剩牌数的分析

**真相**：22 副的完赛名次 `[3,1,0,2]` / `[1,3,0,2]` 显示 **lalala 包揽头游+二游，M3 总是三游+末游**

→ 不是"我们各自表现"，而是 **lalala 两人配合制造了头游+二游的局面**

---

### Bug 5（炸弹策略消极）：从不主动出炸弹

**M3 的炸弹规则**：
- 被动：`pass_num >= 5` 或 `my_pass_num >= 3` 才考虑
- 主动：优先出所有非炸弹，炸弹基本不用
- 对炸弹：仅 `cur_Bomb_num >= 3` 或对手 ≤18 张时才炸

**结果**：
- lalala 果断用炸弹终结
- M3 从未主动出炸弹抢控 → 失去主动权 → 被动挨打

**启示**：炸弹不是"防守牌"，而是"控场牌"。主动用炸弹抢控权，然后出你想出的牌型。

## M3 诊断的关键发现

### 完赛名次对比

**M3 vs lalala 的 22 副对局**：
```
[3, 1, 0, 2]  → lalala(P1+P3)获头游+二游，M3(P0+P2)获三游+末游
[1, 3, 0, 2]  → 同上，lalala 两人互换
...（所有 22 副皆然）
```

**结论**：
- lalala **在每一副都包揽头游+二游** = **系统性的配合**
- M3 **在每一副都是三游+末游** = **无配合能力**

### 对比 M1 的情况

从 ITERATIONS 可见：
```
M1 vs lalala，10 局对战
victoryNum = [0, 3, 0, 3]
→ M1 队（P0+P2）胜场 = 0
→ 对手队（P1+P3）胜场 = 3+

同样的"被完全压制"现象
```

## 从 M3 诊断学到的掼蛋本质

### 三个战略层次（由低到高）

#### Lv1：个别决策的正确性
```
这一副：该出什么牌？
✅ 能判断单张 > 对子 > 三张
✅ 能判断压住对手 vs PASS
✅ 能避免拆掉好顺子
```

**问题**：每一张牌的决策都对，但赢不了。

#### Lv2：队伍联动
```
这一副：我+队友的组合策略是什么？
- 我送一个牌型给队友，队友能接吗？
- 对手攻击队友时，我要不要拦截？
- 队友有残血，我是保护还是冲刺？
```

**M3/M2/M1 的问题**：
- M3 只检查"队友是否控场"，不主动传牌、不压制对手
- M1 也是配合太弱

#### Lv3：全局对抗
```
这一局：我们队能否从2打到A并双上？
- 这一副要争头游还是保存实力？
- 对方即将升A，要全力阻拦吗？
- 级数差距时，激进程度如何调整？
```

**M1/M2/M3 的问题**：完全没有这个层次的规划。

## M3 诊断中的"对手建模"问题

### lalala 的优势：完整状态追踪

```python
# lalala 维护完整的 State
class State:
    history = {
        '0': {'send': [], 'remain': 27},  # 对手P1出过什么
        '1': {'send': [], 'remain': 27},
        '2': {'send': [], 'remain': 27},  # 队友P2出过什么
        '3': {'send': [], 'remain': 27},
    }
    remain_cards = {...}  # 剩余牌库
```

### M3 的劣势：无对手建模

```python
# M3 的决策函数
def decide(message):
    # message 里有：
    # - handCards（我的手牌）
    # - actionList（合法动作）
    # - 其他玩家的剩牌数（numofnext, numofpre, etc.）
    # 
    # 缺失的：
    # - 对手的出牌历史 ❌
    # - 队友的出牌历史 ❌
    # - 总牌库的分布 ❌
    #
    # → 无法做"对手建模"
```

## M3 对 M1 的启示

### 现象对应

| M3 症状 | M1 症状 | 共同根因 |
|--------|--------|---------|
| 60% PASS | 50~60% PASS | 缺乏主动规划 |
| 出牌全无威胁 | 出小牌导致对手压住 | 无两手规划 |
| 无法双上 | 队胜率 0% | 无队伙配合 |
| 消极用炸弹 | 保守用炸弹 | 无主动抢控 |

### 改动优先级（从 M3 学到）

| P | Bug 修复 | 预期效果 |
|---|---------|---------|
| P0 | Bug 2（两手规划）+ Bug 4（队伙配合） | 残局 + 名次组合优化 |
| P1 | Bug 5（炸弹主动） | 控场能力 |
| P2 | Bug 1（index 修复） | 可用性 |

## 结论

M1/M2/M3 的共同问题：

1. **缺乏 Lv2 的队伙规划** → 无法双上
2. **缺乏完整的状态观察** → 无法对手建模
3. **缺乏残局两手规划** → 残局逐张输
4. **缺乏主动炸弹策略** → 失去控场

从 lalala 学来的最关键的东西**不是"if-then 规则"，而是"完整的状态观察"**。
