## 2. 五个判定点

### 判定点 1：是否可联系作者获取源码/数据集

| 维度 | 结论 |
|------|------|
| **开源状态** | 论文未提及开源计划，截止调研时未发现公开代码仓库 |
| **作者联系** | 可通过 `zhangsq@lamda.nju.edu.cn` 联系张绍群助理教授 |
| **数据集** | 论文使用了「专家-牌谱数据集」（标注的真实人类对局），未公开 |
| **可行性** | 可尝试联系作者询问开源意向，但预计获取概率较低（LAMDA 组历史工作多不公开源码） |
| **建议** | 不等待源码开源，基于论文描述独立实现 |

**结论**：论文未开源，可联系但不应依赖获取源码。

### 判定点 2：168 伪动作的完整定义是否可在论文中重建

| 项目 | 内容 |
|------|------|
| **论文描述** | 论文提出了基于领域知识库的动作约简机制，将原始动作空间（~10⁴量级）压缩到约 168 个「伪动作」（pseudo actions）|
| **约简方法** | ① 规则合规过滤（去除非法出牌）；② 牌型分类聚合（同牌型按点数聚合）；③ 基于知识库的剪枝（去除明显劣等动作） |
| **重建难度** | 中等偏高。论文给出了约简思路和框架，但未提供完整伪动作列表。实践中需要根据掼蛋规则自行实现牌型分类器 + 知识库剪枝规则 |
| **兼容性** | 168 伪动作的设计与 Danzero+ 架构的动作头输出层可以兼容——但需将 168 维伪动作映射到 V7 已有的 action_logits 输出 |

**结论**：可在论文描述基础上自行重建，但需要投入工程实现（估 0.2-0.3 迭代），设计需与 V7 现有四头网络结构适配。

### 判定点 3：ABLN（反绎学习网络）模型结构是否公开

| 项目 | 内容 |
|------|------|
| **公开程度** | 论文给出了 ABLN 的总体架构图和高层描述，但未提供网络具体结构（层数、维度、激活函数等） |
| **核心功能** | ABLN 利用对局信息和知识库推断其他玩家的手牌分布（推测剩余牌），为决策模型提供对手牌估计 |
| **可复现性** | 需要自行设计网络结构。可参考类似方向的工作（如 DeepStack 在德州扑克中的对手建模方法） |
| **替代方案** | V7 当前的四头网络已有 position_win_rate 头，可作为简化的对手建模替代方案，无需单独实现 ABLN |

**结论**：ABLN 结构不公开，但 V7 现有 `position_win_rate` 头已有部分对手建模能力，可暂不依赖 ABLN。

### 判定点 4：与 Danzero+ 架构的兼容性

| 维度 | 分析 |
|------|------|
| **V7 当前架构** | 四头网络：action_logits / position_win_rate / action_value / long_term_reward，特征 512 维 |
| **168 伪动作集成方式** | 若要在 V7 中应用 168 伪动作，需要：① 在特征提取后新增动作约简模块；② 将 action_logits 输出从当前设计改为 168 维；③ 在 Phase 3（DMC/PPO）阶段叠加 |
| **兼容性** | 基本兼容，但改造量中等。核心难点在于动作约简模块与已有决策流程的对接，而非网络结构本身 |
| **耦合度** | 低。168 伪动作可视为特征工程/动作空间处理的独立模块，与价值网络/策略网络解耦 |
| **建议** | 建议在 Phase 1（GUA-037a 静态特征完成）后评估集成成本，作为 Phase 2 的备选方案 |

**结论**：与 Danzero+ 架构兼容，可在 Phase 2/3 阶段叠加，但不应在 Phase 1 之前引入。

### 判定点 5：500 局 60.9% 胜率的对手画像

| 项目 | 内容 |
|------|------|
| **原文描述** | "在该数据集上的实验验证 ABL-GD 策略已达到了接近人类专家的水平"；"500 局 60.9%" |
| **对手分析** | 论文对手为「规则 AI 基线」（rule-based baseline），即类似 M1/M3 风格的硬编码规则引擎，并非与 lalala 或人类专家对战 |
| **对比 V7** | 当前 V7 对 lalala 胜率 0/12（0%），lalala 是较成熟的规则引擎。ABL-GD 对规则引擎 60.9% 的胜率说明：**规则引擎是可以被学习方法击败的** |
| **关键区别** | ABL-GD 采用了全套预监督训练 + 强化学习（300+ 轮自对弈），而 V7 当前仅加载了 BC 预训练模型（84.3% BC 分数），**缺乏 RL 微调** |

**结论**：60.9% 胜率是在规则引擎对手上取得的。V7 可通过补全 GUA-038（BC 热启动）+ GUA-039（RL 自对弈）达到类似水平，不一定需要照搬 168 伪动作方案。

## 3. 采纳决策

### 方案 A：采纳 ✗（弃用）

不建议在当前 V7 管线中采纳 168 伪动作方案，理由：

1. **未开源** — 关键实现细节（伪动作列表、ABLN 结构）不公开，自行复现投入产出比不高
2. **V7 已有替代路径** — GUA-037a（静态特征）+ GUA-038（BC 热启动）+ GUA-039（RL 自对弈）构成完整学习管线，168 伪动作对 Phase 1-3 的核心流程是「锦上添花」而非「雪中送炭」
3. **对手画像不对等** — 60.9% 是对规则引擎的胜率，V7 在同类场景（vs lalala 规则引擎）有潜力通过 GUA-038/039 达到类似水平

### 方案 B：备选 △（Phase 2 重新评估）

168 伪动作作为备选方案，在以下条件满足时重新评估：

1. GUA-038（BC 热启动）完成后 V7 胜率仍无明显改善（< 20% vs lalala）
2. 作者开源了 168 伪动作的实现
3. Phase 3 自对弈管线中发现动作空间过大导致训练不收敛

此时可将 168 伪动作动作约简模块集成到 Phase 3 的 Actor 中。

### 最终决策：**弃用**（作为备选跟踪）

---

## 4. 对 GUA-039a 设计的影响

由于采纳决策为 **弃用（备选）**，GUA-039a 自对弈的 Actor 特征输入层**无需**为 168 伪动作预留接口。但在设计动作输出层时，建议：

- 预留伪动作维度的可配置参数（便于未来切换 168 vs 当前方案）
- Phase 3 评估阶段对比测试「原始动作空间 vs 伪动作约简」的效果（若条件允许）
