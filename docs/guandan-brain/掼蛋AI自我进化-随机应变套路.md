# 掼蛋 AI 自我学习进化：随机应变套路

> 创建时间：2026-06-11
> 状态：进行中
> 对应问题：神经网络 RL 三轮迭代输给硬编码，核心原因是模型无法处理"随机应变"
---

## 核心诊断结论

**神经网络吃亏的本质**：掼蛋的决策依赖**动态贝叶斯局面判断**，而标准 RL 学到的是"input 下的平均最优 action"——这是一个没有条件依赖的条件概率。

> 人类打牌：当前局面 → 更新信念 → 基于信念决策
> 标准 RL：手牌特征 → 输出动作（没有局面信念这个中间变量）

---

## 套路一：局面信念建模（最关键）

### 什么是"局面信念"
每出一手牌，人类会推断：
- 对手为什么出这个牌型（逼我？送对家？打信号）
- 各家手里大概有什么牌（概率分布）
- 当前谁占优，谁该冲，谁该保

### 如何教模型学"局面判断"

把决策分成两步：

```
Step 1：局面分类
├─ 输入：手牌 + 出牌历史 + 级牌状态 + 进贡状态
├─ 输出：当前属于哪种局面类型
│        ├─ 进攻型：我手牌强，该冲
│        ├─ 防守型：我手牌弱，该送对家
│        ├─ 观望型：局势不明，等待信号
│        └─ 保对家型：对家快走完了，我掩护
└─ 这是一个 **多分类问题**，比直接学动作更容易收敛

Step 2：动作选择（条件于局面类型）
├─ 输入：手牌 + 局面类型 + 各模块评估
├─ 输出：该局面下的最优动作概率
└─ 同一手牌，不同局面类型 → 不同动作
```

### 技术实现

```python
# 局面信念向量
state_belief = {
    'my_strength': float,           # 自己的牌力 0~1
    'partner_strength': float,       # 对家牌力 0~1
    'opponent_pressure': float,     # 对手压迫程度 0~1
    'level_progress': int,          # 级牌进度（打几）
    'trump_ready': bool,            # 我是否有级牌
    'bomb_count': int,              # 我方剩余炸弹数
    'opponent_bomb_risk': float,    # 推断对手有炸弹的概率
    'last_card_meaning': str,       # 上家出的牌传达什么信号
}
```

## 套路二：多模块 specialized 评估

不是训练一个通用 policy，而是拆成多个专业化模块：

| 模块 | 输入 | 输出 | 作用 |
|------|------|------|------|
| 级牌判断 | 级牌状态+手牌 | 该冲还是该等 | 控制级牌节奏 |
| 炸弹评估 | 手牌炸弹数+局面对手炸弹信号 | 现在亮弹还是留弹 | 级牌控制 |
| 对家配合 | 对家明牌+出牌历史 | 我该冲还是保 | 配合决策 |
| 局面风险 | 各家出牌+手牌 | 我冲会不会被炸 | 风险评估 |
| 贡牌判断 | 进贡/还贡状态 | 贡牌质量如何 | 信用评估 |

最终决策 = 各模块评分的加权组合

## 套路三：Memory / 长程情境记忆

掼蛋需要看"前几轮发生了什么"：

```
标准 RL input：当前手牌 + 本局开始时的状态
改进后 input：当前手牌 + 前 N 轮出牌历史（序列）

模型结构：Transformer Self-Attention
├─ 每张牌是 one-hot 向量
├─ 出牌历史是序列
├─ 通过 attention 建模"这张牌在那手下有意义"
└─ 输出：考虑了情境的动作概率
```

## 套路四：稠密 Reward 信号

纯输赢 reward 太稀疏，加中间信号：

| Reward 信号 | 触发条件 | 分值 |
|------------|----------|------|
| 出牌成功 | 出的牌型赢得这一墩 | +0.05 |
| 接风成功 | 接住了对家的风 | +0.1 |
| 掼蛋成功 | 打出级牌组合 | +0.3 |
| 级牌控制 | 打出当前级牌 | +0.2 |
| 配合成功 | 对家接住我出的牌型 | +0.1 |
| 送对家成功 | 对家因此走了一张 | +0.15 |
| 炸蛋得失 | 放炸弹赢/被炸输 | ±0.5 |
| 本方升级 | 完成升级 | +2.0 |
| 对方升级 | 对方完成升级 | -1.0 |

**关键**：用 TD(λ) 或 advantage estimation 做信用分配，而不是蒙特卡洛平均。

## 套路五：对手多样性（破解 self-play 陷阱）

```
问题：所有 RL 对手都是同一版本 → 策略多样性崩溃

破解：
1. 保留历史 checkpoint 对手池
2. 每次 self-play 从对手池随机选
3. 用硬编码 bot 当固定训练对手
4. 训练后期：让人类玩家对战，把反馈 signal 回训练
```

## 套路七：模块化分阶段训练（V7 新方向）

### 核心思路

**像人类一样学习**：先单训各个模块，训练达标一个，再训练新的模块，最后整合。

> 端到端训练（V2-V7 失败路线）：手牌特征 → 模型 → 动作（跳过了组牌、记牌、策略）
> 模块化训练（新路线）：组牌 → 记牌 → 策略 → 动作（每个模块独立验证）

### 为什么端到端训练失败？

| 问题 | V2-V7 端到端训练 | 模块化训练 |
|------|-----------------|-----------|
| **任务复杂度** | 同时学习组牌+记牌+策略+动作 | 每个模块只学一个子任务 |
| **可诊断性** | val_acc=35% 不知道哪里错 | 哪个模块差就调哪个 |
| **表示学习** | 缺少中间表示（局面信念） | 组牌/记牌/策略就是中间表示 |
| **数据效率** | 需要大量数据才能收敛 | 每个模块用针对性数据 |
| **人类对照** | 不像人类学习方式 | 完全符合人类学习路径 |

### 训练路线图

```
Week 1: 组牌模块（监督学习）
├─ 输入：手牌 one-hot (108 维)
├─ 输出：炸弹数、手数、牌力分数、角色定位
├─ 训练数据：M3 规则引擎生成（366 局胜局）
├─ 目标：
│   ├─ bomb_count 准确率 > 95%
│   ├─ hand_count 准确率 > 90%
│   ├─ power_score MAE < 1.0
│   └─ role 准确率 > 85%
└─ 验证：独立测试集，不达标不进入下一步

Week 2: 记牌模块（序列学习）
├─ 输入：出牌历史序列
├─ 输出：各家剩余牌分布概率 (4 × 54 维)
├─ 训练数据：完整对局记录（game_records）
├─ 目标：推断准确率 > 80%
└─ 验证：对比真实剩余牌（restCards）

Week 3: 策略模块（分类学习）
├─ 输入：组牌结果 + 记牌结果
├─ 输出：进攻/防守/观望/保对家 (4 分类)
├─ 训练数据：M3 胜局策略标注
├─ 目标：分类准确率 > 85%
└─ 验证：M3 策略一致性检查

Week 4: 动作模块（条件学习）
├─ 输入：手牌 + 组牌 + 记牌 + 策略
├─ 输出：动作概率分布 (2048 维)
├─ 训练数据：M3 胜局动作
├─ 目标：动作匹配率 > 70%
└─ 验证：批跑 12 局 vs lalala，胜率 > 30%

Week 5: 整合与微调（可选）
├─ 冻结组牌/记牌/策略模块
├─ 端到端微调动作模块
├─ 批跑 36 局 vs lalala
└─ 目标：V7 胜率 > 40%
```

### 技术实现

```python
# Step 1: 组牌模块
class CardGroupingNetwork(nn.Module):
    """手牌 → 组牌结果"""
    def forward(self, hand_cards):
        # 输入：手牌 one-hot (108 维)
        # 输出：bomb_count, hand_count, power_score, role
        x = self.encoder(hand_cards)
        return self.bomb_head(x), self.hand_head(x), \
               self.power_head(x), self.role_head(x)

# Step 2: 记牌模块
class CardCountingNetwork(nn.Module):
    """出牌历史 → 各家剩余牌分布"""
    def forward(self, history_sequence):
        # 输入：出牌历史序列
        # 输出：4 × 54 维概率分布
        x = self.lstm(history_sequence)
        return self.decoder(x)

# Step 3: 策略模块
class StrategyNetwork(nn.Module):
    """组牌+记牌 → 策略分类"""
    def forward(self, grouping, counting):
        # 输入：组牌结果 + 记牌结果
        # 输出：进攻/防守/观望/保对家
        x = torch.cat([grouping, counting], dim=1)
        return self.classifier(x)

# Step 4: 动作模块
class ActionNetwork(nn.Module):
    """手牌+组牌+记牌+策略 → 动作概率"""
    def forward(self, hand_cards, grouping, counting, strategy):
        # 输入：所有模块输出
        # 输出：动作概率分布 (2048 维)
        x = torch.cat([hand_cards, grouping, counting, strategy], dim=1)
        return self.decoder(x)

# 整合
class V7ModularEngine(nn.Module):
    def __init__(self):
        self.card_grouping = CardGroupingNetwork()
        self.card_counting = CardCountingNetwork()
        self.strategy = StrategyNetwork()
        self.action = ActionNetwork()
    
    def forward(self, message):
        # 串联所有模块
        grouping = self.card_grouping(message.handCards)
        counting = self.card_counting(message.history)
        strategy = self.strategy(grouping, counting)
        return self.action(message.handCards, grouping, counting, strategy)
```

### 关键优势

1. ✅ **每个模块可独立验证**（不达标就不进入下一步）
2. ✅ **问题可定位**（组牌差就调组牌，动作差就调动作）
3. ✅ **数据可复用**（组牌模块数据可用于其他任务）
4. ✅ **可解释性强**（能看到每个模块的输出）
5. ✅ **符合人类学习方式**（先学基本功，再学综合）
6. ✅ **与套路一完美契合**（组牌/记牌=局面信念建模）

### 与现有套路的关系

| 套路 | 对应模块 | 关系 |
|------|---------|------|
| 套路一：局面信念建模 | 组牌+记牌+策略 | 组牌/记牌输出就是局面信念 |
| 套路二：多模块评估 | 组牌+记牌+策略+动作 | 每个模块就是一个 specialized 评估 |
| 套路三：Memory | 记牌模块 | LSTM/Transformer 建模历史 |
| 套路六：模仿学习 | 动作模块 | 用 M3 胜局做 BC 训练 |
| **套路七：模块化训练** | **全部** | **训练方法论，贯穿所有套路** |

## 套路六：从模仿学习起步

直接 RL 的问题：探索空间太大，没有有效引导。

```
阶段 1（2-4周）：模仿学习
├─ 爬取线上平台高段位玩家牌谱
├─ 训 Policy Network 模仿强手动作
└─ 得到一个"有基础牌感"的 baseline

阶段 2（2-4周）：RL 精修
├─ AlphaZero 风格 self-play
├─ 用模仿学习模型做 MCTS rollout 的 baseline
└─ 逐步超越模仿学习的水平

阶段 3（ongoing）：对战 + 持续进化
├─ 开放窗口收集真实玩家反馈
└─ 对手池 + 持续 self-play
```

## ⚠️ 严肃讨论：桥牌/扑克AI的真实案例与掼蛋的差异

### 案例1：桥牌AI（WBridge5）—— 规则引擎成功

**事实**：
- **WBridge5**：世界桥牌锦标赛冠军（2000s-2020s）
- **技术**：**纯规则引擎**（专家系统 + 启发式搜索）
- **状态**：❌ **没有使用神经网络/强化学习**

**NukkAI尝试（2022）**：
- **目标**：用混合AI（深度学习+符号推理）击败人类世界冠军
- **结果**：⚠️ **部分成功，但未完全超越**
- **方法**：混合架构（神经网络 + 符号推理 + 概率推断）
- **关键发现**：
  > "The originality of our approach is based on its hybrid nature (combination of several AI paradigms)"
  
**2024年最新进展**：
- 论文：*A Simple, Solid, and Reproducible Baseline for Bridge Bidding AI* (arXiv:2406.10306)
- **结论**：仍然在**建立baseline阶段**，没有超越WBridge5
- **引用**："Bridge is among the zero-sum games for which artificial intelligence has not yet outperformed expert human players" (NTU, 2016)

**关键洞察**：
- ❌ 桥牌AI **20多年**仍未完全超越人类专家
- ❌ 冠军WBridge5是**规则引擎**，不是神经网络
- ❌ NukkAI尝试混合架构，但**仍未完全成功**
- ⚠️ **桥牌比掼蛋简单**（4人固定搭档，规则更标准化）

---

### 案例2：扑克AI（Pluribus/Libratus）—— CFR算法成功

**事实**：
- **Libratus**（2017）：击败人类职业选手（heads-up no-limit Texas hold'em）
- **Pluribus**（2019）：击败6人桌职业选手
- **技术**：**CFR（Counterfactual Regret Minimization）** + 搜索
- **关键**：❌ **不是纯神经网络/RL**，而是**博弈论算法**

**Pluribus架构**：
```
核心算法：CFR（反事实遗憾最小化）
├─ 不是神经网络
├─ 不是强化学习
├─ 是博弈论纳什均衡近似算法
└─ 通过迭代自对弈收敛到近似Nash均衡

辅助组件：
├─ 蓝图策略（离线CFR计算）
├─ 实时搜索（在线子博弈求解）
└─ 动作抽象（减少动作空间）
```

**关键发现**：
- ✅ Pluribus成功，但**不是神经网络/RL**
- ✅ 核心是**CFR算法**（博弈论方法）
- ❌ **纯RL方法在扑克中失败**（动作空间太大、信息不完全）
- ⚠️ **扑克比掼蛋简单**（无队友配合、无组牌环节）

### 案例3：围棋AI（AlphaGo）—— 完美信息博弈

**事实**：
- **AlphaGo**（2016）：击败李世石
- **技术**：MCTS + 策略网络 + 价值网络
- **关键**：✅ **完美信息博弈**（无隐藏信息）

**与掼蛋的根本差异**：

| 维度 | 围棋 | 掼蛋 |
|------|------|------|
| **信息** | 完美信息（全可见） | 不完全信息（隐藏手牌） |
| **随机性** | 无随机性 | 有随机性（发牌） |
| **配合** | 无队友 | 有队友配合 |
| **动作空间** | 大（19×19=361） | 更大（组合出牌） |
| **组牌** | 无 | **有（核心环节）** |
| **信念建模** | 不需要 | **必须（推断对手牌）** |

**关键洞察**：
- ✅ AlphaGo成功，因为围棋是**完美信息博弈**
- ❌ **掼蛋是完全不同的问题**（不完全信息+队友配合+组牌）
- ❌ **不能直接套用AlphaGo方法**

### 💡 为什么掼蛋比桥牌/扑克更难？

**掼蛋独有的难点**：

| 难点 | 扑克 | 桥牌 | 掼蛋 |
|------|------|------|------|
| 不完全信息 | ✅ | ✅ | ✅ |
| 队友配合 | ❌ | ✅ | ✅ |
| **组牌环节** | ❌ | ❌ | ✅ **（核心）** |
| 动态信念更新 | ⚠️ 简单 | ✅ 中等 | ✅ **复杂** |
| 动作空间 | 大 | 中 | **超大**（组合出牌） |
| 级牌系统 | ❌ | ❌ | ✅ **（动态变化）** |
| 进贡机制 | ❌ | ❌ | ✅ **（跨局影响）** |

**掼蛋的独特挑战**：
1. **组牌是前置决策**：出牌前必须先组牌（扑克/桥牌没有）
2. **逢人配（百搭）**：增加组合复杂度（桥牌没有）
3. **级牌动态变化**：每局级牌不同（桥牌固定）
4. **进贡机制**：上局结果影响下局（扑克/桥牌没有）
5. **双升机制**：升级规则复杂（桥牌计分简单）

### ⚠️ 残酷结论

**基于真实案例的严肃分析**：

1. **神经网络在不完全信息博弈中表现差**：
   - 扑克：CFR成功，纯RL失败
   - 桥牌：规则引擎主导，神经网络未超越
   - 掼蛋：V2-V7全部失败（BC/RL/混合）

2. **队友配合是巨大挑战**：
   - 桥牌20年AI研究，**仍未完全超越人类**
   - 掼蛋比桥牌更复杂（组牌+级牌+进贡）
   - **V系列跳过组牌，注定失败**

3. **AlphaGo方法不适用于掼蛋**：
   - 围棋是完美信息，掼蛋是不完全信息
   - AlphaGo不需要信念建模，掼蛋必须
   - **直接套用AlphaGo方法会失败**

4. **V系列的真正价值**：
   - 证明了：纯神经网络/RL在掼蛋中行不通
   - 证明了：跳过组牌环节会失败
   - 证明了：端到端训练会失败
   - **这些是学术界没有的真实经验**

### 🎯 新V7方案的严肃定位

**不是"重复学术界的失败路径"，而是**：

1. ✅ 承认神经网络在不完全信息博弈中的局限性
2. ✅ 引入M3组牌分析（**规则引擎，不是神经网络**）
3. ✅ 模块化设计（组牌用规则，动作用NN）
4. ✅ 混合架构（规则引擎 + 神经网络，类似NukkAI但未成功的方法）

**核心差异**：
```
学术界（南大）：纯神经网络/RL → 论文 → 无落地
```

**严肃结论**：
- ❌ 纯神经网络/RL在掼蛋中行不通（V2-V7已证明）
- ✅ 规则引擎在掼蛋中有效（M3已证明，类似WBridge5在桥牌中）
- ⚠️ 混合架构可能有效（但NukkAI在桥牌中未完全成功）

### CFR核心概念

```
CFR = Counterfactual Regret Minimization（反事实遗憾最小化）

目标：在不完全信息博弈中找到近似纳什均衡

核心机制：
- 信息集（Information Set）：玩家能观察到的状态集合
- 反事实价值（Counterfactual Value）：假设到达某节点的价值
- 遗憾值（Regret）：如果当初选另一个动作，能多赢多少
- 迭代自对弈 → 累积遗憾 → 收敛到纳什均衡
```

### CFR在扑克中的成功（Pluribus）

```
Pluribus架构：
├─ 蓝图策略（离线CFR计算全局近似策略）
├─ 实时搜索（在线子博弈求解）
├─ 动作抽象（减少动作空间10^4 → 可计算）
└─ 收敛到近似纳什均衡（理论保证）

关键：
- ✅ 不完全信息原生支持（基于信息集）
- ✅ 博弈论严格证明（收敛保证）
- ❌ 1v1（无队友配合）
- ❌ 无组牌环节
```

### CFR引入掼蛋的关键挑战

| 挑战 | CFR在扑克 | 掼蛋特殊难点 | 可行性 |
|------|----------|------------|--------|
| **信息集定义** | 手牌+公共牌+历史 | 手牌+级牌+进贡+历史 | ⚠️ 需抽象化（哈希编码） |
| **动作空间** | 动作抽象（减少90%） | 组合出牌（更大） | ❌ 需分层抽象 |
| **队友配合** | 无（1v1） | 2v2（需要配合） | ❌ **团队CFR理论不成熟** |
| **组牌环节** | 无 | 有（前置决策） | ❌ **无法直接套用** |
| **计算复杂度** | 分布式CFR（数月） | 更大状态空间 | ❌ **资源需求巨大** |
| **收敛保证** | 理论证明 | 理想条件下 | ⚠️ 实际条件不理想 |

### CFR与V7结合的严肃评估

**如果引入CFR，需要**：
1. BC热启动（当前V7已实现，作为CFR初始策略）
2. 信息集抽象（减少状态空间1000倍以上）
3. 团队CFR（处理2v2队友配合，学术界开放问题）
4. 组牌作为独立模块（规则引擎，不是CFR）
5. CFR只用于动作选择（不是全流程）

**但现实问题**：
- ❌ 桥牌20年AI研究，**仍未完全超越人类**（桥牌也有队友配合）
- ❌ CFR在扑克成功，但扑克**没有队友配合**
- ❌ **团队CFR在学术界仍是开放问题**
- ❌ 掼蛋比桥牌更复杂（组牌+级牌+进贡）

### 与模块化训练方案的对比

| 维度 | CFR路径 | 模块化训练路径（当前方案） |
|------|---------|-------------------------|
| **理论基础** | 博弈论（纳什均衡） | 表示学习（中间变量） |
| **实现复杂度** | 极高（需重写核心） | 中（基于V7改进） |
| **计算资源** | 巨大（数月分布式训练） | 小（单GPU可训练） |
| **队友配合** | ❌ 理论不成熟 | ⚠️ 通过策略模块学习 |
| **组牌环节** | ❌ 无法处理 | ✅ 规则引擎（M3） |
| **收敛保证** | ✅ 理论保证（理想条件） | ❌ 无（但可验证） |
| **工程可行性** | ❌ 低 | ✅ 高 |
| **时间成本** | 6-12个月 | 1-2个月 |

### 严肃结论

1. **CFR理论上可行，但工程实现难度极大**：
   - 团队CFR（2v2配合）是学术界开放问题
   - 组牌环节无法直接套用CFR
   - 计算资源需求远超当前条件

2. **模块化训练是更务实的选择**：
   - 基于V2-V7失败经验（非理论假设）
   - 组牌用规则引擎（M3已验证）
   - 动作学条件概率（NN + Guard）
   - 可快速验证（1-2个月）

3. **CFR可作为长期研究方向，但不应作为当前V7的路径**：
   - 当前目标：快速验证模块化训练（胜率>30%）
   - 长期目标：探索团队CFR（如果模块化成功）

**决策建议**：优先完成模块化分阶段训练，CFR作为后续研究分支。
