### 2.3 批跑 / 数据分析汇报（WF-04）

**必含字段**：**局胜**（`victoryNum[0]` vs `[1]`，同队 [0]=[2]、[1]=[3]）、**副数**（`game_records` 文件数或 `total_rounds`）、**口径声明**（`--target-games`、batch_games 真源）。禁止用副数当局数。

**标准解读流程**（按 wiki「如何解读批跑数据」§五步）：

1. **Step 1 明确口径**：`victoryNum` 是**本局升级数**（0/1/2/3），非"胜局数"；`completed_games` 也不等于"真打局数"，必须 L1 vs L4 核对。
2. **Step 2 跑分析工具**（**别自己推**，直接以工具输出为真源）：

   | 粒度 | 工具 | 用途 |
   |------|------|------|
   | 局级 + 副级 | `python scripts/analysis/analyze_v7_rounds.py --all` | 胜率、victoryNum 末级分布、名次分布 |
   | 副级 curRank 分组 | `python scripts/tools/analyze_v7_round_levels.py` | 调试升级路径、≤5/JK/A 双峰 |

3. **Step 3 写 v7-win-rate-history.md**：按其「记录格式」一行，公式 `V7 队胜率 = [0]+[1] vs 总局数`；**副数 = mtime 窗内 JSON / 2**；**备注列须写本批 L2 日志文件名**（见下 Step 4a）。
4. **Step 4 校验 L1 + L4 一致性**（防数据污染，必走）：

   | 层级 | 位置 | 写入时机 |
   |------|------|----------|
   | L1 | `<repo_root>/batch_executor/latest_victory_num.json` | 每局结束 |
   | L2 | `<repo_root>/logs/`（见 **Step 4a**） | 批跑 / 客户端进程启动后实时写入（不进 Git） |
   | L3 | `<repo_root>/v7_vs_lalala_scores.json`（**非** `batch_executor/`） | 每局结束 |
   | L3′ | `<repo_root>/v7_vs_lalala_state.json`（台账：`completed_games` / `target_games`） | 批跑过程 |
   | L4 | `<repo_root>/game_records_v7/` | 每副结束 |

   **路径定音（防混）**：L3/L3′ 与 L1 不同目录——`run_v7_vs_lalala_games.py` 把 scores/state 写在**仓库根**；勿读 `batch_executor/v7_vs_lalala_scores.json`（不存在）。

   **Step 4a — L2 日志定位（必做 · 禁止未验就报「找不到日志」）**

   **定音**：V7 批跑相关日志**只**落在仓库根 **`logs/`**，不会写到 `%TEMP%`、用户目录或其它盘。代码锚点：

   | 文件 | 写入方 | 命名 |
   |------|--------|------|
   | `logs/v7_vs_lalala_YYYYMMDD_HHMMSS.log` | `scripts/launchers/v7/run_v7_vs_lalala_games.py` | 批跑 launcher 启动时刻 |
   | `logs/yf1_v7_YYYYMMDD_HHMMSS.log` | `src/communication/yf1_v7.py` | yf1 客户端进程启动时刻 |
   | `logs/yf2_v7_YYYYMMDD_HHMMSS.log` | `src/communication/yf2_v7.py` | yf2 客户端进程启动时刻 |

   一次完整 V7 批跑（`run_v7_vs_lalala_games.py --games N`）正常应有 **≥3 个** L2 文件（1 批跑主 log + 2 客户端 log）。`batch_executor_*.log` 仅旧 CLI 入口产生，**不是** V7 批跑必产物。

   **Agent 工具约束（必读）**：`.cursorignore` 含 `logs/` → Cursor **Read / Grep 读不到该目录**。查日志**必须**用 **Shell**（终端 `Get-ChildItem` / `rg` / `python` 读文件），**禁止**因 IDE 搜索无结果就写「logs 为空 / 找不到日志」。

   **定位步骤**（批跑结束后、写 WF-04 汇报前必跑）：

   ```powershell
   # 1) 列目录（真源：磁盘，非 IDE）
   Get-ChildItem "D:\guandanscore\YiFeiAI-GD\logs" -Force |
     Sort-Object LastWriteTime -Descending |
     Format-Table Name, Length, LastWriteTime -AutoSize

   # 2) 与本批牌谱时间窗对齐（L4 mtime 与 L2 应同批，如 202607032149xx）
   Get-ChildItem "D:\guandanscore\YiFeiAI-GD\game_records_v7\20260703*.json" |
     Measure-Object
   ```

   ```bash
   # R-G080-4：card_mask / 组牌退化（与 batch_executor/executor.py 同款正则）
   rg "_run_grouping_engine\s*失败|_basic_classify\s*也失败|_group_consistency_filter\s*失败" logs/yf*_v7_*.log logs/v7_vs_lalala_*.log
   ```

   **何时目录真的为空**（可写「无 L2」）：

   - 刚执行 **净盘** `clean_v7_runtime_artifacts()`（会 `unlink logs/*`），且**尚未**跑完新批跑；
   - 或批跑进程未正常启动客户端（此时应查 `v7_vs_lalala_*.log` 里的启动错误，而非假设路径错误）。

   **关联产物（非 L2，但 WF-04 / WF-12 常用）**：

   | 路径 | 内容 |
   |------|------|
   | `game_decision_traces/{game_id}.jsonl` | GUA-098 决策 trace（`V7_ENABLE_DECISION_TRACE=1` 时） |
   | `game_records_v7/*.json` | 牌谱（L4） |

   **WF-04 汇报必写**：本批 3 个 L2 文件的**完整文件名** + R-G080-4 扫描结论（零退化 / 有告警 + 计数）。

   **三优先级校验**：
   - P1：`[0]+[1]==batch_games` 且 `[0]==[2]` 且 `[1]==[3]` → 通过
   - P2：任一不等 → 走 fallback
   - P3：fallback 仅 `batch_games==1` 时认领 `curTimes==1`

5. **Step 5 避坑**（常见误读）：
   - **vn 元素是「本局升级数」非「胜局数」**：不要 `for _ in range(vn[1]): record_game("team_b")`（典型 bug：`tracker.team_b_wins` 被错累）。
   - **文件名 `[idx]-[total]`**：`idx` 是 batch 内**副序号**（不是局号），`total` 是该局声明的副数（通常 2）。
   - **completed_games** 是按 `batch_games` 累加的台账（方案 A），**不等于 server 真打局数**。
   - **同局 record 数**：每局 4 玩家 × 2 副 = 8 record（V7 仅 yf1/yf2 写 = 4 record/局；lalala 客户端不写 record 是设计）。
   - **70/70 victoryNum 相同** ⇒ server gameResult 漏推，**backfill 用同 vn 回填所有 record**——是 server 端问题，非 V7 引擎问题。

**避坑自检四连问**（写汇报前必答）：
- L1 的 `vn[0]+vn[1]` 与 L4 的实际局数是否一致？若不一致，先标注「数据完整性事故」再继续。
- 工具输出里"会话 N = X 局 Y 副" 与 `<repo_root>/v7_vs_lalala_scores.json` 的 `total_games` 是否对得上？
- 副数公式 `JSON/2` 是否与你 L4 mtime 窗范围一致（避免把历史残留算进本批）？
- **是否已用 Shell 列出 `logs/` 并写入本批 L2 文件名？** 若未跑 Shell，不得声称「找不到日志」。

**WF-04 一步到位清单**（批跑已结束、按序执行，勿跳步、勿手写 Python 数副胜）：

### 2.4 V8 批跑 / 数据分析汇报（WF-04-V8）

> **适用范围**：`v8-dev` 分支，OpenGuanDan 平台（`guandan.exe`，端口 8181）。V7 WF-04 保留不变（§2.3）。

**V8 vs V7 关键差异**：

| 维度 | V7 | V8 |
|------|----|----|
| 服务器 | `guandan_offline_v1006.exe N` | `guandan.exe`（无 N 参数） |
| 1 局（round） | 1 副（episode） | **1 局**（2→A，多副升级） |
| 执胜判定 | `victoryNum` 四席升级数 | `victoryRank`（谁先到 A） |
| `victoryNum` 语义 | 本局升级数（0/1/2/3） | **各席副胜次数**（≠ 局胜负） |
| 牌谱目录 | `game_records_v7/` | `game_records_v8/` |
| 状态文件 | `v7_vs_lalala_*.json` | `v8_vs_lalala_*.json` |
| 日志前缀 | `yf1_v7_`, `yf2_v7_`, `v7_vs_lalala_` | `yf1_v8_`, `yf2_v8_`, `v8_vs_lalala_` |
| 客户端数 | 4（含 lalala 无日志） | 同（lalala 有窗口但无持久日志） |
| 胜率历史 | `v7-win-rate-history.md` | `v8-win-rate-history.md`（新建） |

**必含字段**：**局胜者**（`victoryRank` 含 "A" 的队）、**各席副胜**（`victoryNum`）、**最终等级**（`victoryRank`）、**牌谱副数**（`game_records_v8` JSON 数 / 2）。

**标准解读流程**：

1. **Step 1 明确口径**：
   - V8 的 `victoryNum` 是**各席副胜次数**（如 `[3,2,4,4]`），不是"升级数"。
   - 局胜负看 `victoryRank`（如 `["A","K"]` → V8 队胜；如 `["A","A"]` → 先到 A 的队胜）。
   - `completed_games`（`v8_vs_lalala_state.json`）当前不自动递增（executor 的 game completion 检测依赖 game_records 增量）。

2. **Step 2 数据采集**（Shell 必跑）：

   ```powershell
   cd <repo_root>

   # ① L2 日志（V8 前缀）
   Get-ChildItem logs -Force | Where-Object { $_.Name -like '*v8*' } |
     Sort-Object LastWriteTime -Descending |
     Format-Table Name, Length, LastWriteTime -AutoSize

   # ② 局胜负真源（L2 yf1_v8 日志中的战绩汇总）
   rg "最终等级|局胜者" logs/yf1_v8_*.log

   # ③ L1 / L3 / L3' 对账
   Get-Content batch_executor/latest_victory_num.json
   Get-Content v8_vs_lalala_scores.json
   Get-Content v8_vs_lalala_state.json

   # ④ L4 牌谱（game_records_v8，非 game_records_v7）
   (Get-ChildItem game_records_v8 -File).Count
   ```

3. **Step 3 写 v8-win-rate-history.md**：
   - 新建 `docs/guandan-brain/v8-win-rate-history.md`
   - 格式：`日期 | --target-games | 局胜 (V8:LALALA) | 副数 | 各席副胜 victoryNum | 最终等级 victoryRank | 备注`

4. **Step 4 校验 L1/L3/L4 一致性**：
   - **P1**：`victoryNum[0]+[2]` vs `[1]+[3]` → V8 队副胜数 vs LALALA 副胜数。
   - **P2**：L4 `game_records_v8` JSON 数 / 2 = 副数，与 `victoryNum` 四席和是否一致（每副产生 2 个 yf 视角 JSON）。
   - **P3**：`v8_vs_lalala_scores.json` 可能为 0（executor 未自动更新），以 L1 `latest_victory_num.json` + 日志战绩汇总之 `victoryRank` 为准。

5. **Step 5 避坑**：
   - **`victoryNum` ≠ 升级数**：V8 的 `[3,2,4,4]` 表示各席赢了 3/2/4/4 副，不是"升了几级"。
   - **`completed_games` ≠ 真打局数**：V8 executor 当前不自动递增台账。
   - **`batch_games=1`**：V8 每批只跑 1 局（OpenGuanDan `round=1` = 2→A 完整一局），靠 restart_count 重启服务器实现多局。
   - **牌谱文件名 `[N]-[2]`**：N 是副序号（1 局内递增），2 是 curRank 格式（A/2/3...K/A）。
   - **LALALA 无持久日志**：lalala 客户端窗口输出随 `cmd /c` 关闭消失，分析只读 yf1_v8 + yf2_v8 日志。

**一步到位清单**（V8 批跑结束后）：

```powershell
cd <repo_root>

# ① L2 列目录
Get-ChildItem logs -Force | Where-Object { $_.Name -like '*v8*' } | Sort-Object LastWriteTime -Descending

# ② 局胜负（L2 yf1_v8 日志）

# ③ L1 / L3 / L3'

Get-Content v8_vs_lalala_scores.json -Encoding utf8
Get-Content v8_vs_lalala_state.json -Encoding utf8

# ④ L4 副数
(Get-ChildItem game_records_v8 -File).Count

# ⑤ 写 v8-win-rate-history.md +（若本轮迭代）ITERATIONS
```
