## 1. 人类战术：卡下家到底是什么（定音）

口号「打上家、卡下家、让对家」里的 **卡下家**，**不是**「下家一出牌就用同型最大牌砸死」。

### 1.1 何时该卡

| 条件 | 含义 |
|------|------|
| **本方牌力偏弱**（弱牌 / 助攻 / 散乱多） | 需要主动挡下家控权，避免被带着跑 |
| **卡点 ≈ J 左右** | 不是同型最大，而是 **正好卡到别人脖子** 的那张（够压、又不过分抬圈） |
| 典型单张 | greater 为小单时，用 **9～J（偶尔 Q）** 档去卡；**留住 A/王** 作回手 |

「卡脖子」= 压过后，圈面高度落在中高档，下家再大一档才吃得动；**不是**把大王/顶大结构甩出去结束对话。

**适用范围（全牌型，不只单张）**：卡点 ≈ **J 这一档牌力**，对以下同型均成立：

| 牌型 | 卡点含义（示例） |
|------|------------------|
| Single | 单张约 9～J |
| Pair | 对子约 9～J |
| Trips / ThreeWithTwo | 主牌约 9～J（TWT 比主牌，不比带牌） |
| Straight | 顺子最大点约落在 J 一带（或刚好压过 greater 的最小够压顺） |
| ThreePair / TwoTrips | 结构顶牌约 J 档 |

即：卡的是 **该牌型的点数高度 ≈ J**，不是「只对单张讲 J」。

### 1.2 何时不该卡（顺势跟）

| 条件 | 含义 |
|------|------|
| **本方牌力为强牌**（主攻 / 超强主攻、多炸、结构完整） | 不需要用高张抢下家节奏 |
| **且有多同型可跟**（多张可压散单，或对/顺/TWT 等多档可跟） | 应 **顺势跟牌** = 最小够压，把控牌资源留给真残局 |

本锚点正是反例：`role=超强主攻`（`power_score=7`）、散单含 `H9`/`CJ`/`SB`/`HR`、下家只出 7 → 应顺势出 `H9`/`CJ`，**不该**出 `HR`。

> **卡点 ≈ J 适用于全部同型**（Single / Pair / Trips / ThreeWithTwo / Straight / ThreePair / TwoTrips），比的是该牌型主牌或顶牌高度，不是只对单张。

### 1.3 与「打上家」对照

| | 打上家 | 卡下家（正确） | 现行代码（错误简化） |
|--|--------|----------------|----------------------|
| 触发 | `greaterPos=上家` | `greaterPos=下家` **且** 本方弱牌需挡 | 凡下家控牌 |
| 同型选牌 | 最小够压 | **脖子位 ≈ J**（够压中的「卡点」） | **无条件最大** |
| 强牌多单 | — | **不卡，顺势 min 跟** | 仍 max → 出王 |

### 1.4 旧方案字面哪里偏了

[`V7-决策架构改造-从排除法到推荐法.md`](../V7-决策架构改造-从排除法到推荐法.md) §4.2 写「有同型可压 → 用最大可压的同型（不留余地）」——把「卡」误写成「打满」。


## 4. 修复说明（挂 GUA-075 · 待实施 · 未改代码）

### 4.1 决策分档（按人类定音）

```text
greaterPos == 下家 且 有同型可压:
  │
  ├─ 【强牌 + 多单】role∈{主攻,超强主攻} 且 可压散单数 ≥ 2
  │     → 顺势跟：min 够压（日志：卡下家-顺势 / follow_min）
  │     → 禁止出王/A 除非那是唯一可压
  │
  ├─ 【弱牌需卡】role∈{助攻,弱牌,超弱…} 或 散单少、结构差
  │     → 卡脖子：在可压候选中选「卡点」
  │        单张：优先 rank 落在 9～J（平台序），取 ≥ greater 的最小卡点；
  │        若可压全 >J（如只有 Q/K/A/王）→ 取其中最小够压，仍勿无谓打满王
  │     → 日志：卡下家-卡点
  │
  └─ 【危急锁】下家 rest≤5 / 报单临界 / 残局已接管
        → 可维持更强压制（含 max / 改炸）；由残局 Q1 优先时本分支可不抢
```

**禁止**：`if greater==7 and has_9: not HR` 样本缝合。

### 4.2 「卡点 ≈ J」操作化（全牌型，不只单张）

在可压同型集合中选 **脖子位**（点数高度约 9～J），按牌型：

| greater 型 | 比较键 | 卡点偏好 |
|------------|--------|----------|
| Single | 单张 rank | 优先 9/T/J |
| Pair | 对子 rank | 优先 9/T/J |
| Trips / ThreeWithTwo | **主牌** rank（TWT 不用带牌） | 优先 9/T/J |
| Straight | 顺子最大点 / 声明 rank | 顶牌约落在 J 一带，或最小够压顺 |
| ThreePair / TwoTrips | 结构顶牌 | 同「约 J」 |

算法骨架（各型共用）：

1. 可压集合 `C` 非空  
2. 若存在「卡点档」候选（主牌/顶牌 ∈ {9,T,J}）→ 取该档内 **最小够压**  
3. 否则 → 全体 **最小够压**（勿 max）  
4. 仅 `|C|=1` 或危急锁 → 允许唯一大牌/王/顶大结构  

强牌多单（或多同型可跟）路径：直接全体 **min**，不进卡点档。

### 4.3 「强牌」「多单」信号（建议用现有字段）

| 信号 | 来源 |
|------|------|
| 强牌 | `role ∈ {主攻, 超强主攻}` 或 `score_tier` 强牌+/超强牌；本锚点开局 `power_score=7→超强主攻`、加权分≈0.56 |
| 多同型可跟 | 可压候选 ≥2（单/对/顺/TWT 等同型均计，不限散单） |
| 弱牌 | `role ∈ {助攻, 弱牌, 超弱…}` 或强牌条件不成立 |

### 4.4 落点

1. `_recommend_play` ④：先判强牌多单 → 调 `min_press` 单张逻辑（或 `max_press(..., mode=)`）  
2. 弱牌档：实现 §4.2 卡点选择，**删除**「单张永远 -value 最大」  
3. 日志：`卡下家-顺势` / `卡下家-卡点` / `卡下家-危急`  
4. 不新开 GUA；pytest 挂 `test_gua075*`；GUA-091 复用处跟随

### 4.5 验收

| 用例 | 期望 |
|------|------|
| 超强主攻 + 散单 9/J/HR + 下家 Single/7 + rest 大 | `H9` 或 `CJ`，非 `HR`（顺势） |
| 弱牌/助攻 + 散单 5/9/J/HR + 下家 Single/7 | `H9` 或 `CJ`（卡点≈J），非 `HR` |
