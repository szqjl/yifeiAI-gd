## 零、从服务器消息到返回动作 —— 完整链路追踪

### 0.1 端到端简图

```
游戏服务器 WebSocket ──"act" JSON──▶ yf1_v7 / yf2_v7
                                       │
  [1] process_message()                收到消息
  [2] handle_action_request()          解析 payload
  [3] stage 检查                       进贡/还贡 → 直接 actIndex=0
  [4] asyncio.wait_for(                ← 0.8 秒超时保护
        asyncio.to_thread(
          engine.decide(action_data)   ← 在独立线程跑
        ), timeout=0.8s)
  [5] 11 步决策管线                     见 §一 总览图
  [6] send_action({"actIndex": N})     ← 返回服务器
```

### 0.2 第一步：WebSocket 收到 `type="act"` 消息

服务器推送一条 JSON，核心字段：

```json
{
  "type": "act",
  "data": {
    "handCards":  ["S2", "D4", "CA", ...],   // 当前手牌（字符串列表）
    "curRank":    "2",                         // 当前级牌
    "curPos":     0,                           // 当前轮到谁（0/1/2/3）
    "greaterPos": 2,                           // 上一轮谁获出牌权
    "greaterAction": ["Single", "A", ["SA"]], // 上一轮出的什么
    "actionList": [                            // 服务器给的可选动作
      ["PASS"],
      ["Single", "A", ["SA"]],
      ["Pair", "5", ["C5", "H5"]],
      ...
    ],
    "publicInfo":   [{"rest":20}, ...],       // 四家剩余张数
    "history":      [...],                     // 出牌历史
    "selfRank":     "2",                       // 我方等级
    "oppoRank":     "2"                        // 对方等级
  }
}
```

### 0.3 第二步：客户端 `handle_action_request()`

**位置**：`yf1_v7.py:240-321`（`yf2_v7.py` 完全相同）

1. **解包** `unwrap_platform_payload(data)` → `action_data`
2. **stage 检查**：
   - `stage == "tribute"` → 进贡阶段，直接 `actIndex=0` 返回
   - `stage == "back"` → 还贡阶段，直接 `actIndex=0` 返回
   - 否则 → 正常出牌阶段，走引擎
3. **actionList 空保护**：如果 `actionList` 为空 → 回退 `actIndex=0`
4. **座位同步**：`ensure_my_pos_int()` 确保 `myPos` 正确
5. **字段规范化**：`normalize_act_message_fields(action_data)`
6. **0.8 秒超时调用**：
   ```python
   act_index = await asyncio.wait_for(
       asyncio.to_thread(self.decision_engine.decide, action_data),
       timeout=self.max_decision_time,  # 0.8 秒
   )
   ```
7. **超时回退**：`asyncio.TimeoutError` → `actIndex=0`（通常是 PASS）
8. **校验与记录**：`validate_action()` + `game_recorder.record_decision()`
9. **返回服务器**：`send_action({"actIndex": act_index})` 通过 WebSocket 发回

### 0.4 第三步：引擎 `decide()` —— 11 步决策管线

**位置**：`engine.py:172-370`

按执行顺序：

| # | 步骤 | 函数 | 作用 |
|:--:|------|------|------|
| ① | 组牌引擎 | `_run_grouping_engine()` | 枚举手牌分组，产出 card_mask + role + 24D 特征 |
| ② | 玩家计数注入 | `_inject_numofplayers()` | 推四家剩余张数，供 Guard 用 |
| ③ | 接风记忆 | `_update_teammate_last_trick()` | 记队友末手牌型 |
| ④ | Tracker 注入 | 直接赋值 | 注入 `_memory_tracker` 到 game_state |
| ⑤ | **Guard 层1** | `filter_action_list()` | 硬删除错误动作（14 条规则） |
| ⑥ | **组牌过滤** | `_group_consistency_filter()` | 角色驱动：删拆核心牌型的动作 |
| ⑦ | **接风跟线** | `_apply_wind_catch_anchor()` | 队友刚走完 → 匹配牌型重排在前 |
| ⑧ | **投喂策略** | `_try_teammate_feeding()` | 弱牌角色拆牌送队友 |
| ⑨ | **NN 决策** | `_model_decision()` | 512 维特征 → NN → softmax → argmax |
| ⑨c | **Guard 层3** | `validate_decision()` | 二次校验：纠正炸队友/PASS违规 |
| ⑨d | **Heuristic 覆盖** | GUA-071 检查 | 纠正拆局/joker滥用/炸弹滥用 |
| ⑩ | **索引映射** | 两级映射 | group_idx → filtered_idx → original_idx |
| — | 异常保底 | `_rule_based_decision()` | 选第一个非 PASS 动作 |

### 0.5 第四步：NN 怎么选动作？

```python
# engine.py:1465-1472
features_tensor = torch.FloatTensor(features).unsqueeze(0).to(self.device)
with torch.no_grad():
    predictions = self.model(features_tensor)
    action_logits = predictions['action_logits']       # [1, 512]
    probabilities = torch.softmax(action_logits, dim=-1)

action_probs = probabilities[0][:len(action_list)]      # 截取前 N 个
best_action_idx = torch.argmax(action_probs).item()     # 取概率最高
```

- **没有温度采样**、**没有 top-k**、**没有 beam search**
- `softmax → argmax` 拍脑袋选概率最高的那个
- 如果最高概率的动作有问题 → 靠 Guard 层3 + GUA-071 后置覆盖纠正

### 0.6 第五步：如果模型不可用怎么办？

```
model is None
  → _heuristic_select()    ← 8 条计分规则排序选最优
    → 组局一致性 +10000（碾压一切）
    → 拆局扣分 -300×(n-1)
    → 队友控牌 PASS +200 / 非炸 +100
    → 对手急眼 炸弹 +800 / PASS -100
    → 非 PASS 基础 +50
    → rank 越小越好
    → 早期不出王压小牌 -500
    → 有 SB 不用 HR -300
    → 有同型可压却炸 -600
```

### 0.7 第六步：一切崩了怎么办？

```python
# engine.py:1809-1834
_rule_based_decision()  ← 终极保底
  → 遍历 action_list，选第一个非 PASS 动作
  → 如果全是 PASS → 返回 0
```

### 0.8 关键决策点汇总

| 问题 | 答案 |
|------|------|
| NN 怎么选动作？ | `argmax(softmax(logits))`，选概率最高的，无温度/top-k |
| NN 选错了呢？ | Guard 层3 (`validate_decision`) 纠正炸队友/违规PASS；GUA-071 纠正拆局/joker滥用/炸弹滥用 |
| 模型不可用呢？ | `_heuristic_select()` 8 条计分规则排序 |
| 一切崩了呢？ | `_rule_based_decision()` 选第一个非 PASS |
| 超时了呢？ | `actIndex=0`，通常是 PASS |
| 进贡/还贡呢？ | 不走引擎，直接 `actIndex=0` |
| 两个 V7 用同一模型？ | 是，都加载 `bc_model_v3.pth` |
| 6 层保护包围圈？ | ①组牌引擎 ②Guard 14条 ③角色过滤 ④接风投喂 ⑤NN argmax ⑥validate+heuristic纠正 |

## 三、管线步骤详解

### 步骤 ① `_run_grouping_engine()` — 组牌引擎一次枚举

**位置**：`engine.py:428-507`

**功能**：调用 `enumerate_groupings()` → 一次枚举，产出三样东西缓存到实例属性：

| 产出 | 属性 | 类型 | 用途 |
|------|------|------|------|
| card_mask | `self._card_mask` | `Dict[str, tuple]` | card → (group_id, is_core, group_size)，供 `_group_consistency_filter` 和 `_heuristic_select` 使用 |
| role | `self._current_role` | `str` | 主攻/助攻/超强主攻/超弱，决定过滤强度和投喂策略 |
| 24维特征 | `self._grouping_features` | `np.ndarray` | 进 NN 输入的第 220-243 维 |

**缓存机制**：通过手牌 hash 判断是否需重算（`engine.py:443-445`）：
```python
hand_hash = hash(tuple(sorted(hand_cards)))
if hand_hash == self._last_hand_hash and self._card_mask is not None:
    return  # 复用缓存
```

**降级保护（GUA-072）**：组牌引擎异常时，调用 `_basic_classify()`（`engine.py:538-588`）用简单点数统计识别炸弹（≥4张同点数），确保 card_mask 非空，防止 `_group_consistency_filter` 失效导致炸弹被拆。

### 步骤 ② `_inject_numofplayers()` — 注入玩家剩张数

**位置**：`engine.py:511-534`

**功能**：从 `MemoryTracker.hand_counts` 推算 4 玩家剩余手牌数，注入 `game_state["numofplayers"]`。供 Guard R07/R08/R09 使用。

### 步骤 ③ `_update_teammate_last_trick()` — 接风跟线记忆

**位置**：`engine.py:1125-1154`

**功能**：当上一轮 greaterPos == 队友且出非 PASS 动作时，记忆队友末手牌型到 `self._teammate_last_trick_type`。队友走完或回合切换后清空。

### 步骤 ⑤ Guard 层 1 — `filter_action_list()`

**位置**：`v7_guards.py:1192-1362`

**功能**：硬排除明显错误动作，14 条规则（R01~R15）依次执行。返回 `(filtered_actions, action_map)`（重排后列表 + 重排下标→原始下标映射）。

**规则清单**：

| 规则 | 类型 | 功能 |
|:---:|------|------|
| R10 | 排除 | 自己领出（greaterPos == myPos 或 -1）→ 排除炸弹/同花顺 |
| R15 | 排除 | 炸后相克：炸了上家某牌型后，领出时禁出同型 |
| R05 | 排除 | 队友控牌 → 排除炸弹/同花顺 |
| R11 | 排除 | 对手出不可压牌 → 全局牌记忆 + 节流（两阶段：Phase A 查剩余王/级牌, Phase B 按 pass_num 节流） |
| R01 | 排除 | 压单张 → 有单牌可压时排除炸弹 |
| R02 | 排除 | 多个炸弹 → 只保留最小炸弹 |
| R06 | 排除 | 存在天然对子 → 排除拆结构对子 |
| R12 | 排除 | 同一三张 rank 多个三带二变体 → 只保留带最小对子的 |
| R14 | 排除 | 领出时不拆天然牌型（有天然对子/三张 → 排除拆散动作） |
| R07 | 排除 | 队友控牌且非残局 → 按 6 种牌型 curVal 阈值让道 |
| R13 | 排除 | 平台炸弹合法性：平台标记 Bomb 但实际牌型不符 → 排除 |
| R03 | 重排 | 被动且对手出牌 → 有同型非 PASS 时 PUT PASS 置后 |
| R04 | 重排 | 对手 Single + 己方有可压单牌 → PASS 置后 |
| R08 | 重排 | 主动 + 队友剩 1 张 → 出最小 Single |
| R09 | 重排 | 主动 + 队友剩 5 张 → 优先 Pair/ThreeWithTwo |

### 步骤 ⑥ `_group_consistency_filter()` — 组牌一致性过滤

**位置**：`engine.py:592-761`

**功能**：在 Guard 之后、NN 之前，用 `card_mask` 和 `role` 过滤拆核心牌型的动作。

**过滤规则**：

| 场景 | 行为 |
|------|------|
| 自己剩 ≤5 张 | 全部放行（硬例外） |
| 对手剩 1-2 张 | 全部放行（硬例外） |
| R16: 队友剩 1 张 + 下家非 1 张 | 全部放行（送单） |
| Solo 模式（队友已走完） | role 强制主攻 |
| 对手控牌且 greaterPos == 队友 | role 强制助攻 |
| 炸弹/同花顺被拆 | 永不放行（全角色） |
| 主攻/超强主攻 | 一律过滤所有拆 core |
| 助攻 | 全部放行拆 core（GUA-069 之前行为保留） |
| 超弱 | 按投喂场景三条件放行顺子，场景一/二/三条件放行其他 |
| 过滤后候选为空 | 安全阀：全部放行 |

**R12 附加检查**（`engine.py:692-701`）：所有角色共享——有自然单张时禁止拆对子出单。

### 步骤 ⑦ `_apply_wind_catch_anchor()` — 接风跟线

**位置**：`engine.py:1156-1200`

**功能**：当 greaterPos == 队友（接风窗口）时，将匹配队友末手牌型且不拆 core 的动作重排到列表前面。

### 步骤 ⑧ `_try_teammate_feeding()` — 投喂策略

**位置**：`engine.py:1204-1417`

**功能**：仅弱牌角色（超弱/助攻）触发。两阶段：
- **阶段 1 硬约束**（`_should_rescue_teammate`）：对手压队友 → 删 PASS 重排到末尾
- **阶段 2 软引导**（`_pick_feeding_action`）：按队友余牌数选最小现成牌型重排到前

退出条件（D5）：对手余 ≤2 / 自己余 ≤5 → 不投喂。

### 步骤 ⑨ NN 决策 + Guard 后置校验

**位置**：`engine.py:242-351`

#### ⑨a `_extract_features()` — 512 维特征拼接

**位置**：`engine.py:1487-1545`

| 段 | 维度 | 来源 | 说明 |
|----|:--:|------|------|
| 静态 | [0:124] | `extract_static_features()` | 手牌 one-hot(108) + 级牌/逢人配(9) + 局面标记(6) + 计数(1) |
| 动态 | [124:188] | `extract_dynamic_features()` | 最近 20 步出牌 → LSTM → 64 维 |
| 信念 | [188:196] | `extract_state_belief()` | 己方牌力/敌方牌力/队友剩牌/阶段/炸弹密度/控制力/局势类型 |
| 追踪 | [196:220] | `MemoryTracker.get_tracking_vector()` | 24 维牌追踪（不含组牌特征） |
| 组牌 | [220:244] | `_grouping_features`（步骤①缓存） | 24 维组牌特征（6 方案枚举 + 方案级特征） |
| 填充 | [244:512] | 补零 | 训练时动作列表维度预留 |

#### ⑨b NN forward

**位置**：`engine.py:1462-1472`

```
512维输入 → UltimateWinRateNet → 512 logits
                                       │
取前 len(action_list) 个 logits
  → softmax → argmax → best_action_idx
```

#### ⑨c `validate_decision()` — Guard 层 3

**位置**：`v7_guards.py:1365-1471`

**功能**：模型决策后二次校验，覆盖三种错误：
1. 炸队友（greaterPos == teammate）→ 找非炸动作
2. 领出炸弹 → 找非炸动作
3. 被动 PASS 但有同型可压 → 选同型最小
4. Q12 Solo 强化：队友已走 + 对手出牌 + 模型选 PASS → 强制同型压制

#### ⑨d GUA-071 后置覆盖

**位置**：`engine.py:262-337`

**功能**：NN 返回后，检查是否违反组牌策略。三种覆盖触发器：

| 触发器 | 条件 |
|--------|------|
| 拆局 | NN 选中动作拆了核心牌型 → `_heuristic_select` 覆盖 |
| joker 滥用 | NN 选 HR 单张但有 SB 也能压对手 |
| 炸弹滥用 | NN 选炸弹但有同型非炸弹可压 |

**两级索引映射**（`engine.py:339-351`）：
```
group_actions_idx → group_filter_map → filtered_idx
filtered_idx → action_map → original_idx
```

### 步骤 ⑩ `_heuristic_select()` — 启发式选择（模型不可用/覆盖时）

**位置**：`engine.py:1582-1807`

**功能**：Layer 2 软排序。在 Guard 保留的动作中打分选最优。

**计分规则**：

| # | 条件 | 分值 |
|:--:|------|:--:|

## 五、三层决策管道（GUA-073）

```
Layer 1: Guard 过滤 (v7_guards.py:filter_action_list)
  职责：硬排除错误动作（13 条排除规则 + 4 条重排规则）
  语义：只"移除"，不排序/不打分

Layer 2: 排序选择
  - NN 可用: _model_decision → 512 logits → softmax → argmax
  - NN 不可用: _heuristic_select → 8 条计分规则 → 取最高分

Layer 3: 安全网 (v7_guards.py:validate_decision + GUA-071 后置检查)
  职责：覆盖 Layer 2 的错误决策（炸队友/违规 PASS/拆局/joker滥用/炸弹滥用）
```
