# M1：yf1_m1 与 yf2_m1 表现对照（复现与记录）

> 目的：判断 **yf2_m1 是否仍明显差于 yf1_m1**，再决定改 **`yf2_m1.py` 独立路由** 还是 **共用决策层**（`src/decision/`）。  
> 关联台账：**GUA-006**（历史已关）、**GUA-020**（**已关闭**，`closed_in` 2026-04-21，见 `ISSUES.md`）。

## 1. 前提

- 分支建议：**m1-dev**（与 `START_M1_GUI.bat` 一致）。  
- 四条客户端：`scenarios/client_sets.json` 中 **`m1`** 键（0/2 为 YiFei，1/3 为 lalala）。  
- 评测入口见 **`EVAL.md`**（M1 GUI / 无头 CLI）。

## 2. 最小复现步骤

1. **跑批量对战**（场次 ≥10 更有统计意义，开发期可先用 3～5 场）：  
   - `START_M1_GUI.bat` → `py batch_executor_gui_m1.py`  
   - 或：`python -m batch_executor --server-path "<SERVER_EXE>" --target-games N --clients ...`（四元组同 `client_sets.json` 的 `m1`）。  
2. **收集记录**：`game_records/` 下按时间排序，取最新若干局；确保含 **`player_id` 0 与 2** 的 JSON（yf1_m1 / yf2_m1）。  
3. **对齐指标**（每局、按 player 聚合均可）：

   | 指标 | yf1_m1 (P0) | yf2_m1 (P2) | 说明 |
   |------|-------------|-------------|------|
   | 决策次数 | | | `my_decisions` 条数 |
   | PASS 次数 / 率 | | | |
   | 「问题 PASS」次数（有合法非 PASS 仍 PASS） | | | 需日志或脚本判定 |
   | 主动出牌次数 | | | |
   | 阶段分布（opening / mid_* / endgame_*） | | | 若有 |

4. **队伍结果**：`victoryNum` 或 `game_info` 中胜负；关注 **0+2 一队** 是否常负于 1+3。

## 3. 结论怎么写（便于迭代大脑）

在 **`ITERATIONS.md`** 中写清：

- **若 yf2 明显差于 yf1**（PASS 率、问题 PASS、主动次数等）：  
  - **优先**：检查 `yf2_m1.py` 是否比 `yf1_m1.py` 少调用同一决策入口、或 `player_id`/消息字段不一致。  
  - **再考虑**：是否两边应 **完全共用** 同一 `decide()` 路径，仅保留通信差异。  
- **若差距不大**：问题更可能在 **共用层**（`phase_handlers` 等），不必先分叉 `yf2_m1` 路由。

## 4. 可选自动化

- 使用现有分析脚本（若仓库中有 `analyze_m1_*.py`）：对 `game_records` 批量统计 PASS 与阶段。  
- 将典型牌局 ID 记在 **`ITERATIONS.md`** 或本文件末尾附录。
