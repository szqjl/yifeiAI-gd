## 零、一句话定位

**让 V8 的组牌方案从「开局/手牌变化时跑一次静态最优」升级为「每个决策回合都能按对手出牌模式重新评估与调整」**：当对手连续出某牌型、而当前 plan 把回应牌锁死在其他结构里时，系统能生成「针对性重组」候选、量化重组后的牌力损失，并结合队友获胜收益决定是否执行——掼蛋有时需要牺牲自己成全队友。**动态组牌有牌力门禁：超强牌不启用，仅强牌以下才需要，且强牌细分强牌+ / 强牌 / 强牌-（§二）**；同时须联动领出，感知队友需要什么牌型并重组出对应结构（§3.5）。

## 一、问题本质

### 1.1 静态 plan 不感知局面

当前组牌方案生命周期：

```
decide(521)
 └ _run_grouping_engine(557)
     └ hand_hash 变化才重跑（v7:1466-1468）
     └ enumerate_groupings → best_plan + Top3（grouping_engine.py:2440）
     └ 只保留 best_plan → _card_mask/_group_type_map/_group_members（v7:1480）
     └ Top3 其余候选丢弃
```

**关键事实（全部已核实）**：

| 项 | 现状 | 位置 |
|----|------|------|
| plan 触发 | 仅手牌 hash 变化才重跑；**对手出牌不改我方手牌 → plan 永不因对手模式变化** | `v7:1466-1468` |
| 候选保留 | `enumerate_groupings` 返回 Top3，`_run_grouping_engine` 只用 best_plan | `grouping_engine.py:2440`、`v7:1480` |
| 中局触发 | `_check_midgame_triggers` 只按手牌降量阈值（15/10/5）+ 拆核标记，仍等 hash 自然重跑 | `v7:2847-2882` |
| 拆核成本 | `_group_break_cost` 静态表：SF/Bomb=1000、复合子组=600、straight/trips=500 | `v7:2019-2032` |
| 推荐器压牌 | 只从 plan groups 找同型组（Pair/Trips/Straight），plan 无该型 → None → 改炸/PASS | `v7:5250/5671` |
| 拆对拦单 | 已有零散加分（GUA-157/166：无自然单才拆对、拆 9-J 对优先），但仍是「加分」非「重组」 | `v7:3754-3784` |
| 对手信号 | `memory_tracker.get_inferred_opponent_types` / `rule_card_counter.can_opponent_suppress` 已存在，**未反哺组牌决策** | `memory_tracker.py:630`、`rule_card_counter.py:74` |

**结论**：plan 是「当前手牌」的静态最优划分，不感知「对手正在打什么、队友需要什么」。对手连续出单时，V8 的单张被锁进对子/顺子/三带二里；要回应就只能靠 heuristic 加分「鼓励拆」，但拆哪个、拆完整副牌还顺不顺、值不值得，没有统一框架。

### 1.2 三个子问题

局面感知动态组牌 = 三个子问题的统一回答：

1. **触发（Trigger）**：什么时候该重新评估当前 plan？
2. **候选（Candidate）**：重组该生成哪些「应对性方案」？
3. **决策（Decide）**：重组代价（牌力损失）与收益（压制对手 / 成全队友）如何权衡？

## 二、动态组牌限定条件（牌力分层门禁）【用户 ①】

**超强牌不启用动态组牌；仅强牌以下才需要；强牌细分强牌+ / 强牌 / 强牌-。**

### 2.1 牌力档位定义（复用现有信号，不另造）

V8 已有两套牌力信号，直接作为门禁输入：

| 现有信号 | 输出 | 位置 |
|----------|------|------|
| `_score_power` | `power_score`（牌力分，用于角色定位） | `grouping_engine.py:1379` |
| `_score_plan_v2` → `plan.score` | 四维加权总分 → `score_tier`（天胡/好牌/尚可/偏弱/烂牌） | `grouping_engine.py:1603/1564` |
| `determine_role` | `role`（超强主攻 ≥7 / 主攻 4-6 / 助攻 1-3 / 超弱 <1） | `grouping_engine.py:1544` |

档位映射（评审可调阈）：

| 用户档位 | 映射依据（建议） | 动态组牌策略 |
|----------|------------------|--------------|
| **超强牌** | `score_tier == "天胡"`（score ≥0.50）或 `role == "超强主攻"`（power ≥7） | **不启用**——牌力已碾压，静态 plan 最优，重组是多余损耗 |
| **强牌+** | `score_tier == "好牌"`（0.40-0.50）或 `role == "主攻"` 上沿（power 5-6） | 启用低频触发（仅对手连续同型 ≥3 / 队友 close），可拆仅限低价值结构（对子/顺子/附牌） |
| **强牌** | `score_tier == "尚可"`（0.30-0.40）或 `role == "主攻"`（power 4） | 默认全触发；可拆低价值结构 + 复合子组 |
| **强牌-** | `score_tier == "偏弱"`（0.20-0.30）或 `role == "助攻"`（power 1-3） | 全触发 + 激进：以配合队友/送牌为优先，可容忍拆掉高价值结构（除 SF/Bomb 硬核） |
| **超弱牌** | `score_tier == "烂牌"`（<0.20）或 `role == "超弱"`（power <1） | 触发面最大，但以「尽快送队友 / 消耗炸弹扛线」为目标，不追求保结构 |

### 2.2 门禁规则

1. **门禁判定时点**：每个决策回合 `decide()` 入口，用**当前 plan 的 `score_tier` + `role`**（若尚未组牌则用最新一次 `_score_power`）判定档位，一次判定该回合动态组牌是否开启。
2. **硬边界不随档位放宽**：无论哪档，拆 SF/Bomb core 仍否决（GUA-108 语义保留）；只是「低价值结构 vs 高价值结构」的拆核容忍度随档位放宽。
3. **不启用 ≠ 不压制**：超强牌档关闭的是「重组」，现有拆对拦单等 heuristic 照常工作；只是不因对手模式去改动 plan 本身。
4. 新档位**不新增常量**：复用 `determine_score_tier` / `determine_role` 已有阈值，仅在其上定义组合规则。

## 三、硬边界（评审必认）

1. **禁止**写成「看到单就拆对、看到顺就拆三连对」的牌例特判（`stage_0_1`/`stage_2` 或 heuristic 加分支）；落点必须是「候选生成 + 统一代价评估」框架。
2. **禁止**形成「逢压制必拆结构」退化：拆 SF/Bomb core 仍严格禁止（保留 GUA-108 停手条件 ③ 语义）；拆低价值结构（对子/顺子/三带二附牌）须经代价评估。
3. **复用既有评分**：牌力损失用现有 `_score_power`（`grouping_engine.py:1379`）+ `_score_plan_v2`（`:1603`）重算，不另造评分体系。
4. 新增行为不得降低 83.3% 队胜率 KPI（净盘批跑护栏）+ 针对性 pytest 回归全绿。
5. 队友获胜权衡需显式建模：掼蛋是 2v2，「牺牲自己牌力成全队友头游」是合法且高价值选择，不是「尽量不拆」。
6. **限定门禁先行**：任何动态组牌逻辑必须先过 §二 牌力档位门禁，未过门禁的档位（超强牌）不产生重组候选。

## 四、四要素框架

### 3.1 触发（Trigger）——何时重估 plan

在现有「手牌 hash 变化重跑」之外，新增**局面感知触发**。候选触发条件（须评审裁剪）：

| 触发类型 | 信号来源 | 说明 |
|----------|----------|------|
| **对手出牌模式** | 本回合 `greaterAction` + 历史最近 N 手 `play_history` | 对手连续 ≥2 手同一牌型（Single/Pair/Straight…）→ 该牌型是当前争夺焦点，值得为它重组 |
| **对手压制窗口** | `memory_tracker.get_inferred_opponent_types` / `rule_card_counter.can_opponent_suppress` | 对手当前打 Single 且我方无自然单 → 触发「拆结构出单」候选 |
| **队友 close** | `endgame_preprocessor` 的 `teammate.is_close`（≤5 张） | 队友即将走完 → 触发「送牌型」候选（牺牲自己结构成全队友） |
| **中局阈值** | 现有 `_check_midgame_triggers`（15/10/5 张） | 保留，但让「重跑」真正发生在阈值触发时，而非等 hash |
| **我方 core 已被拆** | `_core_broken_since_regroup` | 已有标记，重跑时按新局面生成候选 |

**设计点**：触发后不是「重新跑一次同样的静态枚举」，而是带着「当前争夺牌型」的上下文重新生成候选（见 3.2）。

### 3.2 候选（Candidate）——重组成什么

两个层面：

**(a) 保留多 plan 不再丢弃**：`enumerate_groupings` 已返回 Top3（`grouping_engine.py:2440`），`_run_grouping_engine` 应缓存全部 Top3，供决策时按局面选用（方案 C 基础，改动最小）。

**(b) 针对性重组候选**：当触发命中（对手连续 Single + 我方无自然单）时，对当前手牌生成「拆出目标牌型」的重组候选。关键思路——**不是全手牌重组，而是「局部重划 + 重新评分」**：

1. 目标牌型 T（如 Single/Pair/Straight）→ 从当前 plan 中找出所有「可贡献给 T 的结构」（含子组）；
2. 对每个候选结构生成「拆它 → 组 T → 剩余牌重划」的重组方案；
3. 每个重组方案用 `_score_plan_v2` 重新评分，得到 `new_score`；
4. 与当前 plan 的 `score` 对比 → **牌力损失 delta**。

示例（用户场景）：手牌 `10,10,J,J,Q,Q,K,K,A`，当前 plan 把 `1010JJQQ` 锁进三连对。
- 候选 A：拆三连对出 `10-J-Q-K-A` 顺子压对手 8-Q → 剩余 `10,J,Q,K,A` 重划 → 重评分；
- 候选 B：拆三连对出对子/单张压对手 → 同样重评分；
- 候选 C：保持 plan 不变（PASS）→ 对比三者 delta。

**注意**：重组候选的生成应复用组牌引擎现有的「结构贡献」逻辑（`_build_consecutive_structure_press` 已会从 `pair_in_three_pair` 重建三连对，`v7:5489`），本质是把它从「从 plan 子结构重建」扩展为「从手牌全局找可拆结构重建」。

### 3.3 代价量化（Cost）——重组后牌力下降多少

**用现有评分函数重算 delta**，不另造体系：

```
delta = plan_score(当前) - plan_score(重组后)   # 四维加权总分差（_score_plan_v2）
power_delta = _score_power(当前) - _score_power(重组后)  # 纯牌力差（可解释性）
```

`_score_plan_v2` 四维：牌力 0.5 + 手数 0.3 + 回收 0.1 + 灵活性 0.1（`grouping_engine.py:1632-1638`）。重组后手数可能下降（拆 3 轮结构组 1 轮压牌）→ rounds_score 上升；但牌力可能下降（拆了对子/顺子）→ bomb_score 下降。**delta 由评分自动综合，不是人拍脑袋**。

额外提供**解释性指标**（供 trace/日志）：
- 拆了哪个 core/子组（复用 `_group_break_cost` 表）
- 手数变化
- 单张残渣数变化

### 3.4 决策权衡（Decide）——值不值得，含为队友牺牲

这是「动态组牌」区别于「鼓励拆牌加分」的核心。统一权衡函数：

```
exec_weight = current_control_gain + teammate_win_gain - plan_loss - core_break_penalty
```

| 项 | 含义 | 信号 |
|----|------|------|
| `current_control_gain` | 压住对手这手牌的即时收益 | 对手是否在冲刺（剩张数）、greaterVal 高度、能否夺回牌权 |
| `teammate_win_gain` | **成全队友获胜的收益** | `teammate.is_close`（≤5 张）+ 队友前序牌型（`_teammate_last_trick_type`）+ 送出的牌型队友能否接 |
| `plan_loss` | 重组牌力损失 | 3.3 的 delta |
| `core_break_penalty` | 拆 SF/Bomb core 的硬罚 | 拆核即否决（保持禁止） |

**关键理念（掼蛋 2v2 牺牲语义）**：
- 如果 `teammate.is_close` 且重组送出的牌型能让队友一手走完 → `teammate_win_gain` 应显著高于 `plan_loss`，允许「牺牲自己结构」；
- 如果对手冲刺、重组能压住 → `current_control_gain` 高，允许拆低价值结构；
- 如果重组纯属拆结构但既压不住对手也帮不了队友 → 否决，保持 plan。

**与 GUA-109（候选并存+统一评分）的关系**：GUA-109 已在组牌层建立「保未来结构 vs 拆结构换当前夺权」并存 + 评分比较（closed_in）。本框架把同一理念**扩展到推荐器/决策层**，并显式加入「队友获胜」这一 2v2 特有的牺牲维度。

### 3.5 领出联动 + 队友需求感知（Lead-Feed）【用户 ②】

动态组牌不只服务「压对手」，还服务「**我方领出时给队友喂什么牌型**」。用户问题：「动态组牌后必须辅助领出后出什么牌型？如何感知队友需要什么牌型？」

#### 3.5.1 队友需求感知：已有真源，直接复用

V8 已有成套「队友需要什么牌型」信号，**不需新建**：

| 信号 | 输出 | 位置 |
|------|------|------|
| `assist_prefer_for(remaining)` | 队友剩 N 张 → 允许投喂的牌型列表（1→Single、2→Pair、3→Trips/Pair/Single、4→Pair/Single、5→Straight/TWT/Single）——**单一真源** | `assist_prefer_table.py:11` |
| `assist_is_close(remaining)` | 队友 1-5 张 → 接近头游 | `assist_prefer_table.py:26` |
| `endgame_preprocessor` | `teammate.remaining` / `is_close` / `assist_prefer` 装配进残局上下文 | `endgame_preprocessor.py:724-730` |
| `_teammate_last_trick_type` | 队友上一手非 PASS 牌型（接风窗口） | `ultimate_win_rate_engine_v7.py:2886-2911` |
| `_feeding_target_types(rest)` | 队友剩张 → 投喂目标牌型（R16 体系） | `v7:3180-3200` |
| `_should_rescue_teammate` | 队友被困 → 强制压制/送牌 | `v7:3014` |

现有领出消费点（动态组牌的重组候选要被它们消费）：
- `stage_assist_feed.py`（GUA-117 助攻领出）
- `EndgameDecider Q2`（`endgame_decide.py:1438` teammate close → 送牌）
- `_q1_lead_feed_teammate_special`（GUA-202 领出送队友，`endgame_decide.py:2537`）
- `_q1_feed_teammate_twt_when_downseat_two`（GUA-220，送 TWT，`endgame_decide.py:1958`）
- `pick_teammate_sprint_small_single`（GUA-160 送单，`endgame_decide.py:1188`）
- R09 过滤（`guards/v7_guards.py:1229`）

**结论**：队友需求的「感知」已经完备；缺的是——当队友需要的牌型**当前 plan 没有对应组**时，没有「重组候选」让这些领出逻辑有牌可送（现有领出只能从 plan 现有组里选，找不到就放弃送牌/退回整牌锁敌）。

#### 3.5.2 领出联动设计

```
我方领出 & 队友需要牌型集 P = assist_prefer_for(teammate.remaining)
  → 若 plan 已有 P 中牌型的组 → 走现有领出逻辑（不重组）
  → 若 plan 无 P 中牌型（如队友剩5张需要 Straight/TWT，plan 全是 Pair）：
      → 生成「重组出 P 中某牌型」的候选（复用 §3.2 针对性重组）
      → 用 §3.3 delta 量化损失
      → 过 §3.4 权衡（teammate_win_gain 主导）
      → 选出的重组 plan 交给现有领出消费点（stage_assist_feed / Q2 / GUA-202）
```

- 目标牌型 T 的来源是 **P 集合并集**（`assist_prefer_for` 优先序第 1 位优先，第 2/3 位备选），而非「压对手」场景的对手牌型。
- **队友末手牌型补强**：若 `_teammate_last_trick_type` 非 None（队友刚打过某型），说明队友手里该牌型可能已不多，需结合 `assist_prefer` 综合；以 `assist_prefer` 为主、last_trick 为辅。
- **优先级**：领出场景下重组候选与压对手场景**同池评分**（同一 §3.4 权衡函数），只是 `teammate_win_gain` 在领出送牌时权重更高。

#### 3.5.3 与牌力门禁的关系

- 领出送牌重组同样受 §二 档位门禁约束：**强牌+ / 强牌** 档仅在队友 close（1-5 张）时允许为送牌重组；**强牌- / 超弱** 档领出即以送队友为首要目标，允许更激进拆结构。
- 超强牌档仍不启用（牌力碾压，自己快走更划算，送牌反而拖慢自己）。

## 五、落地方案（分层，评审后择期）
