# V7 架构演进与新增规则准入治理

> **目的**：把两件事合成一个入口：
> 1. `V7 从补丁主脑 → 统一中局大脑 → 候选统一评分器` 的架构演进主线
> 2. 每条新规则在进入 V7 前的**准入审查**与**落点约束**
> **结论**：两者不是并行两套系统，而是同一治理闭环的两面。**架构演进定义“大脑往哪里长”，准入审查定义“新知识允许长到哪里”。**

## 1. 一条总任务

**总任务只有一条**：

**把 replay 中发现的新知识，优先沉淀为统一状态、统一意图、统一评分；只在确属 P0 止血时，才允许临时补丁规则进入主脑。**

这条总任务同时约束两件事：

- **架构侧**：V7 必须从“补丁主脑”长向“统一中局大脑”，再长向“候选统一评分器”
- **治理侧**：每一条新增规则，都必须回答“它是在帮助 V7 长脑，还是只是在继续堆补丁”

### 1.1 执行卡片（默认闭环）

```text
replay / 异常扫描 / 批跑结果
→ WF-12：先判断是单副现象还是一类局面
→ 过本文件 5 问准入审查
→ 定落点：_phase_relation / _belief / intent / scorer / hard safety constraint / 驳回
→ 修复 + 构造态回归 + trace
→ 净盘批跑（WF-04）
→ replay 复核
→ 再把新发现送回同一闭环
```

**禁止**：`发现 bug → 直接加规则 → 批跑` 的原始补丁循环。

---

## 2. 为什么必须合并治理

如果只讲架构路线，不设规则准入闸门，结果会是：

- 口头上要做统一中局大脑
- 实际上每次还是往 `stage_2 / Q1 / recommend_play` 塞特判

如果只讲规则准入，不讲架构路线，结果会是：

- 每条规则都能自圆其说
- 但整体不知道要收敛到什么形态

所以这两者必须合并成一份文档，统一回答两个问题：

1. **系统下一步应该长什么**
2. **眼前这条规则该不该进、该进哪一层**

---

## 3. V7 的三阶段演进

## 3.1 阶段 A：补丁主脑

这是当前现实，不回避。

当前 V7 仍然主要依赖：

- 残局 `Q1/Q2/Q3`
- `stage_0_1` / `stage_2` 入口特判
- teammate / cutoff / sprint fire / enemy critical 一类规则

这一阶段允许存在的原因只有一个：

- **先止血**

也就是优先拦住：

- 报单乱放
- 反压队友
- 无收益升炸
- 明显可压却 PASS
- 明显能锁敌却还领伪安全单

但阶段 A 不是目标形态，只是**故障封口层**。

### 阶段 A 的允许新增

- 明确 P0 败招止血规则
- 已能抽象成一类局面，而非只修一副牌
- 必须带构造态回归
- 必须带 WF-12 trace 可见命中点
- 必须写明停手条件

### 阶段 A 的禁止新增

- 只对某副 replay 生效的硬编码
- 写死某个点数牌，如“直接围绕 K/A/Q 写规则”
- 不能解释为一类局面的局部 if
- 没有回归、没有 trace、没有迁移出口的补丁

## 3.2 阶段 B：统一中局大脑

这是当前主线。

现有最小闭环已经明确：

- **GUA-090**：开局入口
- **GUA-094**：推断层 `_phase_relation`
- **GUA-091**：`stage_2` 统一消费 `_belief + _phase_relation + role + greaterAction`

这一阶段的关键不是“规则更多”，而是：

- **先统一状态，再出动作**

统一状态至少应包含：

- `critical_enemy_seat`
- `enemy_shape_hint`
- `teammate_cover_confidence`
- `teammate_rear_single_cover_confidence`
- `same_type_suppressor_outside`
- 当前角色 `role`
- 当前阶段 `stage`

统一中局大脑只输出少量意图，不直接输出零散特判：

- `yield_to_teammate`
- `hold_lane`
- `min_press`
- `max_press`
- `cutoff`
- `sprint_fire`

### 阶段 B 的允许新增

- 新知识优先沉到 `_belief / _phase_relation / role / intent`
- 新规则优先写成**状态生产器**或**意图分流条件**
- 可以新增少量 hard safety constraint，但仅限明显防炸裂场景

### 阶段 B 的禁止新增

- 继续在 `stage_2` 平铺更多 replay 特判
- 让 `_phase_relation` 直接操纵 actIndex
- 用“命中某条件就 return 某动作”的短路方式替代意图层
- 新增一层候选增强/兜底模块，重复 v4/v5 的 fallback 结构

## 3.3 阶段 C：候选统一评分器

只有阶段 B 稳住后，才进入这一层。

这一阶段的定义是：

1. 统一产候选
2. 每个候选绑定同一套状态特征
3. 用同一评分目标比较候选
4. fallback 只保留 crash-safe，不再承担主决策

至少要统一比较的候选包括：

- PASS 让道
- 最小同型压
- 最大同型压
- 主动整牌领出
- 炸弹切权
- 炸弹封口
- 队友保护型承接

### 阶段 C 的允许新增

- 评分特征
- 候选约束
- hard safety constraint
- trace 字段

### 阶段 C 的禁止新增

- 新的动作短路 return
- 任何“绕开评分器直接拍板”的非 safety 类规则
- 继续扩展多层 fallback

## 4. 新增规则准入审查表

每条新规则进入 V7 前，必须回答下面 5 个问题。

| 审查问题 | 要点 | 不满足时怎么处理 |
|----------|------|------------------|
| 1. 这是“一类局面”还是“单副现象”？ | 必须能抽象为可重复局面，不是只修某一步牌谱 | 退回 WF-12 继续分析，不准入 |
| 2. 它能不能先沉到统一状态/意图，而不是直接控动作？ | 优先落到 `_phase_relation / _belief / role / intent / scorer_feature` | 若能沉状态却仍想直接写动作，驳回 |
| 3. 它是不是 P0 止血？ | 只有明显送头游、反压队友、无收益炸损、关键 PASS 才可走补丁特例 | 非 P0 不得进入补丁主脑 |
| 4. 它的验证闭环是什么？ | 至少要有构造态回归；能补 trace 就补 trace；必要时配异常扫描或批跑观察 | 没验证闭环，不准入 |
| 5. 它的迁移出口是什么？ | 必须写清最终会迁到“统一状态 / 统一意图 / 统一评分 / safety constraint”哪一层 | 没出口说明，视为坏补丁，不准入 |

这 5 个问题不是为了“证明规则一定正确”，而是为了防止：

- 补丁进入错误层
- 单副经验冒充通用规律
- 规则越修越多，却没有向统一大脑收敛

---

## 5. 审查后的落点规则

不是所有新知识都应该落成“规则”。

| 新发现类型 | 默认落点 | 说明 |
|------------|----------|------|
| 敌方像 `4+1` / 整牌冲刺 / 单张通道 | `_phase_relation` | 先变成状态信号 |
| 队友尾位大概率可接 / 队友已控牌 | `_belief` / `_phase_relation` / intent gate | 先变成让道或保 lane 条件 |
| 主攻可点火 / 助攻应让道 | `intent` | 不直接写死某个动作 |
| 候选 A 比候选 B 更节牌力/更稳控权 | `scorer feature` | 进入候选统一评分器 |
| 明显炸裂败招，如反压队友、无收益升炸 | `hard safety constraint` | 允许短路，但必须是少量硬约束 |
| 只在一副 replay 中出现、无法抽象 | 不准入 | 继续分析，不写代码 |

---

## 6. 分阶段准入策略

同一条规则，在不同阶段的准入门槛不同。

| 阶段 | 准入策略 | 默认落点 |
|------|----------|----------|
| 阶段 A 补丁主脑 | 从严放行少量 P0 止血 | hard safety constraint / 临时补丁 |
| 阶段 B 统一中局大脑 | 优先禁止新增动作特判，优先改写为状态与意图 | `_phase_relation / _belief / intent` |
| 阶段 C 候选统一评分器 | 原则上不再接受新的动作短路规则 | `scorer feature / candidate constraint` |

这意味着：

- **越往后，越不允许“直接加动作规则”**
- V7 的新增知识，必须越来越多地沉到状态层、意图层、评分层

---

## 7. 什么情况下说明我们又走回 v4/v5 老路

出现下面任一现象，都要视为治理失效：

- 新增规则没有状态抽象，直接改动作
- `stage_2` 的 replay 特判持续膨胀
- `_phase_relation` 开始变成“动作脚本表”
- 新模块名字叫“增强”“再排序”“兜底”，本质还是多层 fallback
- 文档里写了很多命中率、触发率，但批跑队胜不动
- 每次只能解释单副牌，解释不了一类局面

一旦出现这些，说明系统没有往统一大脑演进，而是在继续长补丁壳。

---

## 8. 当前落地顺序

按当前仓库状态，唯一正确的推进顺序是：

1. 继续以 **GUA-101 → GUA-094 → GUA-091** 为主线，先把统一中局大脑站住
2. 所有新增 replay 发现，先过本文件的**准入审查表**
3. 能沉状态的先沉状态，能沉意图的先沉意图
4. 只有确属 P0 止血时，才允许少量补丁进入主脑
5. 等 `stage_2` 稳定消费统一状态后，再进入候选统一评分器

---

## 9. 结论

V7 的主线不是“继续堆规则”，而是：

**把规则发现机制，转成统一大脑的养料机制。**

所以从今天起，新增规则不再被视为默认正确路径，而只是五选一：

- 沉到统一状态
- 沉到统一意图
- 沉到统一评分
- 收敛为少量 hard safety constraint
- 或者直接驳回，不准入

这就是 V7 当前唯一可落地的治理总任务。
