# 指挥系统（大脑职责说明）

本目录 **`docs/guandan-brain/`** 在流程上承担 **规划、统筹、部署**——即「指挥系统」：不替代你写每一行代码或替你点离线 exe，但负责 **定目标、定口径、定顺序、验收与归档**。

## 四角色分工

| 角色 | 身份 | 做什么 | 产出 / 载体 |
|------|------|--------|-------------|
| **Hermes（总协调）** | 另一 AI 工具（如 Claude 网页/API） | 从 `ISSUES.md` 选 Top 1～2 定迭代；拆任务写入 `TASKS.md`（注明派给谁）；审查交付物 diff → 验收 → 更新 `ISSUES.md` / `ITERATIONS.md` | `TASKS.md` 任务分派、审查结论、台账更新 |
| **Opencode（执行 AI-A）** | 本终端内的 AI | 从 `TASKS.md` 认领任务 → 改 `src/` 等代码 → 跑自动化测试/脚本验证 → 交"一句话交接"回 `TASKS.md` | 代码改动、测试结果、`TASKS.md` 回写 |
| **Cursor（执行 AI-B）** | Cursor IDE 内的 AI | 从 `TASKS.md` 认领任务 → 改 `src/` 等代码 → 跑验证 → 交"一句话交接"回 `TASKS.md` | 代码改动、测试结果、`TASKS.md` 回写 |
| **人类（局主）** | 你 | 定期看 `TASKS.md` → 分别告诉 Opencode/Cursor 去执行新任务；本机跑离线对局生成 `game_records`；回填对战结果 | 新 `game_records` 文件、`execution_state.json` |

## 协作流程

```
Hermes ──定迭代──→ TASKS.md（拆任务）
              ↓
       ┌──────┴──────┐
       ↓              ↓
   Opencode       Cursor
   (认领+改代码)   (认领+改代码)
       ↓              ↓
       └──────┬──────┘
              ↓
       Hermes（审查 diff → 验收 → 更新台账）
              ↓
       人类（本机跑局回填 game_records）
              ↓
       ITERATIONS.md（闭环）
```

## 标准一轮（可重复）

1. **盘点**：`ISSUES.md` 里 **open** 的 `GUA-xxx`。  
2. **定迭代**：Hermes 在 `ITERATIONS.md` 追加一行——目标 GUA、完成定义、评测命令/路径。  
3. **拆任务**：Hermes 在 `TASKS.md` 写具体任务（派给 Opencode 或 Cursor），包含任务/范围/依据/交付/完成定义。  
4. **执行**：人类告诉对应 AI 去认领 → 改代码 → 跑验证 → 写回"一句话交接"。  
5. **验收**：Hermes 审查 diff，对照完成定义验收；达标则 `closed` + 更新 ITERATIONS。  
6. **下轮唯一 priority**：写在同一行表格末列，避免并行多主线失焦。

## 任务分派规范（Hermes 写 TASKS.md 时使用）

每条任务必须包含以下字段：

| 字段 | 说明 |
|------|------|
| **任务ID** | `TASK-xxx` 顺序编号 |
| **来源** | 对应的 `GUA-xxx` 编号 |
| **派给** | `opencode` 或 `cursor` |
| **状态** | `待接` / `进行中` / `待验收` / `已完成` / `已取消` |
| **【任务】** | 一句话：要达成什么 |
| **【范围】** | 允许改的目录/文件类型；明确禁止项 |
| **【依据】** | 优先读的文档与条目 |
| **【交付】** | 必须包含仓库内代码/配置改动 + 列出改动文件 |
| **【完成定义】** | 可验收的一条或几条指标 |
| **【交接摘要】** | 执行 AI 完成后填写的一句话交接 |

---

**一句话**：**Hermes = 台账 + 分派 + 验收**；**Opencode/Cursor = 执行**；**人类 = 跑局 + 回填**；**跑完局 = 把数字写回大脑**。
