## 1. 问题摘要

| 项 | 说明 |
|----|------|
| **现象** | 队友 yf1 走光后 yf2 接风出小 3；对手 6/对 6 可压却 PASS；对手 5 张三带二一手走完 |
| **根因** | 无「队友 rest=0 → solo 冲刺」模式；`_active` 仍走 `rankone/ranktwo`；`_Single/_Pair.normal()` 只认真单/真对，不拆 trips；R3 在 `_Pair` 等分支可能未兜底 |
| **现有能力** | `numofplayers[]` / `publicInfo.rest` 有；GUA-031 仅 `numoffri∈{1,5}`；`numofnext==0` 仅改看上家，**非** solo 模式 |

## 2. 硬边界（评审必认）

| 边界 | 要求 |
|------|------|
| **GUA-026** | 常态三带二仍禁拆炸/级牌 trips；**仅** solo_sprint + 拦对手一手时允许定向拆牌 |
| **GUA-031** | solo 时 greater 为对手，队友让道自然不触发；**禁止**在 solo 下误开 P-F02 |
| **GUA-029** | R3/R4/R5 仍生效；增强 R3 兜底须回归 `test_m3_gua029` |
| **GUA-030** | 不在 M3 堆整页残局知识；方案须 **可 pytest 的 guard**，非 rank 体系重写 |
| **关单** | END-M01–M04 + `test_m3_gua034.py` ≥4 case；**不要求**队胜率达标 |

## 3. 候选方向

### 方向 A：Guard 切片（END-M01–M04）— **文档推荐默认**

| 项 | 内容 |
|----|------|
| **做法** | `_is_solo_sprint()`（`numoffri==0`，可选 `numofmy<=12`）→ END-M02 接风禁 rank* 拆对出单，优先三带二/三张/对子；END-M03/M04 被动允许拆 trips 压牌/凑对；各 handler 末统一 R3 兜底 |
| **优点** | 与 ISSUES 完成定义 1:1；改动面可控；易回归 |
| **风险** | 仅覆盖「队友先走光」；双下等场景仍靠 GUA-031 |
| **工作量** | 中（约 1 迭代） |

### 方向 B：仅 R3 统一兜底

| 项 | 内容 |
|----|------|
| **做法** | 不引入 solo_sprint；`_Single/_Pair` 在 `return 0` 前强制 `_gua029_try_bomb` |
| **优点** | diff 最小；可能单独改善 106 步 |
| **缺点** | 不解决 102 接风出小 3；非 solo 场景可能多炸 |
| **工作量** | 小 |
| **关单** | **不足以单独关 GUA-034** |

### 方向 C：移植 lalala「两手出完」（BUG2 全量）

| 项 | 内容 |
|----|------|
| **做法** | `numofmy<=12` 枚举 actionList 两手组合清牌 |
| **优点** | 残局规划最完整 |
| **缺点** | 与 ISSUES「不在范围」冲突；易与 GUA-026 打架；工作量大 |
| **工作量** | 大 |
| **建议** | GUA-034 关单后独立迭代或 V5+ |

### 方向 D：V5+ / IDecisionProvider 挂接

| 项 | 内容 |
|----|------|
| **做法** | M3 只检测 END-M01，残局决策委托 V 层 |
| **优点** | 符合 P1+→V5+ 路线图 |
| **缺点** | 短期无法关 GUA-034；跨模块 |
| **工作量** | 大 |

### 方向 E：混合（A + 轻量两手模板）

| 项 | 内容 |
|----|------|
| **做法** | A 全部 + `solo_sprint && numofmy<=8` 时查 2–3 种「两手走完」模板（如三带二+单） |
| **优点** | 比 A 多规划层，比 C 可控 |
| **缺点** | 模板须文档化，否则隐式策略 |
| **工作量** | 中偏大 |
| **建议** | A 关单后再开 |
