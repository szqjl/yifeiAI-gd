# GUA-064 方向调研：温度采样 vs Beam Search vs 自对弈 Policy Gradient

> **背景**：V7 BC argmax collapse 日志确证——2048 维输出空间仅用 2 维（PASS 50.1% + 首候选 48.9%，actIndex≥2 仅 0.9%）。组牌引擎 v2 + 衔接改造均未改变此结构。本文调研三种破局方向的利弊与项目切合度。

> **调研日期**：2026-06-18 | **来源**：GitHub/arXiv/掘金/知乎 公开资料

---

## 1. 方案总览

| 维度 | 温度采样 | Beam Search | 自对弈 Policy Gradient |
|------|:---:|:---:|:---:|
| 改动量 | 🔵 极小（3行） | 🟡 中（需搜索框架） | 🔴 大（训练管线重建） |
| 见效速度 | 🔵 即时 | 🟡 需调 K 和搜索策略 | 🔴 数天～数周 |
| 治本程度 | 🔴 治标 | 🟡 部分（受限于世界模型） | 🟢 治本 |
| 计算开销 | 🔵 零 | 🟡 K倍 forward+对手建模 | 🔴 高（自对弈训练） |
| 掼蛋成功案例 | 🟡 无直接案例 | 🔴 零 | 🟢 DouZero/DanZero+/赢麻哒 |

## 2. 方向一：温度采样（Temperature Sampling）

### 原理
将 `argmax(logits)` 替换为 `softmax(logits / T).sample()`：
- **T < 1**：分布变尖，接近 argmax（保守）
- **T = 1**：标准 softmax 按概率采样
- **T > 1**：分布变平，增加多样性（激进探索）

### 文献支撑
- 大模型解码（GPT/LLaMA）标配：温度采样 + top-K + top-p 三件套
- SAC（Soft Actor-Critic）使用温度参数控制探索-利用平衡
- 2026 新工作"Temperature as Meta-Policy"将温度作为可学习参数

### 优势
1. **实现极简**：`decide()` 中 3 行代码改动，不改训练管线
2. **即时验证**：立即可跑批跑看效果
3. **可控**：T 值可手动调参，也可用网格搜索找到最优 T
4. **不退步**：T→0 等价 argmax，有安全兜底
5. **不破坏 BC 模型**：保留 bc_model_v3 权重，仅改推理方式

### 劣势
1. **分布本身有问题**：BC 训练的 logits 分布偏向 PASS 和首候选，温度只改变"挑选方式"不改变"分布质量"
2. **T>1 可能采样到非法动作**：需在 softmax 前做 action mask（V7 已有 mask 机制）
3. **T>1 可能采样到弱动作**：BC 学到的低概率动作往往是"人类不会打的烂牌"，采样出来可能更差
4. **治标不治本**：仍然是 teacher forcing 下学到的分布，argmax 问题只是冰山一角

### 与本项目切合度：⭐⭐⭐（快速试错）

**建议**：无论最终走哪条路，温度采样作为 5 分钟可完成的"免费实验"值得一做。T∈[0.5, 2.0] 各跑 3 局批跑，观察 actIndex 分布变化和副胜率。如果 T=1.2-1.5 能让 actIndex≥2 从 0.9% 涨到 5-10% 且副胜率不降，说明方向靠谱；否则快速排除。

## 3. 方向二：Beam Search

### 原理
每一步保留 top-K 个候选动作序列，在序列级别（而非单步决策）评价最优路径。源自 NLP 机器翻译的解码策略。

### 文献支撑
- NLP 领域成熟应用（NMT 翻译、文本生成）
- 博弈领域：AlphaGo MCTS 本质也是一种 beam search over game tree
- **但在 card game AI 中无成功案例**

### 优势
1. **利用序列结构**：不只看当前步，而是看"出牌-对手反应-队友接牌"的连锁效果
2. **K 可控**：beam width K=5-10 在计算上可行

### 劣势

#### 致命伤 1：需要对手/队友模型（世界模型）
Beam search 展开 K 个候选序列时，每步需要知道**对手/队友会怎么反应**才能继续推演。简单的做法：
- 假设对手/队友也按同一 BC 模型行动 → **但 Lalala 不是 BC，假设不成立**
- 学习一个 world model → **训练代价 ≈ 重训一个 BC，且精度未知**

#### 致命伤 2：计算爆炸
- 单步 K=5，深度 D=3（出牌→对手→队友→回我），需 5×5×5=125 次 NN forward
- V7 每次 forward ~10ms → 125 次 = 1.25s，超时风险

#### 致命伤 3：4 人博弈中"序列"语义弱
- NLP 的 beam search 是自回归生成（自身控制整个序列）
- 掼蛋中你只能控制自己的出牌，对手/队友不可控
- 序列优化的假设（"我这么打，他们就会这么接"）在博弈中不成立

#### 致命伤 4：无同领域成功案例
- DouZero（斗地主冠军）：不用 search
- DanZero+（掼蛋领先）：不用 search
- 赢麻哒 LSTM+DMC：不用 search
- Big 2 PPO 论文：不用 search

### 与本项目切合度：⭐（不推荐）

**结论**：Beam search 适用于自回归生成任务，不适合多人不完美信息博弈。在掼蛋这种 4 人交互博弈中，beam search 退化为 top-K 采样（单步 beam），而多步 beam 需要不可获取的世界模型。

## 4. 方向三：自对弈 Policy Gradient（DMC / PPO）

### 原理
从零（或从 BC 预训练模型）开始，通过自对弈收集经验，用策略梯度直接优化期望奖励。核心公式：

```
∇J(θ) = E[ Σ_t ∇log π_θ(a_t|s_t) · R_t ]
```

其中 R_t 是累积奖励（局终 reward / 稠密 reward / GAE），π_θ 是策略网络。

### 成功案例（掼蛋 / 同类卡牌游戏）

#### 4.1 DouZero（快手，ICML 2021）
| 项目 | 详情 |
|------|------|
| 游戏 | 斗地主（3人不完美信息） |
| 算法 | **Deep Monte-Carlo (DMC)** |
| 训练 | 4 GPU，**数天**，从零开始 |
| 成果 | 344 个 AI 中**排名第一** |
| 特点 | **不依赖人类数据**、不搜索、不使用人工特征 |
| 架构 | LSTM 编码出牌历史 + 多头 Q 值输出 |
| 开源 | ✅ [GitHub: kwai/DouZero](https://github.com/kwai/DouZero) |

#### 4.2 DanZero / DanZero+（中科大，COG 2022 / 2023）
| 项目 | 详情 |
|------|------|
| 游戏 | **掼蛋**（4人 2v2 不完美信息） |
| 算法 | **DMC（DanZero）→ DMC + policy-based RL + 预训练模型（DanZero+）** |
| 成果 | DanZero 显著超启发式规则；DanZero+ 进一步提升 |
| 动作空间 | 通过预训练模型**缩小动作空间**（核心贡献） |
| 特点 | 分布式训练框架；预训练模型不是 BC 而是**动作空间压缩器** |
| 开源 | ⚠️ 未找到完整开源代码，但论文公开 |

#### 4.3 赢麻哒 LSTM+DMC（麻邻国，2026 掘金技术博客）
| 项目 | 详情 |
|------|------|
| 游戏 | **掼蛋** |
| 算法 | **DMC 自对弈** |
| 架构 | 手牌编码器（216→256→128）+ 2层LSTM(256) + 队友编码器(128→64) + 等级 Embedding(13,16) → 策略头 364 维 |
| 训练 | **3000 万局**，V100 GPU，**约 3 周** |
| 成果 | 对 greedy 基准胜率：**0.35 → 0.72** |
| 踩坑 | ① 队友配合难收敛（需独立队友编码器提升 5%）② 炸弹使用极端化（需阶段性奖励）③ 升级机制致状态膨胀（Embedding 注入） |
| 动作空间 | 规则引擎动态枚举合法动作（含 PASS），只在合法动作上 softmax |

#### 4.4 Big 2 Self-Play（Patwa, arXiv 2026.05）
| 项目 | 详情 |
|------|------|
| 游戏 | Big 2（4人不完美信息卡牌，类似掼蛋简化版） |
| 算法 | **PPO + 熵正则化** |
| 自对弈策略 | **current-policy self-play > checkpoint self-play > fixed-opponent** |
| 对比 | PPO > MC-Q > SARSA > Q-learning |
| 关键发现 | **适度熵正则化防止策略过早确定**（直接对应 V7 argmax collapse） |

### 优势

1. **天然解决 argmax collapse**：策略输出是**概率分布**而非点估计，探索-利用内建平衡
2. **掼蛋领域主流成功方案**：三个已有掼蛋案例均用 DMC/PPO 自对弈
3. **可利用现有基建**：
   - 已有 self-play 框架规划（GUA-039a/b）
   - 已有稠密 reward 设计（GUA-051，9 种中间 reward）
   - 已有 BC 预训练模型（bc_model_v3）可作 warm start
   - 已有 offline_platform 可跑自对弈
4. **BC warm start 有理论支撑**：
   - DanZero+ 预训练模型辅助训练
   - "Posterior Behavioral Cloning"（NeurIPS 2025）证明合理的 BC 预训练可加速 RL 微调
   - "When Life Gives You BC, Make Q-functions"（2026）BC→RL 过渡策略
5. **V7 已经在 RL 方向上做了大量基建**（GUA-039a/b、GUA-051、GUA-053）

### 劣势

1. **训练资源高**：赢麻哒 3000 万局 3 周 V100；但 DouZero 仅需几天 4 GPU
   - 估算：本项目单机 RTX 3060，每局 ~2s → 10 万局/天 → 收益出现约需 2-4 周
2. **训练不稳定**：
   - 奖励设计对收敛至关重要（炸弹使用极端化、配合策略难收敛）
   - 需大量超参调优（学习率、熵系数、GAE λ、clip 范围等）
3. **需要自对弈环境**：
   - 4 个 AI 同时运行 + 对局记录 + 经验回放
   - offline_platform 单次 3 局限制需改造或绕过
4. **从零训练 vs BC warm start 的博弈**：
   - BC warm start 加速但可能**把 BC 的 bias 带进 RL**（policy 过早收敛到 BC 的次优分布）
   - DouZero 从零开始也只需几天
5. **开发周期长**：
   - 即使复用 DouZero 开源代码（MIT License 可直接参考），掼蛋适配仍需 2-4 周

### 与本项目切合度：⭐⭐⭐⭐⭐（最佳方案）

**结论**：自对弈 Policy Gradient 是 V7 的唯一出路。三个独立团队（快手/中科大/赢麻哒）在掼蛋/斗地主上均用此方案成功。BC argmax collapse 是 BC 路线的死胡同，RL 自对弈天然绕过此问题。

## 5. 综合推荐：两阶段路线

```
Phase 1: 温度采样快速验证（1 天）
  └─ 修改 decide() 3 行代码
  └─ T∈[0.8, 1.0, 1.2, 1.5, 2.0] 各 3 局批跑
  └─ 观察 actIndex 分布 + 副胜率 + 末级分布
  └─ 结论：
       ├─ T=1.2-1.5 有改善 → 短中期方案成立，可延缓 RL
       └─ 无改善 → 确认 BC 路线的分布已死，加速推进 RL

Phase 2: DMC/PPO 自对弈（主体方案）
  └─ 复用 DouZero 开源代码（MIT License）
  └─ 适配掼蛋 2v2 规则 + 4 人环境
  └─ BC v3 作 warm start（可选，需实验对比 from scratch）
  └─ 训练 1-4 周 → 达到对 Lalala 队胜 > 0
```
