# 人类掼蛋决策流程完整分析

> 创建时间：2026-06-18
> 状态：分析中
> 目的：从人类真实决策流程出发，重新审视掼蛋AI架构设计
> 核心原则：**争夺牌权，尽快通过任何方式将手牌出清**

---

## 一、人类决策的本质特征

### 1.1 不是"手牌→动作"的直接映射

```
V系列AI的错误假设：
输入特征（220维） → 神经网络 → 动作概率（2048维） → 输出动作

人类真实决策：
组牌（多方案） → 角色定位 → 初期试探 → 中期动态调整 → 残局记忆决胜
```

### 1.2 核心目标

**每一副的要求就是争夺牌权，尽快通过任何方式，将自己的手牌出清，多获得牌权，就多一手出牌机会。**

| 维度 | 人类决策 | V2-V7 AI | 差距 |
|------|---------|---------|------|
| **组牌** | 多方案生成+动态调整 | ❌ 跳过或单次固定 | 核心缺陷 |
| **角色** | 初始定位+动态转换 | ❌ 无角色概念 | 缺失 |
| **记忆** | 跟踪各家出牌历史 | ⚠️ 简单序列编码 | 不足 |
| **动态调整** | 根据局面实时调整 | ❌ 端到端静态映射 | 核心缺陷 |
| **牌权争夺** | 核心目标 | ❌ 无明确建模 | 缺失 |
| **残局** | 精确记忆+推断 | ❌ 无专门处理 | 缺失 |

## 二、完整决策链路

### 阶段0：开局组牌（静态分析）

**时机**：拿到27张手牌后，出牌前

**输入**：
- 27张手牌
- 当前级牌（打几）
- 进贡状态（谁贡谁）

**组牌扫描**：
```
1. 炸弹识别
   ├─ 4张相同（无逢人配）
   ├─ 3张相同 + 1逢人配
   ├─ 2张相同 + 2逢人配
   └─ 1张 + 3逢人配

2. 同花顺识别
   └─ 5张连续同花（最大牌型）

3. 顺子识别
   ├─ 5张连续
   ├─ 6张连续
   └─ 可含逢人配

4. 三带二识别
   ├─ 三张 + 对子
   └─ 三张可含逢人配

5. 钢板识别
   └─ 2个三张连续

6. 其他牌型
   ├─ 对子
   ├─ 单张
   └─ 三张（不带）
```

**多方案生成**（不是唯一解）：
```
例：手牌 333444555667789JQKA小王大王红桃2

方案A：
├─ 炸弹：3333（含红桃2逢人配）
├─ 顺子：45678
├─ 三带二：555+99
├─ 对子：JJ, QQ, KK, AA
├─ 单张：小王, 大王
└─ 评估：1炸 + 10手牌，牌力0.7

方案B：
├─ 炸弹：3333（红桃2）, 4444
├─ 顺子：56789
├─ 三带二：555+JJ
├─ 对子：QQ, KK, AA
├─ 单张：小王, 大王
└─ 评估：2炸 + 9手牌，牌力0.85（最优）

方案C：
├─ 炸弹：无（保留逢人配组顺子）
├─ 顺子：23456, 789JQ
├─ 三带二：333+KK, 444+AA
├─ 对子：55, 77
├─ 单张：小王, 大王
└─ 评估：0炸 + 8手牌，牌力0.6
```

**组牌评估维度**：
| 维度 | 权重 | 说明 |
|------|------|------|
| **炸弹数** | 0.3 | 越多越好（压制力强） |
| **手数** | 0.2 | 越少越好（出牌次数少） |
| **回收能力** | 0.3 | 每种牌型能否回收（关键） |
| **灵活性** | 0.2 | 多种出牌路径 |

**输出**：
```
组牌方案列表（排序）：
├─ 方案B（最优）：2炸 + 9手牌，牌力0.85
├─ 方案A（备选1）：1炸 + 10手牌，牌力0.7
└─ 方案C（备选2）：0炸 + 8手牌，牌力0.6
```

**关键洞察**：
- 组牌不是唯一解，有多个合法方案
- 最优方案不是最终决定，会根据局势动态调整
- 回收能力是关键评估维度（能否压制对手并收回牌权）

### 阶段1：角色定位（基于组牌+进贡）

**时机**：组牌完成后，首圈出牌前

**输入**：
- 最优组牌方案（炸弹数/手数/牌力）
- 进贡状态（谁贡谁）
- 对家进贡牌力（推断）

**判断逻辑**：
```
if 牌力强(>0.7) and 有炸弹(≥1):
    角色 = "主攻"
elif 牌力中(0.5-0.7) and 有炸弹:
    角色 = "可主攻可助攻"（根据对家情况）
elif 牌力弱(<0.5) or 无炸弹:
    角色 = "助攻"
elif 对家牌力强:
    角色 = "助攻"（让对家主攻）
```

**角色定义**：
| 角色 | 职责 | 出牌策略 |
|------|------|---------|
| **主攻** | 负责走完 | 积极出牌，争夺牌权，尽快出清 |
| **助攻** | 配合对家 | 送对家需要的牌型，压制对手，掩护对家 |

**输出**：
```
角色定位：
├─ 主攻/助攻
└─ 置信度（0.0-1.0）
```

**关键洞察**：
- 角色是初始定位，不是固定不变的
- 中期可能动态转换（主攻→助攻，或助攻→主攻）
- 角色决定出牌策略的根本方向

### 阶段2：初期出牌（第1-5圈）- 试探阶段

**时机**：前3-5圈

**输入**：
- 我的角色（主攻/助攻）
- 最优组牌方案
- 回收能力评估（每种牌型）
- 当前圈数（1-5）

**决策因素**：

#### 2.1 首发牌型选择

```
if 我是主攻:
    if 有能回收的牌型:
        出不能回收的牌型（先出弱牌）
        # 例：有单张3但有大王 → 先出单张3
    else:
        出安全牌型（对手不太可能压制）
elif 我是助攻:
    if 对家先发牌:
        配合对家牌型（对家出单张，我跟单张）
    else:
        出对家可能需要的牌型
```

#### 2.2 能回收判断

**回收能力定义**：出的牌型，我有更大的牌能收回牌权

```
例1：出单张3
├─ 我有大王？→ 能回收（大王最大）
├─ 我有级牌？→ 能回收（级牌次大）
└─ 我有小王？→ 可能能回收（取决于对手）

例2：出对子55
├─ 我有对子AA？→ 能回收
├─ 我有炸弹？→ 能回收（但浪费炸弹）
└─ 我无更大对子？→ 不能回收

例3：出顺子34567
├─ 我有更大顺子89JQK？→ 能回收
└─ 我无更大顺子？→ 不能回收
```

#### 2.3 风险评估

```
出这个牌型：
├─ 对手能压制吗？
│   ├─ 对手可能有大牌？
│   └─ 根据进贡推断（对手贡了大牌，手牌可能弱）
├─ 对家能接住吗？
│   ├─ 对家可能有更大牌型？
│   └─ 配合对家角色
└─ 出完后，我的手牌更优还是更劣？
```

**输出**：
```
初期出牌决策：
├─ 具体牌型（单张/对子/顺子/三带二等）
├─ 具体牌（例：单张3）
└─ 预期结果（能否回收/是否安全）
```

**关键洞察**：
- 初期是试探阶段，测试对手牌力
- 主攻先出不能回收的牌，保留大牌回收牌权
- 助攻配合对家，不主动争夺牌权

### 阶段3：中期行牌（第6-10圈）- 动态调整阶段

**时机**：第6-10圈左右

**输入**：
- 当前手牌（可能已出部分）
- 原始组牌方案
- 历史记忆（前N圈出牌）
- 当前角色（可能已转换）
- 牌权状态（我是否先手）

#### 3.1 记忆要素（核心）

```
记忆追踪：
├─ 队友出过什么牌型？
│   ├─ 单张/对子/顺子/三带二
│   └─ 哪些牌型被压制过
├─ 队友缺什么牌型？
│   ├─ 队友出过对子，可能缺单张
│   └─ 队友出过顺子，可能缺三带二
├─ 对手压制过什么牌型？
│   ├─ 对手用大王压制单张
│   ├─ 对手用炸弹压制顺子
│   └─ 推断对手手牌强度
├─ 哪些牌型是安全的？
│   ├─ 对手无法压制的牌型
│   └─ 对手已无炸弹，炸弹外的牌型安全
└─ 炸弹使用情况
    ├─ 哪些炸弹已出
    └─ 哪些炸弹可能还在手
```

#### 3.2 动态调整

**原组牌方案可能不再适用**：
```
例：原方案计划出顺子34567
├─ 但发现对手有更大顺子89JQK
├─ 调整：改出对子或三带二
└─ 或者：用炸弹压制对手的顺子，然后出自己的顺子

例：原方案计划保留炸弹
├─ 但发现对家被对手压制，快走完了
├─ 调整：立即用炸弹保护对家
└─ 牺牲炸弹，换取对家走牌
```

**角色动态转换**：
```
情况1：主攻 → 转助攻
├─ 触发条件：发现对家牌比我强
├─ 判断依据：对家连续出大牌，对手无法压制
└─ 调整策略：改送对家需要的牌型

情况2：助攻 → 转主攻
├─ 触发条件：发现对家被压制，手牌弱
├─ 判断依据：对家出小牌被压，无法接牌
└─ 调整策略：改为自己争夺牌权，尽快出清
```

**炸弹决策**：
```
炸不炸？炸谁？

决策矩阵：
├─ 炸上家（对手）
│   ├─ 目的：阻止对手出牌
│   └─ 适用：对手要出完，必须压制
├─ 炸下家（对手）
│   ├─ 目的：保护对家
│   └─ 适用：对家出牌，下家可能压制
├─ 不炸
│   ├─ 目的：保留炸弹
│   └─ 适用：当前局面可控，不需要浪费炸弹
└─ 判断依据：
    ├─ 炸弹数量（多炸可以浪费，少炸必须谨慎）
    ├─ 牌权状态（我是否需要牌权）
    └─ 对家状态（对家是否需要保护）
```

#### 3.3 核心目标

**"争夺牌权，尽快出清手牌"**

```
每一步评估：
├─ 出这个牌型，能获得牌权吗？
│   ├─ 对手能压制吗？
│   └─ 我有回收能力吗？
├─ 如果不能获得牌权：
│   ├─ 对家能获得牌权吗？
│   └─ 配合对家出牌
└─ 如果都获得不了牌权：
    └─ 尽量减少损失（出小牌，保留大牌）
```

**输出**：
```
中期出牌决策：
├─ 调整后的牌型（可能偏离原组牌）
├─ 具体牌
├─ 炸弹使用（炸/不炸）
└─ 角色状态（主攻/助攻，是否转换）
```

**关键洞察**：
- 中期是动态调整阶段，不能死守原组牌方案
- 记忆是核心能力，跟踪各家出牌历史
- 角色可能转换，根据局势灵活调整
- 炸弹使用是关键决策，影响胜负

### 阶段4：残局（最后3-5手牌）- 记忆决胜阶段

**时机**：剩余≤10张牌

**输入**：
- 剩余手牌（≤10张）
- 完整历史（所有出牌）
- 推断各家剩余牌分布

#### 4.1 关键记忆

```
残局必须记住的信息：
├─ 哪些大牌已出？
│   ├─ 炸弹（4个炸弹已出几个？）
│   ├─ 大王/小王
│   ├─ 级牌
│   └─ 其他大牌（AA/KK/QQ）
├─ 对手可能剩什么牌？
│   ├─ 根据历史出牌推断
│   └─ 对手出过什么，没出过什么
├─ 对家能否接住我的牌？
│   ├─ 对家出过的牌型
│   └─ 对家可能剩余的牌力
└─ 各家剩余牌数
    ├─ 对手A剩几张？
    ├─ 对手B剩几张？
    └─ 对家剩几张？
```

#### 4.2 决策逻辑

```
例1：我剩3张牌

情况A：炸弹 + 单张
├─ 出牌顺序：先出单张
├─ 如果对手压制：用炸弹夺回牌权
└─ 如果对手不压制：下轮出炸弹，直接走完

情况B：三张（如AAA）
├─ 能否一次出完？（三张是否合法）
├─ 如果能：直接出完，胜利
└─ 如果不能：拆开成对子+单张

情况C：对子 + 单张
├─ 先出对子还是单张？
├─ 判断：对手可能剩什么？
│   ├─ 对手剩单张？→ 先出对子
│   └─ 对手剩对子？→ 先出单张
└─ 目标：让对手接不住

例2：我剩5张牌

情况A：炸弹 + 对子
├─ 出牌顺序：先出对子
├─ 对手压制？→ 炸弹夺回 → 走完
└─ 对手不压制？→ 下轮炸弹 → 走完

情况B：顺子（5张）
├─ 直接出顺子
├─ 对手有更大顺子？→ 输
└─ 对手无更大顺子？→ 赢
```

#### 4.3 出牌顺序优化

```
残局目标：找到最优出牌顺序

例：手牌 33 555 大王

方案A：先出对子33
├─ 对手压制（如对子AA）
├─ 我用炸弹555？→ 浪费（555不是炸弹）
└─ 结果：失去牌权，输

方案B：先出三张555
├─ 对手压制（如炸弹）
├─ 我用大王？→ 不能压制炸弹
└─ 结果：失去牌权，输

方案C：先出单张3
├─ 对手出单张（如单张4）
├─ 我出大王 → 获得牌权
├─ 出对子33 → 对手可能接不住
├─ 出三张555 → 走完
└─ 结果：赢（最优）

关键：残局出牌顺序决定胜负
```

**输出**：
```
残局决策：
├─ 出牌顺序（精确到每一手）
├─ 炸弹使用时机
└─ 预期结果（胜/负概率）
```

**关键洞察**：
- 残局完全依赖记忆，不依赖初始组牌
- 出牌顺序决定胜负（不是牌型本身）
- 必须精确推断各家剩余牌分布
- 炸弹最后使用时机是关键

## 三、核心贯穿原则：牌权争夺评估

### 3.1 每一步都评估

```
出这个动作，能获得牌权吗？

评估维度：
├─ 1. 这个牌型能被对手压制吗？
│   ├─ 对手可能有更大的牌型？
│   ├─ 对手有炸弹吗？
│   └─ 根据记忆推断对手牌力
├─ 2. 如果不能压制 → 获得牌权
│   └─ 评分：1.0（确定获得）
├─ 3. 如果能压制 → 可能失去牌权
│   ├─ 对手有炸弹的概率？
│   │   ├─ <30% → 评分：0.7（大概率获得）
│   │   ├─ 30-60% → 评分：0.4（中等概率）
│   │   └─ >60% → 评分：0.1（大概率失去）
│   └─ 我有炸弹能夺回吗？
│       ├─ 有 → 评分+0.2
│       └─ 无 → 评分不变
└─ 4. 对家能接住吗？
    ├─ 对家可能有更大牌型？
    └─ 即使我失去牌权，对家能获得？
        └─ 评分：根据配合情况调整
```

### 3.2 决策目标函数

```
不是"匹配M3动作"（BC模仿学习）
不是"最大化长期奖励"（RL强化学习）
而是"最大化牌权获得次数"

目标函数：
max Σ(power_gain_prob_t)  for t in 1..T

其中：
- power_gain_prob_t = 第t圈获得牌权的概率
- T = 总圈数（直到手牌出清）
```

### 3.3 与V系列的根本差异

| 维度 | V7当前（BC模仿学习） | 人类决策流 |
|------|---------------------|-----------|
| **决策目标** | 匹配M3动作 | **最大化牌权获得** |
| **评估标准** | 动作匹配率 | **牌权获得概率** |
| **组牌** | ❌ 跳过 | ✅ 多方案+动态调整 |
| **记忆** | ⚠️ 简单序列 | ✅ 结构化跟踪 |
| **动态调整** | ❌ 固定映射 | ✅ 实时调整 |
| **残局** | ❌ 无特殊处理 | ✅ 精确推断 |

## 四、人类决策的技术本质

### 4.1 组牌（算法，不是NN）

**为什么组牌不能用神经网络？**

| 维度 | 神经网络 | 硬编码算法 |
|------|---------|-----------|
| **多方案生成** | ❌ 只能输出一个方案 | ✅ 可生成所有合法方案 |
| **精确性** | ⚠️ 可能输出非法方案 | ✅ 100%合法 |
| **可解释性** | ❌ 黑盒 | ✅ 清晰可追踪 |
| **评估维度** | ❌ 端到端，难控制 | ✅ 每个维度独立评估 |
| **动态调整** | ❌ 需要重新推理 | ✅ 快速重新评估 |

**组牌引擎实现**：
```python
class GroupingEngine:
    """组牌引擎（硬编码算法）"""
    
    def generate_all_plans(self, hand_cards):
        """生成所有合法组牌方案"""
        # 1. 识别所有炸弹
        # 2. 识别所有顺子
        # 3. 识别所有三带二
        # 4. 回溯组合生成方案
        # 5. 评估每个方案
        # 6. 排序返回
        pass
    
    def evaluate_plan(self, plan):
        """评估组牌方案"""
        score = 0
        score += plan.bomb_count * 0.3
        score -= plan.hand_count * 0.1
        score += plan.recovery_ability * 0.3
        score += plan.flexibility * 0.2
        return score
```

### 4.2 记忆（结构化跟踪，不是原始序列）

### 8.1 人类的物理记忆机制

#### 8.1.1 人类如何"记住"组牌方案

**不是"记住组牌方案"，而是"手牌已经按方案排列好"**：

```
人类打牌的真实流程：

   ↓
3. 选择最优方案（例：2炸+9手牌）
   ↓
4. 【关键】按组牌方案整理手牌顺序
   ↓
5. 手上的牌已经按"结构"排列好
   ↓
6. 出牌时直接从对应位置取牌
```

#### 8.1.2 人类的"手牌整理"行为

### 8.2 AI模拟方案：手牌重排序与区域索引

#### 8.2.1 核心设计原则

**手牌重排序 = 物理记忆**：
- 组牌后 → 按方案排序手牌 → 存储区域索引
- 决策时 → 直接从区域取牌 → 更新手牌
- 调整时 → 重新排序手牌 → 更新区域索引

**区域索引 = 人类"手指分组"**：
- 炸弹区、顺子区、三带二区、对子区、单张区
- 每个区域有索引范围（start, end）
- 取牌时直接通过索引范围获取

#### 8.2.2 HandCardOrganizer实现

```python
class HandCardOrganizer:
    """手牌整理器（模拟人类整理手牌）"""
    
    def organize_by_grouping(self, hand_cards, grouping_plan):
        """
        按组牌方案整理手牌顺序
        
        输入：
        - hand_cards: 原始手牌列表 [Card, Card, ...]
        - grouping_plan: 组牌方案 {
            'bombs': [[3♠, 3♥, 3♦, 红桃2], [4♣, 4♠, 红桃4, 4♥]],
            'sequences': [[5♥, 红桃5, 6♦, 红桃6, 7♠, 红桃7, 8♣, 黑桃8, 9♥]],
            'triples': [[J♠, J♥, J♦]],
            'pairs': [[Q♥, Q♠], [K♦, K♣]],
            'singles': [A♣, 2♥, 小王, 大王]
          }
        
        输出：
        - organized_cards: 按组牌结构排序的手牌列表
        - card_regions: 区域索引 {
            'bomb_0': (0, 4),      # 炸弹0的索引范围
            'bomb_1': (4, 8),      # 炸弹1的索引范围
            'sequence_0': (8, 17), # 顺子0的索引范围
            'triple_0': (17, 20),  # 三张0的索引范围
            'pair_0': (20, 22),    # 对子0的索引范围
            'pair_1': (22, 24),    # 对子1的索引范围
            'single_0': (24, 25),  # 单张0
            'single_1': (25, 26),  # 单张1
            'single_2': (26, 27),  # 单张2
            'single_3': (27, 28),  # 单张3
          }
        """
        organized_cards = []
        card_regions = {}
        current_idx = 0
        
        # 1. 炸弹区（最高优先级）
        for i, bomb in enumerate(grouping_plan['bombs']):
            organized_cards.extend(bomb)
            card_regions[f'bomb_{i}'] = (current_idx, current_idx + len(bomb))
            current_idx += len(bomb)
        
        # 2. 顺子区
        for i, seq in enumerate(grouping_plan['sequences']):
            organized_cards.extend(seq)
            card_regions[f'sequence_{i}'] = (current_idx, current_idx + len(seq))
            current_idx += len(seq)
        
        # 3. 三带二区
        for i, triple in enumerate(grouping_plan['triples']):
            organized_cards.extend(triple)
            card_regions[f'triple_{i}'] = (current_idx, current_idx + len(triple))
            current_idx += len(triple)
        
        # 4. 对子区
        for i, pair in enumerate(grouping_plan['pairs']):
            organized_cards.extend(pair)
            card_regions[f'pair_{i}'] = (current_idx, current_idx + len(pair))
            current_idx += len(pair)
        
        # 5. 单张区
        for i, single in enumerate(grouping_plan['singles']):
            organized_cards.append(single)
            card_regions[f'single_{i}'] = (current_idx, current_idx + 1)
            current_idx += 1
        
        return organized_cards, card_regions
    
    def get_card_by_region(self, organized_cards, card_regions, region_name):
        """从指定区域取牌（模拟人类从对应位置取牌）"""
        start, end = card_regions[region_name]
        return organized_cards[start:end]
    
    def remove_cards(self, organized_cards, card_regions, cards_to_remove):
        """
        出牌后更新手牌（模拟人类从手中取出牌）
        
        输入：
        - organized_cards: 当前手牌
        - card_regions: 区域索引
        - cards_to_remove: 要出的牌 [Card, Card, ...]
        
        输出：
        - updated_cards: 更新后的手牌
        - updated_regions: 更新后的区域索引
        """
        # 1. 从organized_cards中移除cards_to_remove
        updated_cards = [c for c in organized_cards if c not in cards_to_remove]
        
        # 2. 重新计算区域索引
        updated_regions = self.recalculate_regions(updated_cards)
        
        return updated_cards, updated_regions
```

class GroupingPlanCache:
    """组牌方案缓存（记住多种方案）"""
    
    def __init__(self):

        """存储所有组牌方案"""
        self.original_hand = hand_cards.copy()
        self.plans = sorted(plans, key=lambda x: x.score, reverse=True)
        self.current_plan_idx = 0  # 默认使用最优方案
    
    def get_current_plan(self):
        """获取当前方案"""
        return self.plans[self.current_plan_idx]
    
    def switch_plan(self, new_plan_idx):
        """切换方案（动态调整）"""
        if 0 <= new_plan_idx < len(self.plans):
            self.current_plan_idx = new_plan_idx
            return True
        return False

#### 8.5.1 模块定位

#### 8.5.3 核心方法设计

**方法1：organize_by_grouping(hand_cards, grouping_plan)**

```python
def organize_by_grouping(self, hand_cards: List[str], grouping_plan: Dict) -> Tuple[List[str], Dict[str, Tuple[int, int]]]:
    """
    按组牌方案整理手牌顺序
    
    处理流程：
    1. 炸弹区（最高优先级）
    2. 顺子区（含同花顺）
    3. 三带二区（三张+对子）
    4. 对子区
    5. 单张区
    
    每个区域按索引顺序排列，记录 (start, end) 到 card_regions
    
    Returns:
        (organized_cards, card_regions)
    """
    organized_cards = []
    card_regions = {}
    current_idx = 0
    
    # 1. 炸弹区
    for i, bomb in enumerate(grouping_plan.get('bombs', [])):
        organized_cards.extend(bomb)
        card_regions[f'bomb_{i}'] = (current_idx, current_idx + len(bomb))
        current_idx += len(bomb)
    
    # 2. 顺子区
    for i, seq in enumerate(grouping_plan.get('sequences', [])):
        organized_cards.extend(seq)
        card_regions[f'sequence_{i}'] = (current_idx, current_idx + len(seq))
        current_idx += len(seq)
    
    # 3. 三带二区
    for i, triple in enumerate(grouping_plan.get('triples', [])):
        organized_cards.extend(triple)
        card_regions[f'triple_{i}'] = (current_idx, current_idx + len(triple))
        current_idx += len(triple)
    
    # 4. 对子区
    for i, pair in enumerate(grouping_plan.get('pairs', [])):
        organized_cards.extend(pair)
        card_regions[f'pair_{i}'] = (current_idx, current_idx + len(pair))
        current_idx += len(pair)
    
    # 5. 单张区
    for i, single in enumerate(grouping_plan.get('singles', [])):
        organized_cards.append(single)
        card_regions[f'single_{i}'] = (current_idx, current_idx + 1)
        current_idx += 1
    
    return organized_cards, card_regions
```

def get_card_by_region(self, organized_cards: List[str], card_regions: Dict[str, Tuple[int, int]], region_name: str) -> List[str]:
    """
    从指定区域取牌（模拟人类从对应位置取牌）
    
    Args:
        organized_cards: 整理后的手牌列表
        card_regions: 区域索引
        region_name: 区域名称（如 'bomb_0', 'sequence_0'）
    
    Returns:
        该区域的牌列表

        get_card_by_region(cards, regions, 'bomb_0')

    """

    return organized_cards[start:end]

**方法3：remove_cards(organized_cards, card_regions, cards_to_remove)**

```python
def remove_cards(self, organized_cards: List[str], card_regions: Dict[str, Tuple[int, int]], cards_to_remove: List[str]) -> Tuple[List[str], Dict[str, Tuple[int, int]]]:
    """
    出牌后更新手牌（模拟人类从手中取出牌）
    
    处理流程：
    1. 从 organized_cards 中移除 cards_to_remove
    2. 重新计算区域索引（保持剩余区域的相对顺序）
    
    Args:
        organized_cards: 当前手牌
        card_regions: 当前区域索引
        cards_to_remove: 要出的牌列表
    
    Returns:
        (updated_cards, updated_regions)
    """
    # 1. 移除出的牌
    updated_cards = [c for c in organized_cards if c not in cards_to_remove]
    
    # 2. 重新计算区域索引
    updated_regions = self._recalculate_regions(updated_cards, card_regions, cards_to_remove)
    
    return updated_cards, updated_regions

def _recalculate_regions(self, updated_cards: List[str], old_regions: Dict[str, Tuple[int, int]], removed_cards: List[str]) -> Dict[str, Tuple[int, int]]:
    """
    重新计算区域索引
    
    策略：
    - 保留未受影响的区域（移除的牌不在该区域）
    - 调整受影响的区域（索引偏移）
    - 移除空区域（该区域的牌全部出完）
    """
    updated_regions = {}
    current_idx = 0
    
    # 按原顺序遍历所有区域
    sorted_regions = sorted(old_regions.items(), key=lambda x: x[1][0])
    
    for region_name, (start, end) in sorted_regions:
        # 获取该区域在原手牌中的牌
        original_cards_in_region = updated_cards[start:end]  # 注意：这里需要用原organized_cards
        
        # 计算移除后剩余的牌
        remaining_cards = [c for c in original_cards_in_region if c not in removed_cards]
        
        if len(remaining_cards) > 0:
            # 保留该区域，更新索引
            updated_regions[region_name] = (current_idx, current_idx + len(remaining_cards))
            current_idx += len(remaining_cards)
        # else: 区域为空，不保留
    
    return updated_regions
```

### 8.7 组牌调用机制（2026-06-18新增）

#### 8.7.1 什么时候调用组牌？

**调用时机分为 4 个阶段**：

| 阶段 | 时机 | 触发条件 | 调用内容 |
|------|------|---------|---------|
| **阶段0：开局组牌** | 拿到27张手牌后 | 游戏开始 | 生成所有合法方案 → 评估 → 排序 |
| **阶段1：角色定位** | 组牌完成后 | 基于最优方案 | 使用排序第一的方案 |
| **阶段2：初期出牌** | 第1-5圈 | 使用最优方案 | 直接从最优方案取牌 |
| **阶段3：中期调整** | 第6-10圈或触发条件 | 动态重新组牌 | 基于剩余手牌重新生成方案 |
| **阶段4：残局** | 剩余≤10张 | 精确记忆 | 不再使用组牌，依赖记忆推断 |

**详细触发逻辑**：

```python
class GroupingCallManager:
    """组牌调用管理器"""
    
    def on_new_game(self, hand_cards, rank, tribute_state):
        """
        阶段0：开局组牌（必须调用）
        
        时机：游戏开始，拿到27张手牌
        调用：生成所有合法方案
        """
        # 1. 生成所有方案
        all_plans = self.grouping_engine.generate_all_plans(hand_cards)
        
        # 2. 评估每个方案
        for plan in all_plans:
            plan.score = self.evaluate_plan(plan)
        
        # 3. 排序
        all_plans.sort(key=lambda x: x.score, reverse=True)
        
        # 4. 存储所有方案
        self.plan_cache.store_plans(hand_cards, all_plans)
        
        # 5. 选择最优方案
        best_plan = all_plans[0]
        
        # 6. 整理手牌
        self.organized_cards, self.card_regions = \
            self.organizer.organize_by_grouping(hand_cards, best_plan)
        
        print(f"✅ 开局组牌完成：{len(all_plans)}个方案，最优={best_plan.score:.2f}")
    
    def decide_action(self, game_state):
        """
        阶段2/3/4：出牌决策
        
        判断是否需要重新组牌
        """
        # 判断是否需要重新组牌
        if self.need_replan(game_state):
            # 阶段3：动态调整（重新组牌）
            self.replan(game_state.remaining_cards)
        
        # 从当前方案取牌
        current_plan = self.plan_cache.get_current_plan()
        action = self.select_action_from_plan(current_plan, game_state)
        
        return action
    
    def need_replan(self, game_state) -> bool:
        """
        判断是否需要重新组牌
        
        触发条件：
        1. 原方案被压制（对手有更大牌型）
        2. 角色转换（主攻↔助攻）
        3. 手牌出过半（剩余<14张）
        4. 炸弹已使用（方案结构改变）
        """
        # 条件1：原方案被压制
        if self.memory.was_suppressed(self.plan_cache.get_current_plan()):
            return True
        
        # 条件2：角色转换
        new_role = self.determine_role_from_memory(game_state)
        if new_role != self.current_role:
            return True
        
        # 条件3：手牌出过半
        if len(game_state.remaining_cards) < 14:
            return True
        
        # 条件4：炸弹已使用
        if self.memory.bombs_used_count() > self.initial_bomb_count:
            return True
        
        return False
    
    def replan(self, remaining_cards):
        """
        阶段3：重新组牌（动态调整）
        
        时机：need_replan() 返回 True
        调用：基于剩余手牌重新生成方案
        """
        # 1. 重新生成方案
        new_plans = self.grouping_engine.generate_all_plans(remaining_cards)
        
        # 2. 评估+排序
        for plan in new_plans:
            plan.score = self.evaluate_plan_with_situation(plan, game_state)
        new_plans.sort(key=lambda x: x.score, reverse=True)
        
        # 3. 存储新方案
        self.plan_cache.store_plans(remaining_cards, new_plans)
        
        # 4. 选择最适合当前局势的方案（不一定是最优）
        best_plan = self.select_plan_for_situation(new_plans, game_state)
        self.plan_cache.switch_plan(new_plans.index(best_plan))
        
        # 5. 重新整理手牌
        self.organized_cards, self.card_regions = \
            self.organizer.organize_by_grouping(remaining_cards, best_plan)
        
        print(f"🔄 重新组牌完成：{len(new_plans)}个方案")
```

#### 8.7.2 多种方案的存储策略

**策略：存储所有合法方案，但只使用最优方案**

```python
class GroupingPlanCache:
    """组牌方案缓存"""
    
    def __init__(self):
        self.plans: List[GroupingPlan] = []      # 所有合法方案（排序）
        self.current_plan_idx: int = 0            # 当前使用的方案索引
        self.original_hand: List[str] = None      # 原始手牌
        self.plan_scores: List[float] = []        # 方案评分列表
    
    def store_plans(self, hand_cards, plans):
        """
        存储所有组牌方案
        
        输入：10-50个合法方案
        存储：按评分降序排序
        """
        self.original_hand = hand_cards.copy()
        self.plans = sorted(plans, key=lambda x: x.score, reverse=True)
        self.plan_scores = [p.score for p in self.plans]
        self.current_plan_idx = 0  # 默认使用最优方案
    
    def get_current_plan(self) -> GroupingPlan:
        """获取当前方案（默认最优）"""
        return self.plans[self.current_plan_idx]
    
    def get_top_n_plans(self, n=5) -> List[GroupingPlan]:
        """
        获取前N个方案（用于决策参考）
        
        用途：
        - 评估不同方案的出牌路径
        - 动态调整时对比
        """
        return self.plans[:n]
    
    def switch_plan(self, new_plan_idx):
        """
        切换方案（动态调整）
        
        时机：
        - 原方案被压制
        - 角色转换
        - 需要不同出牌策略
        """
        if 0 <= new_plan_idx < len(self.plans):
            self.current_plan_idx = new_plan_idx
            return True
        return False
    
    def get_plan_by_criteria(self, criteria: str) -> GroupingPlan:
        """
        按特定标准选择方案
        
        criteria:
        - 'max_bombs': 炸弹最多的方案
        - 'min_hands': 手数最少的方案
        - 'max_recovery': 回收能力最强的方案
        - 'best_for_attack': 最适合主攻的方案
        - 'best_for_support': 最适合助攻的方案
        """
        if criteria == 'max_bombs':
            return max(self.plans, key=lambda p: p.bomb_count)
        elif criteria == 'min_hands':
            return min(self.plans, key=lambda p: p.hand_count)
        elif criteria == 'max_recovery':
            return max(self.plans, key=lambda p: p.recovery_score)
        # ...

**决策流程**：

def select_action_from_plan(self, plan: GroupingPlan, game_state) -> Action:
    """
    从组牌方案中选择具体出牌
    
    输入：
    - plan: 当前组牌方案
    - game_state: 游戏状态（牌权、圈数、记忆等）
    
    输出：
    - Action: 具体出牌动作
    """
    current_round = game_state.current_round
    is_first_player = game_state.is_first_player
    role = self.current_role  # 主攻/助攻
    
    # 阶段2：初期出牌（第1-5圈）
    if current_round <= 5:
        return self.early_stage_decision(plan, game_state)
    
    # 阶段3：中期出牌（第6-10圈）
    elif current_round <= 10:
        return self.mid_stage_decision(plan, game_state)
    
    # 阶段4：残局（剩余≤10张）
    else:
        return self.end_stage_decision(game_state)

def early_stage_decision(self, plan, game_state) -> Action:
    """
    初期出牌决策（基于组牌方案）
    
    策略：
    - 主攻：先出不能回收的牌（保留大牌）
    - 助攻：出对家可能需要的牌型
    """
    role = self.current_role
    
    if role == '主攻':
        # 主攻策略：先出弱牌，保留回收能力
        # 1. 从单张区找最小单张
        if plan.singles:
            smallest_single = self.find_smallest_single(plan.singles)
            if self.can_recover('single', smallest_single, plan):
                # 能回收，出这个
                return Action(type='Single', cards=[smallest_single])
        
        # 2. 从对子区找最小对子
        if plan.pairs:
            smallest_pair = self.find_smallest_pair(plan.pairs)
            return Action(type='Pair', cards=smallest_pair)
        
        # 3. 从顺子区找最小顺子
        if plan.sequences:
            smallest_seq = plan.sequences[0]
            return Action(type='Sequence', cards=smallest_seq)
    
    elif role == '助攻':
        # 助攻策略：配合对家
        # 1. 对家出过什么牌型？
        partner_need = self.memory.query_partner_need()
        
        # 2. 出对家需要的牌型
        if partner_need == 'single' and plan.singles:
            return Action(type='Single', cards=[plan.singles[0]])
        elif partner_need == 'pair' and plan.pairs:
            return Action(type='Pair', cards=plan.pairs[0])
    
    # 默认：出最小单张
    return Action(type='Single', cards=[plan.singles[0]])

def mid_stage_decision(self, plan, game_state) -> Action:
    """
    中期出牌决策（动态调整）
    
    策略：
    - 根据记忆调整出牌
    - 考虑炸弹使用
    - 角色可能转换
    """
    # 1. 查询记忆
    safe_patterns = self.memory.get_safe_patterns()
    dangerous_patterns = self.memory.get_dangerous_patterns()
    
    # 2. 优先出安全牌型
    for seq in plan.sequences:
        if self.is_safe_sequence(seq, safe_patterns):
            return Action(type='Sequence', cards=seq)
    
    # 3. 出不能回收的牌
    for single in plan.singles:
        if not self.can_recover('single', single, plan):
            return Action(type='Single', cards=[single])
    
    # 4. 炸弹决策
    if self.need_use_bomb(game_state):
        bomb = plan.bombs[0]
        return Action(type='Bomb', cards=bomb)
    
    # 默认：出最小单张
    return Action(type='Single', cards=[plan.singles[0]])

def can_recover(self, card_type, card, plan) -> bool:
    """
    判断是否能回收
    
    例：出单张3，我有大王 → 能回收
    """
    if card_type == 'single':
        # 有更大的单张？
        for single in plan.singles:
            if self.card_value(single) > self.card_value(card):
                return True
    
    elif card_type == 'pair':
        # 有更大的对子？
        for pair in plan.pairs:
            if self.pair_value(pair) > self.pair_value(card):
                return True
    
    return False
```

| **2. 具体牌张** | 从区域索引中取具体牌 | 出单张 → 出3还是出5？ |
| **3. 出牌顺序** | 根据回收能力决定先后 | 先出不能回收的，保留能回收的 |

```python
class HumanLikeDecisionEngine:
    """类人决策引擎（完整集成）"""
    
    def __init__(self):
        self.grouping_engine = GroupingEngine()
        self.organizer = HandCardOrganizer()
        self.plan_cache = GroupingPlanCache()
        self.memory = MemoryTracker()
        self.call_manager = GroupingCallManager()
        
        self.organized_cards = []
        self.card_regions = {}
        self.current_role = None
        self.current_round = 0
    
    def on_new_game(self, hand_cards, rank, tribute_state):
        """新局开始"""
        # 阶段0：开局组牌
        self.call_manager.on_new_game(hand_cards, rank, tribute_state)
        
        # 阶段1：角色定位
        best_plan = self.plan_cache.get_current_plan()
        self.current_role = self.determine_role(best_plan, tribute_state)
    
    def decide_action(self, game_state) -> Action:
        """出牌决策"""
        self.current_round = game_state.current_round
        
        # 判断是否需要重新组牌
        if self.call_manager.need_replan(game_state):
            self.call_manager.replan(game_state.remaining_cards)
        
        # 从当前方案选择动作
        current_plan = self.plan_cache.get_current_plan()
        action = self.select_action_from_plan(current_plan, game_state)
        
        # 出牌后更新手牌
        self.organized_cards, self.card_regions = \
            self.organizer.remove_cards(
                self.organized_cards,
                self.card_regions,
                action.cards
            )
        
        # 更新记忆
        self.memory.update(action, game_state)
        
        return action
```

### 8.8 组牌方案设计问答记录（2026-06-18新增）

> 本节记录组牌方案设计过程中的关键问答，所有答案均基于项目文档确认。

#### 8.8.1 组牌方案的定义标准

**Q1：炸弹的认定标准是什么？**

**A**：根据 `docs/knowledge/rules/01_basic_rules/04_card_types_guide.md`：
- **标准炸弹**（`Bomb`）：4 张（含）以上牌点相同的单张
- **王炸**（特殊 `Bomb`）：大王（R）、小王（B）各两张
- **逢人配规则**：红桃（H）级牌可组合法牌型，但**不得与大王、小王组牌**

**Q2：顺子的长度限制？**

**A**：**固定 5 张**，不能多也不能少。同花顺也是固定 5 张。

**Q3：三带二的"二"必须是对子吗？**

**A**：是的，**必须是对子**（一个三张 + 一个对子）。

**Q4：钢板是否作为独立牌型？**

**A**：是的，**钢板是独立牌型**（`TwoTrips`）：两个牌点相邻的三张牌。

#### 8.8.1.5 六大组牌核心原则（从根源上掌控牌局）

| 序号 | 原则 | 核心目标 | 实施方法 |
|------|------|---------|---------|
| **1** | **最大限度去单化** | 消除致命短板 | 把单牌灵活组合成顺子、连对或三张 |
| **2** | **小火大轮次** | 避免过早暴露 | 初期用中等牌力试探，后期用大牌控场 |
| **3** | **尽量减少轮次** | 每一轮都要有效 | 预判对手牌型，用最少轮次出清手牌 |
| **4** | **炸弹数量与质量平衡** | 难上游时多囤炸 | 小炸弹多次控场，阻止对手上游 |
| **5** | **逢人配留变化** | 保持灵活性 | 初期观察，后期根据局势灵活组合 |
| **6** | **牌型连贯与互补** | 兼顾攻防 | 顺子、连对衔接配合，避免断层 |

---

**原则1：最大限度去单化**

**问题**：单牌是"致命短板"，一旦手里单牌过多，全程只能被动防守。

**核心做法**：把单牌灵活组合成顺子、连对或三张。

**示例**：单 3+4+5 → 345 顺子；既减少单牌，又提升灵活性。

---

**原则2：小火大轮次**

**问题**：拿着王炸、大炸弹就急于出手，容易陷入"后续无牌可出"的尴尬。

**核心做法**：初期用中等牌力试探，观察对手反应，摸清局势后再用大牌控场。

**示例**：先出对 10、顺子 34567 试探，摸清局势后再用王炸/大炸弹控场。

---

**原则3：尽量减少轮次**

**问题**：没必要的出牌就是浪费机会！

**核心做法**：出牌前预判对手牌型，用最少轮次出完手牌，不给对手反击机会。

**示例**：对手剩少量牌时，用炸弹直接压制抢出牌权，争取用最少轮次出清手牌。

---

**原则4：炸弹数量与质量平衡**

**问题**：如果自己牌型差、难率先出完，就要优先保"炸弹数量"而非"质量"。

**核心做法**：哪怕是小炸弹（比如四带二），多留几张也能在关键时刻连续炸牌。

**示例**：牌型差时，保留多张四带二，在关键时刻连续炸牌，为队友争取时间。

---

**原则5：逢人配留变化**

**问题**：`逢人配`是掼蛋的"万能牌"，过早组合就浪费了灵活性。

**核心做法**：初期先观察对手出牌，后期根据局势灵活组合，可组顺子、连对，甚至补成炸弹。

**示例**：初期逢人配暂不组合；后期根据局势灵活组合为顺子/连对/炸弹。

---

**原则6：牌型连贯与互补**

**问题**：组牌时要兼顾"进攻性"和"防守性"，避免"断层脱节"。

**核心做法**：顺子、连对尽量衔接（比如 34567 + 678910），不同牌型相互配合。

**示例**：34567 + 678910 衔接，既能应对单牌，也能压制对子、三张。

#### 8.8.2 角色定位与转换机制

**Q5：主攻/助攻的判定标准是什么？**

**A**：根据 `docs/knowledge/skills/07_opening/04_card_grouping_skills.md` 第 53-92 行，基于**牌力分数**：

| 牌力分数 | 角色定位 | 说明 |
|---------|---------|------|
| **8 分以上** | 主攻 | 超强牌 |
| **5-7 分** | 攻守兼备 | 强牌 |
| **2-4 分** | 助攻 | 中弱牌 |
| **1 分以下** | 未游 | 超弱牌 |
| **4-5 分临界** | 根据队友决定 | 队友主攻→选助攻；队友助攻→可尝试主攻 |

**牌力计分规则**：
1. 四个头登基牌炸弹以上 → +3 分
2. 四个头不是登基牌的炸弹 → +2 分
3. 登基牌（大王、对级牌、10-A 顺子、登基牌三带二、木板、钢板、逢人配） → +1 分
4. 赘牌（6 以下对子、10 以下单张等） → -1 分
5. 能够顺走的牌 → 0 分
6. 能获得出牌权或首发牌 → +1 分

**Q6：一局游戏中角色可以多次转换吗？**

**A**：**可以多次转换**。

原文（第 93 行）：
> "掼蛋就是这么神奇，在不同的情况下，助攻可转换成主攻，主攻也可以转换成助攻。6 分牌可以做主攻角色，但要根据牌局形势，及时转换为助攻。"

**转换触发条件**：
- 发现对家牌力更强 → 主攻转助攻
- 发现对家被压制、手牌弱 → 助攻转主攻
- 炸弹使用情况变化
- 手牌结构重大变化

├─ 时机成熟 → 打出大王收回牌权
└─ 下家反应：直接开炸
    ├─ 炸完剩 6 张
    ├─ 判断：下家第二手炸弹，手里已无剩余火牌
    └─ 我：立刻开火阻挡对手进攻

阶段4：助攻转主攻（第10圈+）
├─ 下家重新拿到出牌权，打出三带二
├─ 我：故意留出这个牌路，看能不能给对家送牌
├─ 对家：顺利接住三带二
├─ 分析：
│   ├─ 对家不是空炸
│   ├─ 上家还有一对 2
│   └─ 我：压上一对 K
├─ 对手：用一对级牌压制
├─ 判断：下家和对家都不是空炸（是空炸早走牌了）
├─ 对手还有剩余牌力
│
│  【关键转换点】
│  ├─ 对手炸弹消耗大半
│  ├─ 对家牌型暴露
│  └─ 我方牌权可控
│
├─ 转换决策：助攻 → 主攻
│   ├─ ✅ 主动打出大三带二
│   ├─ 目的：消耗上家剩余牌力
│   └─ 试探：上家是否还藏有炸弹
│
├─ 上家：不要
├─ 我：打出小六
├─ 我：直接空炸（给对家借风铺路）

**转换判断依据**：

| 判断维度 | 具体指标 | 示例 |
|---------|---------|------|
| **对手炸弹消耗** | 已出炸弹数量 vs 推断总数 | 下家已出 2 炸，推断无剩余火牌 |
| **对家牌型暴露** | 对家出牌信号 | 对家能接三带二，不是空炸 |
| **我方牌权可控** | 有大牌控场 | 大王已出，但手牌结构完整 |
| **对手剩余牌力** | 是否还能压制 | 上家有大对子，但无炸弹 |

**助攻准则**：

| 准则 | 说明 | 违反后果 |
|------|------|---------|
| **不越级压牌** | 对家出牌，不要强行压制 | 打乱对家节奏 |
| **不抢牌权** | 把轮次交给对家处理 | 对家无法顺牌 |
| **保留大牌控场** | 大王/炸弹留到关键时候 | 提前暴露，失去威慑 |
| **消化自身小单** | 顺势过掉小牌 | 后期被小单卡死 |

**转换时机总结**：

```python
def should_convert_to_attacker(self, game_state) -> bool:
    """
    判断是否应该从助攻转换为主攻
    
    触发条件（全部满足）：
    1. 对手炸弹消耗大半
    2. 对家牌型已暴露（不是空炸）
    3. 我方牌权可控
    4. 对家开始跑牌（剩牌少）
    """
    # 条件1：对手炸弹消耗
    opponent_bombs_used = self.memory.get_opponent_bombs_used()
    opponent_bombs_total = self.memory.estimate_opponent_bombs_total()
    if opponent_bombs_used < opponent_bombs_total * 0.6:
        return False  # 炸弹还没消耗大半
    
    # 条件2：对家牌型暴露
    partner_hand_type = self.memory.infer_partner_hand_type()
    if partner_hand_type == '未知' or partner_hand_type == '空炸':
        return False  # 对家牌型不明
    
    # 条件3：我方牌权可控
    if not self.can_control_power():
        return False  # 无法控场
    
    # 条件4：对家开始跑牌
    if self.memory.get_partner_remaining_cards() > 10:
        return False  # 对家还不需要送牌
    
    return True  # 满足所有条件，转换为主攻
```

**关键洞察**：

1. **助攻转主攻不是牌力变强，而是局势变化**
   - 初始牌力 3 分（弱牌）
   - 但对手炸弹消耗、对家牌型暴露、牌权可控
   - 此时转换为主攻，创造跑牌机会

2. **转换前必须完成助攻任务**
   - 帮对家顺牌
   - 消耗对手火力
   - 留存大牌控场

3. **转换后主动控局**
   - 主动打出大牌消耗对手
   - 试探对手是否还有炸弹
   - 给对家借风铺路

#### 8.8.3 回收能力评估（K 原则）

**Q7："能收回"的定义是什么？**

**A**：**K 原则**（开局和中局的重要原则）：

> **出牌必须能收回，领出牌型要有 K（含级牌）以上的牌型。**

**具体标准**：

| 牌型 | K 原则要求 | 示例 |
|------|-----------|------|
| **单张** | 手牌中有 K 以上单牌 | 出单张 3，手中有大王/小王/级牌/A/K |
| **对子** | 手牌中有 KK 以上对子 | 出对子 55，手中有对 A/对级牌/对 K |
| **顺子** | 手牌中有更大顺子 | 出 34567，手中有 89JQK 或更大 |
| **三带二** | 手牌中有更大三带二 | 出 333+55，手中有 AAA+KK 或更大 |

**评估范围**：

| 阶段 | 评估范围 | 说明 |
|------|---------|------|
| **开局初期**（1-5 圈） | 只考虑自己手牌 | 不依赖队友支援 |
| **中后期**（6 圈+） | 可考虑队友可能支援 | 根据记忆推断队友牌力 |

**K 原则的例外情况**：

| 例外 | 说明 | 示例 |
|------|------|------|
| **残局阶段**（≤10 张） | 不再严格遵循 K 原则，依赖精确记忆 | 剩 8 张，出单张 5，不管能否收回 |
| **助攻配合** | 明知队友能接住，可以出小于 K 的牌 | 推断对家有对 A，出对 8 送牌 |
| **炸弹压制** | 有炸弹兜底，可以临时打破 K 原则 | 手有王炸，出单张 6 试探 |
| **钢板/木板** | 钢板（TwoTrips）和木板不用遵循 K 原则 | 出钢板 333444，不需要更大钢板兜底 |
| **三张牌** | 三同张牌型不用遵循 K 原则 | 出三张 555，不需要更大三张兜底 |
| **级牌为 K** | 级牌如为 K，则 K 原则可降为 Q | 级牌 6，出单张 5，手中有 Q 即可 |

**例外详细说明**：

**1. 钢板/木板例外**

钢板（两个相邻三张）和木板（两个不相邻三张）是特殊牌型，不需要遵循 K 原则：

```python
def is_k_principle_exempt(card_type) -> bool:
    """
    判断是否豁免 K 原则
    
    钢板/木板/三张不需要 K 原则兜底
    """
    exempt_types = [
        'two_trips',    # 钢板：333444
        'wood_board',   # 木板：333555
        'trip',         # 三张：333
    ]
    return card_type in exempt_types
```

**理由**：
- 钢板/木板是稀有牌型，对手很难有更大钢板/木板
- 三张牌型本身就有较高牌力，不易被压制
- 这类牌型的回收概率天然较高

**2. 级牌为 K 时的降级**

当级牌为 K 时，K 原则可降为 Q：

```python
def get_k_threshold(self, rank_card) -> str:
    """
    获取 K 原则的阈值
    
    级牌为 K 时，阈值降为 Q
    其他情况，阈值为 K
    """
    if rank_card == 'K':
        return 'Q'  # 级牌为 K，K 原则降为 Q
    else:
        return 'K'  # 正常情况，阈值为 K

def can_recover_with_rank_adjustment(self, card_type, card, plan, rank_card) -> bool:
    """
    考虑级牌调整的 K 原则检查
    """
    threshold = self.get_k_threshold(rank_card)
    
    if card_type == 'single':
        # 手牌中必须有 threshold 以上单牌
        threshold_value = self.get_card_value(threshold)
        return any(
            self.get_card_value(s) >= threshold_value 
            for s in plan.singles
        )
```

**示例**：
- 级牌 6，出单张 5，手中有 Q/A/K/大王/小王 → 符合 K 原则（降为 Q）
- 级牌 6，出单张 5，手中有 J → 不符合 K 原则（J < Q）
- 级牌 K，出单张 Q，手中有 K/A/大王/小王 → 符合 K 原则（阈值为 K）

**K 原则的实施**：

```python
def can_recover_by_k_principle(self, card_type, card, plan, round_num) -> bool:
    """
    根据 K 原则判断是否能回收
    
    Args:
        card_type: 牌型类型
        card: 要出的牌
        plan: 当前组牌方案
        round_num: 当前圈数
    
    Returns:
        bool: 是否符合 K 原则
    """
    # 开局初期：严格要求 K 原则
    if round_num <= 5:
        if card_type == 'single':
            # 手牌中必须有 K 以上单牌
            k_threshold = self.get_card_value('K')
            has_bigger = any(
                self.get_card_value(s) > k_threshold 
                for s in plan.singles
            )
            return has_bigger
        
        elif card_type == 'pair':
            # 手牌中必须有 KK 以上对子
            return self.has_pair_above('K', plan.pairs)
        
        elif card_type == 'sequence':
            # 手牌中必须有更大顺子
            return self.has_bigger_sequence(card, plan.sequences)
    
    # 中后期：可考虑队友支援
    else:
        # 自己能回收，或队友可能接住
        return self.can_recover_or_partner_can_help(card_type, card, plan)
```

#### 8.8.4 动态调整的代价

**Q8：重新组牌的计算开销是否可接受？**

**A**：**不建议每次都重新组牌**。

**确认策略**：
- **首次组牌**（游戏开始时）：生成 **2 个最优组牌方案**
  - 根据牌力分数选择主次方案
  - 牌力强（8+ 分）→ 主攻方案为主
  - 牌力弱（<5 分）→ 助攻方案为主
- **渐进调整**（局势变化时）：
  - **不重新生成全部方案**
  - 基于原始方案进行局部调整
  - 调整类型：拆炸弹/拆顺子/改带牌/改级牌
- **重大调整**（角色转换时）：
  - 重新评估原始 2 个方案的适用性
  - 必要时重新生成方案（最多 2-3 个）

**关键原则**：

| 原则 | 说明 | 理由 |
|------|------|------|
| **不每次都重新组牌** | 避免计算开销和决策混乱 | 保持组牌一致性 |
| **首次生成 2 个方案** | 主攻方案和助攻方案各一个 | 应对不同局势 |
| **渐进调整优先** | 局部调整优于全部重生成 | 保留原始逻辑 |
| **重大调整才重生成** | 角色转换或结构重大变化 | 必要时才改变 |

**实施示例**：

```python
def update_card_groups(self, game_state) -> None:
    """
    更新组牌方案（渐进式）
    
    策略：
    1. 首次组牌：生成 2 个最优方案
    2. 常规调整：局部调整原始方案
    3. 重大调整：重新评估并生成新方案
    """
    if not self.card_groups:
        # 首次组牌
        self.card_groups = self.generate_initial_plans(count=2)
        self.primary_plan = self.select_primary_plan()
        self.backup_plan = self.select_backup_plan()
        return
    
    # 判断是否需要重大调整
    if self.need_major_adjustment(game_state):
        # 重新评估原始方案
        self.reassess_existing_plans()
        # 必要时生成新方案（最多 2-3 个）
        if len(self.card_groups) < 2:
            new_plans = self.generate_initial_plans(count=2 - len(self.card_groups))
            self.card_groups.extend(new_plans)
        return
    
    # 常规渐进调整
    self.adjust_primary_plan_locally(game_state)

def adjust_primary_plan_locally(self, game_state) -> None:
    """
    局部调整主方案
    
    调整类型：
    1. 拆炸弹（炸弹被压制）
    2. 拆顺子（顺子无法收回）
    3. 改带牌（三带二改为三带一）
    4. 改级牌（逢人配重新分配）
    """
    plan = self.primary_plan
    
    for group in plan.groups:
        if group.type == 'bomb' and self.is_bomb_suppressed(group):
            # 炸弹被压制，考虑拆开
            self.try_split_bomb(group)
        
        elif group.type == 'straight' and not self.can_recover(group):
            # 顺子无法收回，考虑拆开
            self.try_split_straight(group)
        
        elif group.type == 'three_with_two':
            # 三带二，考虑是否改为三带一
            if self.need_change_carry(group):
                self.try_change_carry(group)
```

```python
def scan_available_plays(self, remaining_cards) -> List[CardType]:
    """
    后期扫描手牌，找出所有可出牌型
    
    人类视角：不重新组牌，只扫描剩余手牌
    """
    available = []
    
    # 1. 扫描炸弹
    bombs = self.find_bombs(remaining_cards)
    available.extend([('bomb', b) for b in bombs])
    
    # 2. 扫描三张（可组三带二/三带一）
    trips = self.find_trips(remaining_cards)
    available.extend([('trip', t) for t in trips])
    
    # 3. 扫描对子
    pairs = self.find_pairs(remaining_cards)
    available.extend([('pair', p) for p in pairs])
    
    # 4. 扫描单张
    singles = self.find_singles(remaining_cards)
    available.extend([('single', s) for s in singles])
    
    # 5. 扫描顺子（如有逢人配）
    if self.has_wild_card(remaining_cards):
        straights = self.find_straights_with_wild(remaining_cards)
        available.extend([('straight', s) for s in straights])
    
    return available

def select_play_from_scan(self, available_plays, game_state) -> Action:
    """
    从扫描结果中选择出牌
    
    优先级：
    1. 助攻阶段：小单 → 对子 → 三带二（给对家送牌）
    2. 主攻阶段：大牌 → 炸弹 → 三带二（消耗对手）
    """
    if self.role == 'assistant':
        # 助攻：优先消化小单
        singles = [p for p in available_plays if p[0] == 'single']
        if singles:
            return Action(type='Single', cards=[min(singles, key=lambda x: x[1].rank)])
    
    elif self.role == 'attacker':
        # 主攻：主动消耗对手
        big_trips = [p for p in available_plays if p[0] == 'trip' and p[1].rank >= 'K']
        if big_trips:
            return Action(type='ThreeWithTwo', cards=big_trips[0])
    
    # 默认：按牌型优先级选择
    return self.select_by_priority(available_plays)
```

#### 8.8.5 初期试探期的组牌策略

**Q10：初期试探的具体策略是什么？**

**A**：根据手牌情况选择开局打法，核心是**收集信息**而非跑牌。

**策略A：无变化单张探路（戴长胜教学）**

**核心口诀**：
> **局势不明，无变单张先行；先打短牌探路，后定进攻路线。**

**适用场景**：
- 首发没有强势大牌
- 缺大王
- 手里零散单张多
- 局势不明（四家牌型全是未知）

**什么是"无变化的牌"**：
> 手里孤立的小单张，打出去之后，**不会拆掉你手上的顺子、同花、炸弹、对子**，打完不破坏你整手牌的组合结构。

**示例**：
- ✅ 单独一张 10、单 6、单 9（多余小单）
- ❌ 顺子中的牌（如 34567 中的 5）
- ❌ 炸弹中的牌
- ❌ 对子中的牌

**探路三大好处**：

| 好处 | 说明 | 示例 |
|------|------|------|
| **1. 隐藏真实牌力** | 对手猜不透你手里有什么大牌、有没有炸弹 | 出单 10，对手不知道你有 2 炸 |
| **2. 快速摸清大牌分布** | 记录大小王、2、A、K、红桃配在哪家 | 下家顶大王→大王在下方 |
| **3. 提前消耗零散单张** | 打到后期不用一堆小单兜底、被动挨压 | 先出单 10、单 6，后期手牌更整 |

根据手牌类型选择开局策略：

| 打法 | 适用手牌 | 策略 | 出牌示例 |
|------|---------|------|---------|
| **试探型** | 中等牌（好坏掺半） | 出中等对子/三连张，不暴露弱点，试探对手抗压能力 | 对子 77、88；三连对 556677 |
| **稳控型** | 一般牌/烂牌偏多 | 不出零散小单张，优先出成型小牌组，保留大牌防守 | 小顺子 34567、小三带二 333+55 |
| **压制型** | 天胡牌（大牌多、牌型整齐） | 中等大牌开路，主动抢占出牌权，压制对手 | 对子 QQ、KK；顺子 89JQK |

**按手牌选开局的差异化策略**：

| 手牌特征 | 开局策略 | 避免 |
|---------|---------|------|
| **散乱零碎**（单牌多、不成型） | 优先出连体牌、小顺子，打包走牌 | ❌ 乱出小单张 |
| **整齐规整**（对子/钢板/顺子齐全） | 中等牌型开局，稳中求进，保留大牌后手 | ❌ 开局就出大牌 |
| **大牌居多**（王/大牌/炸弹多） | 强势出牌，主动进攻，逼对手拆大牌 | ❌ 保守出小牌 |

---

**两种策略的关系**：

| 维度 | 无变化单张探路 | 三种开局打法 |
|------|--------------|-------------|
| **核心目标** | 收集信息（大牌分布） | 根据手牌类型选择策略 |
| **适用场景** | 局势不明、缺大牌 | 所有手牌情况 |
| **优先级** | 首发首选 | 根据手牌分类选择 |
| **配合使用** | 探路后 → 根据信息选择后续打法 | 开局后 → 可能转为探路 |

**完整开局决策流程**：

```python
def opening_decision(self, plan, game_state) -> Action:
    """
    开局决策（第1-3圈）
    
    流程：
    1. 判断是否适合无变化单张探路
    2. 如果不适合，按手牌类型选择开局打法
    """
    # 步骤1：检查是否有无变化单张
    no_change_singles = self.find_no_change_singles(plan)
    
    if no_change_singles and self.should_probe(game_state):
        # 策略A：无变化单张探路
        probe_card = min(no_change_singles, key=lambda c: self.card_value(c))
        return Action(type='Single', cards=[probe_card])
    
    # 步骤2：按手牌类型选择开局打法
    hand_type = self.classify_hand_type(plan)
    
    if hand_type == '中等牌':
        # 试探型：出中等对子/三连张
        medium_pairs = [p for p in plan.pairs if 7 <= self.pair_rank(p) <= 12]
        if medium_pairs:
            return Action(type='Pair', cards=medium_pairs[0])
    
    elif hand_type == '烂牌':
        # 稳控型：出成型小牌组
        if plan.sequences:
            small_seq = min(plan.sequences, key=lambda s: self.sequence_rank(s))
            return Action(type='Sequence', cards=small_seq)
    
    elif hand_type == '天胡牌':
        # 压制型：中等大牌开路
        big_pairs = [p for p in plan.pairs if self.pair_rank(p) >= 10]
        if big_pairs:
            return Action(type='Pair', cards=big_pairs[0])
    
    # 默认：出最小单张
    return Action(type='Single', cards=[plan.singles[0]])

def find_no_change_singles(self, plan) -> List[str]:
    """
    找出无变化单张
    
    定义：打出去不会破坏任何牌型组合的孤立单张
    """
    no_change = []
    
    for single in plan.singles:
        # 检查这张牌是否属于任何组合
        is_part_of_combo = False
        
        # 检查是否在顺子中
        for seq in plan.sequences:
            if single in seq:
                is_part_of_combo = True
                break
        
        # 检查是否是对子拆开后的单张
        # （如果是，说明原方案中有对子，这张不是孤立单张）
        
        if not is_part_of_combo:
            no_change.append(single)
    
    return no_change

def should_probe(self, game_state) -> bool:
    """
    判断是否应该探路
    
    条件：
    - 首发没有强势大牌
    - 缺大王
    - 手里零散单张多
    - 局势不明
    """
    # 检查是否有大王
    has_big_king = self.has_card('big_king')
    
    # 检查手牌是否散乱
    is_scattered = self.is_hand_scattered()
    
    # 检查是否首发
    is_first_turn = game_state.current_round == 1
    
    return is_first_turn and (not has_big_king or is_scattered)
```

**探路阶段的 K 原则应用**：

| 开局类型 | K 原则要求 | 说明 |
|---------|-----------|------|
| **无变化单张探路** | 不需要严格遵循 | 探路目的是收集信息，不是为了收回牌权 |
| **试探型** | 必须有 K 以上回收牌 | 出中等对子 77，手中有对 A/对 K 能收回 |
| **稳控型** | 必须有炸弹或大牌兜底 | 出小顺子 34567，手中有炸弹或大王能夺回牌权 |
| **压制型** | 出牌本身就是大牌 | 出对子 KK，本身就是大牌，不需要额外回收 |

**关键洞察**：

1. **探路不是为了走牌，而是为了收集信息**
   - 记录大牌位置（王、2、A、K）
   - 推断对手牌力分布
   - 为后续决策提供依据

2. **探路后必须根据信息调整策略**
   - 对手强→保守，配合对家
   - 对手弱→进攻，主动压制
   - 对家强→送对家需要的牌型

3. **新手循序渐进练习**
   - 重点锻炼记牌、算牌能力
   - 不要只机械模仿出牌
   - 实战要结合手牌、进贡还贡、对手风格灵活调整

```python
def probe_stage_decision(self, plan, game_state) -> Action:
    """
    试探型开局决策（第1-3圈）
    
    目标：
    - 不暴露弱点
    - 不浪费大牌
    - 试探对手抗压能力
    """
    # 判断手牌类型
    hand_type = self.classify_hand_type(plan)
    
    if hand_type == '中等牌':
        # 试探型：出中等对子/三连张
        # 中等对子：77-QQ
        medium_pairs = [p for p in plan.pairs if 7 <= self.pair_rank(p) <= 12]
        if medium_pairs:
            return Action(type='Pair', cards=medium_pairs[0])
        
        # 或三连对
        if plan.three_pairs:
            return Action(type='ThreePair', cards=plan.three_pairs[0])
    
    elif hand_type == '烂牌':
        # 稳控型：出成型小牌组
        # 小顺子
        if plan.sequences:
            small_seq = min(plan.sequences, key=lambda s: self.sequence_rank(s))
            return Action(type='Sequence', cards=small_seq)
        
        # 小三带二
        if plan.triples and plan.pairs:
            return Action(type='ThreeWithTwo', cards=plan.triples[0] + plan.pairs[0])
    
    elif hand_type == '天胡牌':
        # 压制型：中等大牌开路
        # 中大对子
        big_pairs = [p for p in plan.pairs if self.pair_rank(p) >= 10]
        if big_pairs:
            return Action(type='Pair', cards=big_pairs[0])
        
        # 大顺子
        if plan.sequences:
            big_seq = max(plan.sequences, key=lambda s: self.sequence_rank(s))
            return Action(type='Sequence', cards=big_seq)
    
    # 默认：出最小单张
    return Action(type='Single', cards=[plan.singles[0]])

def classify_hand_type(self, plan) -> str:
    """
    分类手牌类型
    
    Returns:
        '天胡牌' / '中等牌' / '烂牌'
    """
    score = self.calculate_hand_score(plan)
    
    if score >= 8:
        return '天胡牌'
    elif score >= 4:
        return '中等牌'
    else:
        return '烂牌'
```
