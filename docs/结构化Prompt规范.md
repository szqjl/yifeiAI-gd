# 结构化Prompt规范

**创建时间**: 2025-12-09  
**目的**: 规范用户与AI的交互指令，提高指令明确性和执行效率  
**适用范围**: 掼蛋AI项目的所有开发、训练、调试任务

---

## 📊 当前指令明确性评估

### ✅ 明确的指令示例

1. **具体操作类**
   - ✅ "推送更新" - 明确，执行git push
   - ✅ "删除不再需要的测试、分析、调试等工具" - 明确，清理临时文件
   - ✅ "更新阶段0、1、2、3文档" - 明确，更新指定文档

2. **具体文件操作**
   - ✅ "@文件路径 更新这个文档" - 明确，指定了文件
   - ✅ "检查是否完成了" - 明确，检查任务完成状态

### ⚠️ 需要猜测的指令示例

1. **缺少上下文**
   - ⚠️ "继续实施阶段3" - 需要查看文档了解具体任务
   - ⚠️ "运行训练测试" - 需要猜测是哪个训练脚本
   - ⚠️ "在796样本上重新测试" - 需要猜测测试什么

2. **缺少范围**
   - ⚠️ "实施这些改进" - 需要查看上下文了解改进内容
   - ⚠️ "按建议实施" - 需要查看之前的建议

3. **缺少参数**
   - ⚠️ "训练模型" - 需要猜测训练参数、数据量等
   - ⚠️ "评估模型" - 需要猜测评估指标、评估脚本

## 🎯 是否需要结构化Prompt？

### 结论：**强烈建议使用结构化Prompt**

**理由**：

1. **项目复杂性高**
   - 多模块：训练、决策、知识库、通信
   - 多阶段：阶段0-3，每个阶段多个任务
   - 多文档：训练文档、架构文档、知识库文档

2. **指令不明确导致的问题**
   - ❌ 理解偏差：AI需要猜测用户意图
   - ❌ 重复询问：需要多次确认才能执行
   - ❌ 执行错误：理解错误导致操作错误
   - ❌ 效率低下：来回沟通浪费时间

3. **结构化Prompt的优势**
   - ✅ 明确指令格式：减少理解偏差
   - ✅ 提供上下文信息：AI无需猜测
   - ✅ 规范操作流程：确保操作正确
   - ✅ 减少误解：结构化信息更清晰

## 📋 结构化Prompt模板

### 模板1：训练任务

```
【训练任务】
- 任务类型：[预训练/强化学习/评估/调试]
- 阶段：[阶段0/阶段1/阶段2/阶段3]
- 具体任务：[任务名称或描述]
- 数据量：[样本数量，如796/33,023]
- 训练参数：[epochs, batch_size, lr等，可选]
- 预期目标：[期望达到的效果]
- 参考文档：[相关文档路径，可选]
```

**示例**：
```
【训练任务】
- 任务类型：预训练
- 阶段：阶段0
- 具体任务：使用课程学习训练基础模型
- 数据量：33,023个样本
- 训练参数：epochs=100, batch_size=64, lr=0.0003
- 预期目标：卡牌识别准确率≥99%，牌型识别准确率≥70%
- 参考文档：docs/training/阶段0-实施基础验证.md
```

## 📝 使用建议

### 1. 根据任务复杂度选择模板

- **简单任务**：使用简化版模板
- **复杂任务**：使用完整模板
- **多步骤任务**：使用综合任务模板

### 2. 必填字段和可选字段

- **必填**：任务类型、具体内容
- **可选**：参考文档、影响范围、测试要求等

### 3. 逐步完善

- 开始时可以使用简化版
- 如果AI需要更多信息，再补充完整信息
- 逐步形成习惯

## 🔄 与现有工作流的结合

### 当前工作流

1. 用户给出指令
2. AI理解指令（可能需要猜测）
3. AI执行操作
4. 如有问题，AI询问或用户补充

### 使用结构化Prompt后的工作流

1. 用户使用结构化模板给出指令
2. AI直接理解（无需猜测）
3. AI执行操作
4. 如有问题，基于结构化信息快速定位

## ⚠️ 注意事项

1. **不要过度结构化**
   - 简单任务不需要完整模板
   - 根据实际情况选择模板

2. **保持灵活性**
   - 模板是指导，不是强制
   - 可以根据需要调整

3. **逐步养成习惯**
   - 开始时可能不习惯
   - 逐步使用，形成习惯

4. **与AI配合**
   - 如果AI需要更多信息，会主动询问
   - 可以根据AI的询问补充信息
