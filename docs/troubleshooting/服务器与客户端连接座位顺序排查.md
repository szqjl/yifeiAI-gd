# 服务器与客户端连接、座位顺序排查方案

## 背景

第二项任务（队友/对方识别）已通过「同步服务器 myPos」修复压制队友问题，但存在不确定性：

- 服务器在**多客户端连接**时，如何分配座位（按连接顺序？按客户端标识？）。
- 若连接顺序与预期不一致（如 yf1 后连、yf2 先连），或消息里 `myPos` 与真实座位不符，仍可能导致座位错乱、误判队友。

需在联调/对局中**可重复地验证**：服务器下发的 `myPos` 与各客户端实际座位是否一致，以及连接顺序是否影响分配。

---

## 排查思路概览

1. **打点日志**：在各客户端收到「游戏开始」或「首次 act」时，把**原始消息中的座位相关字段**和**本地同步后的 `self.player_id`** 打出，便于对局后对照。
2. **可选：轻量诊断脚本**：连接服务器后只收包、不决策，打印每条消息里的 `myPos`/`playerPosition`/连接顺序，跑一局即可看到四家分配。
3. **对照清单**：用一份清单在真机/联调时逐项确认，避免遗漏。

## 2026-02-27 一局排查结论（示例）

**日志**：`logs/yf1_m1_20260227_210123.log`、`logs/yf2_m1_20260227_210138.log`

| 客户端 | 原始 myPos | 同步后 player_id | 结论     |
|--------|------------|------------------|----------|
| yf1_m1 | 0          | 0                | 正确     |
| yf2_m1 | 2          | 2                | 正确     |

- 服务器下发的座位与客户端期望一致（yf1→0、yf2→2），0 与 2 为队友，座位识别正确。
- **额外发现**：act 请求里服务器可能不带 `myPos`，决策层（stage_router）用默认值 0，导致 yf2_m1 在决策时被当成 0 号位（如日志中 `my_pos=0`）。已在 M1 客户端在调用 `decide(data)` 前注入 `data["myPos"] = self.player_id`，保证决策层始终用已同步的座位。

## 2. 可选：连接与座位诊断脚本

思路：启动 1～4 个「只连接、只收包」的客户端，不参与决策，只打印：

- 连接成功顺序（谁先 `connect` 完成）。
- 每条消息中的 `type`、`stage`、`myPos`、`playerPosition`（若有）、以及 `handCards` 长度（用于判断是否开局）。

实现方式可二选一：

- **方式 A**：在现有某个客户端（如 yf1_m1）加「诊断模式」命令行参数，例如 `--diagnose-seat-only`，该模式下只连接、只打印上述字段、不调用决策、不发送出牌。
- **方式 B**：单独写一个 `diagnose_seat_order.py`，复用现有 `WebSocketManager` 或连接逻辑，只订阅同一游戏端口的消息并打印上述内容。

跑一局后即可看到：四家连接顺序与四条「游戏开始/首次 act」里的 `myPos` 对应关系，从而确认「服务器是否按连接顺序分配 0/1/2/3」或是否有其它规则。

## 3. 联调时的对照清单（明天可逐项勾）

- [ ] **单客户端**：只开一个客户端，看服务器是否固定给 0（或固定给某一号）；多开几局看 `myPos` 是否稳定。
- [ ] **双客户端**：开 yf1 + yf2，看两边的 `myPos` 是否分别为 0 和 2；若服务器按连接顺序，先连的应为 0，后连的为 2（或 1）；记录谁先连、谁后连。
- [ ] **四客户端**：四家都开，看 0/1/2/3 是否与连接顺序一致；若不一致，记录「连接顺序 → 实际分配到的 myPos」。
- [ ] **多局**：同一组客户端连续打多局，看每局各客户端的 `myPos` 是否不变；若变，说明服务器可能每局重排座位或按其它规则分配。
- [ ] **日志搜 [座位排查]**：确认每条记录里「原始 myPos」与「同步后 player_id」一致；若曾出现不一致，说明有中间状态或其它消息覆盖，需再查。

---

## 4. 若发现座位错乱可采取的后续动作

- **若服务器按连接顺序分配**：在启动脚本里固定客户端启动顺序（如先起 yf1_m1、再 yf2_m1、再对家），并保证连接间隔（如已有 `DELAY_BEFORE_CONNECT`），避免抢连导致顺序颠倒。
- **若服务器按客户端 ID/用户名分配**：确认各客户端 `user_info`/标识与服务器约定一致，且服务器文档里明确 0/1/2/3 与标识的对应关系。
- **若 myPos 在局中或某条消息里会变**：在客户端做「同一局内 myPos 只允许在开局或首次 act 时更新一次」的约束，避免中途被错误覆盖；若业务上确实会变，再与服务器约定并在文档里写明。
