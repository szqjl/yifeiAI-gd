## 一、欢乐掼蛋 AI 深度解析（网易数智技术方案）

### 1.1 技术方案

欢乐掼蛋采用的是**模仿学习**（Imitation Learning），而非强化学习。

**为什么选模仿学习：**

| 对比维度 | 行为树 | 强化学习 | 模仿学习 |
|---------|--------|----------|---------|
| 样本效率 | 中等 | 低（大量试错） | **高** |
| 策略复杂度 | 受限 | 难以收敛 | **优秀** |
| 适应性 | 维护成本高 | 对环境敏感 | **强** |
| 人类智慧传承 | 否 | 否 | **是** |

### 1.2 牌态编码方案（网易数智公开）

```
状态矩阵：10 × 9 × 14

分层编码：
├─ 基础卡牌（9×14）：除逢人配、大小王外普通牌
├─ 级牌/逢人配（3×14）：红心级牌，可变任意牌
└─ 王牌（2×14）：大小王信息

历史编码：前8次出牌 × 9×14
其他信息：手牌数、级牌、回合信息、剩余手牌数
```

**特征维度估算：** ~1000+ 维输入向量

### 1.3 核心能力评估

| 能力 | 水平 | 说明 |
|------|------|------|
| 单人出牌决策 | ⭐⭐⭐⭐ | 业余~高手，能计算牌力 |
| 配合队友 | ⭐⭐⭐ | **最大短板**，信号理解弱 |
| 段位适配 | ⭐⭐⭐⭐ | 支持动态难度调节 |
| 拟人化 | ⭐⭐ | 几乎无，过度完美 |
| 教学复盘 | ⭐⭐⭐ | 有基础复盘功能 |

## 二、大模型打掼蛋（清华唐杰团队研究 2025）

### 2.1 研究背景

清华、北邮、智谱、博世AI团队联合研究，让大模型学习8种棋牌游戏。

### 2.2 核心结论

**微调后模型 vs API模型 vs 基础模型：**

| 模型类型 | 表现 | 说明 |
|---------|------|------|
| 基础模型（Qwen/Llama/GLM） | ⭐⭐ | 很差，几乎不会打 |
| **GLM4-9B-Chat-mix（微调）** | **⭐⭐⭐⭐⭐** | 全能型，掼蛋第一 |
| GPT-4o（API） | ⭐⭐⭐⭐ | 综合最佳，掼蛋不如GLM |
| 欢乐掼蛋（规则AI） | ⭐⭐⭐⭐ | 略逊于微调GLM |

**GLM4-9B 微调后在以下游戏均第一：**
- 斗地主 ✅
- **掼蛋 ✅**
- Uno ✅
- 金拉米 ✅
- 德州扑克 ✅

### 2.3 掼蛋特殊性

> "掼蛋的对局本质上是由多个回合构成的，**获胜规则要求玩家必须从2升级到A，游戏进程较长，自然需要更多的回合**。"
> — 清华团队

**数据量：** 掼蛋和斗地主、麻将各采集 **100万训练实例**

### 2.4 大模型方案 vs 强化学习方案

| 维度 | 大模型微调（清华方案） | 强化学习（Danzero+/SDMC） |
|------|----------------------|--------------------------|
| 数据需求 | 100万轨迹 | 自对弈可生成 |
| 算力需求 | 高（需微调大模型） | 中（可小模型） |
| 配合能力 | 较好（大模型有语义理解） | 弱（无显式协同建模） |
| 拟人化 | 天然好（大模型有语言风格） | 难（过于完美） |
| 推理延迟 | 高（大模型推理慢） | 低（小模型实时） |
| 可解释性 | 中 | 高 |

**结论：大模型方案在配合+拟人化有优势，但延迟是落地难点。**

## 六、差异化机会点

基于以上分析，我们项目的差异化突破点：

```
1.【配合AI】（最大机会）
   - 现有方案均弱
   - 清华大学已验证大模型配合优于规则AI
   - 可借鉴：双LSTM共享编码 + 队友信号通道

2.【拟人化风格】（市场空白）
   - 引入"姿态出牌"惩罚，故意失误
   - 多种风格可选：稳健/激进/保守

3.【智能教学】（高需求低供给）
   - 牌局复盘 + 战术讲解
   - 错误提示 + 段位适配练习
```
