# 推送前检查指南

## 🎯 目的

确保在推送到远程仓库之前，不会意外推送大文件（模型文件、日志文件等），避免仓库大小再次超过Gitee限制。

## ✅ 当前配置状态

### .gitignore 已配置的规则

✅ **模型文件**：
- `models/**/*.pth` - 所有子目录的.pth文件
- `models/**/*.pkl` - 所有子目录的.pkl文件
- `models/**/*.h5` - 所有子目录的.h5文件
- `models/*.pth` - models根目录的.pth文件
- `models/*.pkl` - models根目录的.pkl文件
- `models/*.h5` - models根目录的.h5文件

✅ **日志文件**：
- `logs/` - 整个logs目录
- `*.log` - 所有.log文件

✅ **其他大文件目录**：
- `Testscore/` - Testscore目录
- `game_records/` - 游戏记录目录

## 🔍 推送前检查步骤

### 方法1：使用验证脚本（推荐）

```bash
python verify_gitignore.py
```

这个脚本会检查：
- ✅ 模型文件是否被忽略
- ✅ 日志文件是否被忽略
- ✅ Testscore目录是否被忽略
- ✅ 暂存区是否有大文件
- ✅ 工作区是否有未跟踪的大文件

### 方法2：使用批处理脚本（Windows）

```bash
pre_push_check.bat
```

### 方法3：手动检查

```bash
# 1. 检查暂存区
git diff --cached --name-only

# 2. 检查工作区状态
git status

# 3. 检查特定文件是否被忽略
git check-ignore -v models/some_model.pth

# 4. 检查仓库大小
git count-objects -vH
```

## ⚠️ 常见问题

### Q1: 如果发现大文件在暂存区怎么办？

**解决方法**：
```bash
# 从暂存区移除（但保留本地文件）
git reset HEAD <文件路径>

# 确认.gitignore规则正确
# 然后重新检查
python verify_gitignore.py
```

### Q2: 如果发现未跟踪的大文件未被忽略？

**解决方法**：
1. 检查文件路径是否匹配.gitignore规则
2. 更新.gitignore添加相应规则
3. 如果文件已经在Git历史中，需要清理历史（参考仓库清理报告）

### Q3: 如何确保子目录中的模型文件也被忽略？

**当前配置**：
- ✅ 已使用 `models/**/*.pth` 匹配所有子目录
- ✅ 也保留了 `models/*.pth` 匹配根目录

## 📋 推送前检查清单

在每次推送前，请确认：

- [ ] 运行 `python verify_gitignore.py` 检查通过
- [ ] `git status` 中没有大文件显示为未跟踪
- [ ] `git diff --cached` 中没有大文件在暂存区
- [ ] `.gitignore` 规则已正确配置
- [ ] 仓库大小检查：`git count-objects -vH` 显示合理大小（<500MB）
