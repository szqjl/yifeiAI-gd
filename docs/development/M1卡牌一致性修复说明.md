# M1卡牌一致性修复说明

## 修复目标

1. M1能正确获取服务器发送的卡牌信息和各家出牌信息
2. M1能正确获取自身出牌信息和剩余卡牌信息
3. 记录保存和回放系统能完整正确反映原始卡牌信息和比赛过程

## 修复内容

### 1. M1客户端手牌更新逻辑

#### 修复文件
- `src/communication/yf1_m1.py`
- `src/communication/yf2_m1.py`

#### 修复内容
1. **出牌后手牌更新**：
   - 在`handle_action_request`中，出牌后立即从`hand_cards`中移除已出的牌
   - 规范化卡牌格式，支持`["C", "8"]`格式转换为`"C8"`
   - 添加详细的验证和警告日志

2. **服务器手牌更新**：
   - 在`_handle_act_notification`中，优先使用服务器发送的最新`handCards`
   - 验证卡牌格式和数量
   - 规范化卡牌格式

3. **游戏开始时手牌收集**：
   - 从`publicInfo`中尝试获取所有玩家的手牌信息
   - 确保`all_players_hands`包含尽可能多的玩家手牌

### 2. 游戏记录器增强

#### 修复文件
- `src/communication/game_recorder.py`

#### 修复内容
1. **手牌格式验证**：
   - 在`start_game`中验证所有玩家的手牌格式
   - 统一使用字符串键（`str(pos)`）存储`all_players_hands`
   - 过滤无效卡牌格式

2. **动作规范化**：
   - 新增`_normalize_action`方法，规范化动作中的卡牌格式
   - 支持`["C", "8"]`格式转换为`"C8"`
   - 在`record_action`中自动规范化动作

3. **卡牌验证增强**：
   - `_validate_action_cards`使用字符串键查找初始手牌
   - 增强验证逻辑，提供更详细的警告信息

### 3. 回放系统修复

#### 修复文件
- `yf_replay.py`

#### 修复内容
1. **卡牌移除逻辑增强**：
   - 在`_calculate_current_hands`中规范化卡牌格式
   - 支持`["C", "8"]`格式转换为`"C8"`
   - 添加移除数量验证和警告

2. **服务器日志补充逻辑优化**：
   - 只在游戏记录中完全没有该玩家手牌时才使用服务器日志
   - 验证卡牌格式和数量（10-27张）
   - 避免服务器日志解析错误导致显示错误

## 关键改进点

### 1. 卡牌格式统一
- 所有卡牌统一为字符串格式（如`"C8"`）
- 自动转换`["C", "8"]`格式为`"C8"`
- 过滤无效卡牌格式

### 2. 手牌键类型统一
- `all_players_hands`统一使用字符串键（`"0"`, `"1"`, `"2"`, `"3"`）
- 确保验证逻辑能正确查找手牌

### 3. 验证和日志增强
- 添加详细的卡牌验证日志
- 手牌更新时记录变更信息
- 卡牌移除时验证数量匹配

### 4. 数据来源优先级
1. **游戏记录中的手牌**（最高优先级）
2. **服务器发送的`handCards`**
3. **服务器日志**（仅在完全没有时才使用）

## 测试建议

1. **运行游戏测试**：
   - 运行`START_M1_GUI.bat`或直接运行`yf1_m1.py`和`yf2_m1.py`
   - 观察日志中的手牌更新信息
   - 检查是否有卡牌验证警告

2. **回放测试**：
   - 使用`yf_replay.bat`回放游戏记录
   - 验证回放系统显示的手牌是否正确
   - 检查是否有卡牌移除警告

3. **卡牌一致性检查**：
   - 使用`src/tools/check_card_consistency.py`检查游戏记录
   - 验证所有动作中的卡牌都在初始手牌中

## 预期效果

1. ✅ M1客户端能正确获取和更新手牌
2. ✅ 游戏记录能完整保存所有玩家的手牌信息
3. ✅ 回放系统能正确显示卡牌，不会出现C8显示为D8的问题
4. ✅ 卡牌验证能及时发现服务器发牌错误

## 注意事项

1. **服务器日志补充**：如果游戏记录中已有手牌，不会使用服务器日志，避免解析错误
2. **卡牌格式转换**：自动处理多种卡牌格式，确保一致性
3. **验证日志**：如果出现卡牌不一致，会记录详细警告，便于调试
