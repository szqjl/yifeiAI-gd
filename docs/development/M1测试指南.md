# M1 测试指南

## 📋 概述

本文档说明如何测试 M1 系列硬编码规则引擎。

**重要说明**：M1 不是机器学习模型，而是硬编码规则引擎，基于阶段细分路由的决策系统。

## 🎮 测试方法

### 方法一：GUI批量测试（推荐，最简单）

#### 前置条件

1. **启动游戏服务器**
   - 运行掼蛋游戏服务器（本地或局域网）
   - 服务器地址：`ws://127.0.0.1:23456` 或 `ws://[局域网IP]:23456`

2. **准备测试环境**
   - Python 3.8+
   - 已安装依赖：`pip install -r requirements.txt`
   - 已切换到 `m1-dev` 分支

#### 测试步骤

**步骤1：启动M1测试GUI**

```bash
# 方式1：双击运行（Windows）
START_M1_GUI.bat

# 方式2：命令行运行
python batch_executor_gui_m1.py
```

**步骤2：配置参数**

在GUI界面中：
1. **目标场数**：输入要测试的场数（如：10场）
2. **服务器路径**：点击"浏览..."选择服务器可执行文件
3. **客户端脚本**：默认已配置为M1客户端（会自动检测）
   - `src/communication/yf1_m1.py` (Player 0)
   - `src/communication/run_lalala_client3.py` (Player 1)
   - `src/communication/yf2_m1.py` (Player 2)
   - `src/communication/run_lalala_client4.py` (Player 3)

**步骤3：开始测试**

1. 点击"▶ 开始执行"按钮
2. 观察进度条和日志输出
3. 等待测试完成或点击"停止"

#### GUI界面说明

- **配置参数区域**：设置目标场数、服务器路径、客户端脚本
- **控制按钮**：开始执行、停止、清空日志
- **执行状态区域**：显示进度条、已完成场数、重启次数、战绩
- **执行日志区域**：实时显示执行日志

#### 预期输出

GUI界面会显示：
- ✅ 执行进度（已完成/目标场数）
- ✅ 实时日志（INFO/WARNING/ERROR）
- ✅ 战绩统计（胜场-负场）
- ✅ 胜率计算

## 🐛 常见问题

### Q1: 连接失败

**症状**：客户端无法连接到服务器

**解决方法**：
1. 检查服务器是否启动
2. 检查服务器地址是否正确（`ws://127.0.0.1:23456`）
3. 检查防火墙设置
4. 查看日志文件中的错误信息

### Q2: 策略引擎未加载

**症状**：日志显示 "⚠️ Missing: TeammateProtection"

**解决方法**：
1. 检查 `src/decision/strategy_engine.py` 是否存在
2. 检查导入路径是否正确
3. 查看日志中的详细错误信息

### Q3: 决策超时

**症状**：决策时间过长，超过1秒

**解决方法**：
1. 检查是否有性能瓶颈
2. 查看日志中的决策时间统计
3. 优化慢速代码路径

### Q4: 阶段路由错误

**症状**：使用了错误的阶段处理器

**解决方法**：
1. 检查剩余牌数计算是否正确
2. 检查 `StageRouter._get_game_phase()` 方法
3. 查看日志中的阶段信息

## 🎯 测试建议

### 渐进式测试

1. **第一步**：单客户端测试（只启动一个客户端，观察连接和初始化）
2. **第二步**：双客户端测试（启动两个M1客户端，观察对局）
3. **第三步**：完整对局测试（4人完整对局，观察决策质量）

### 重点测试场景

1. **开局阶段**：观察是否使用 `OpeningActiveHandler`
2. **残局阶段**：观察是否使用 `EndgameLateHandler`
3. **队友保护**：观察队友出牌时是否PASS
4. **一手出完**：观察是否能识别并优先选择
