## 🔴 Top 3 - 立即要回答的问题

### 问题 1：M1 队胜率为什么始终为 0%？

**表象**：
- 70+ 局对 lalala
- 改动 50+ 处代码
- PASS 率从 60%↓到 50%、近似问题 PASS 从 13↓到 1
- **但队胜率 0% 始终不动**

**根因假设**：
1. 主被动分界判断失准 → 导致应该主动出牌却被判被动
2. 拆牌方案本质错误 → 即使不 PASS，出牌顺序也不合理
3. 队友保护逻辑过度保守 → 对手冲关时无脑让牌
4. **没有主动进攻路线** → 只会被动接牌，不会规划"我方来进攻"
5. **残局处理失策** → 最后 10 张牌分配与时机错误

**现象支持**：
- PASS 率虽然降到 50~60%，但关键是"出牌质量"
- 改了五轮参数与规则，胜率纹丝不动 → **不是细节问题，是架构问题**

**新假设（来自 M3 诊断）**：
✅ **缺乏 Lv2（队伙联动）与队伙协作所需的信息**
- 无法追踪对手/队友出过什么牌（缺 history）
- 无法做"两手恰好出完"的残局规划（缺两手分析）
- 无法主动为队友传牌（缺队伙意识）

### 问题 2：为什么 PHASE2-001～005 改了 50+ 处代码，胜率反而未动？

**改动清单**：
- PHASE2-001：choose_bomb 优化
- PHASE2-003：拆牌优先级（rank 计数、Trips 降权）
- PHASE2-004：队级进攻（TeamOffensiveStrategy）
- PHASE2-005：清 yf2 近似 PASS（接风判主动、coerce 兜底）

**观察**：
- 单项指标改善了（PASS 率↓、近似问题 PASS↓）
- **但团队整体胜率 = 0% 始终不变**

**假设**：
1. 这些改动解决的是"局部局面"问题，而真正的胜率取决于"全局队伍配合"
2. 即使每个决策都对，但决策的"顺序"和"时序"与 lalala 不匹配
3. 改的都是 **Lv1（个别决策）**，没改 **Lv2（队伙联动）**

**为什么 PHASE2-003 反而拉高近似 PASS？**

```
PHASE2-003 改拆牌优先级
  → 导致"哪个牌型应该优先出"重新调整
  → 但这只改了"单个决策"，没改"两手规划"
  → 结果：某些牌型虽然优先了，但最后仍无法出完
  → 反而暴露出"缺乏残局规划"的问题
  → 近似 PASS（有选择却最后 PASS）增加了
```

### 问题 3：M2 的 Bug 5「极端被动」是否为另一条路的启示？

**M2 现象**：
- 修完 Bug 1～4 后，yf2_m2 仍 **60% PASS**（M1 yf2 是 56%）
- 一旦有非 PASS 动作，全是小单/小对 → 对手秒压 → 继续 PASS

**M1 类似现象**：
- M1 也有"找不到更高牌就 PASS"的逻辑
- M1 主动决策：`_first_non_pass_index` → 出第一张 → 往往是小牌

**假设**：
- **M1 与 M2 都陷入了同一个"局部优化陷阱"**
- 个别动作逻辑没错，但全局缺乏进攻规划
- lalala 的赢点不在"单次决策对不对"，而在"打法风格"（激进进攻 vs 保守跟牌）

**启示**：
- M1 是否也需要 M2 Step 3 的改造（赋予主动进攻能力）？
- "拆三张引诱对手、送队友配合"应该在 **5 阶段路由上层就规划**，不是细节补丁
- 能否从 lalala 的决策记录反向工程其"进攻模板"？

## 🟡 关键技术问题

### 问题 4：为什么 PHASE2-003 拆牌优先级改动后，近似 PASS 反而增加？

**数据对比**：
- PHASE2-002 后：yf2 近似 PASS = 0（新样 3 局）
- PHASE2-003（拆牌优先）：yf2 近似 PASS = 9（**跳升**）
- PHASE2-004（队级进攻）：yf2 近似 PASS = 8
- PHASE2-005（清近似）：yf2 近似 PASS = 1

**问题点**：
- 拆牌优先级为什么反而导致**更多的问题 PASS**？
- 是不是"拆三张"的逻辑**过度**激发了，导致无其他合法选项，只能 PASS？

**关键问题**：
- PHASE2-003 的改动是否正确？还是"为了消除 PASS"反而制造了新的死路？
- 是否应该回溯到 PHASE2-002，用"保守的拆牌"配合更激进的队伙进攻？

### 问题 5：10 局样本是否足够代表性？

**当前做法**：
- 每轮改动后跑 ≥10 对（20 局）
- 用 `victoryNum` 和 PASS 率作为评测指标

**问题**：
- 掼蛋的随机性（洗牌、出牌顺序）很高，10 局是否足以排除统计噪声？
- lalala 是否是"真随机对手"还是"伪随机"（固定种子、预定义出牌）？
- 如果 lalala 有特定的出牌偏好，10 局可能无法覆盖

**假设**：
- M1 对某些特定牌型组合有克制（或被克制），导致同对手不同阵容时差异大
- 应该跑 50～100 局才能看到真实的胜率分布

**关键问题**：
- 能否对 lalala 进行"打样"（跑 100+ 局）来计算其真实胜率，作为 M1 的对标？
- M1 的胜率下限是否真的是 0%（运气因素），还是存在某个"最优解胜率"（如 30% 或 45%）？
- 是否应该换对手测试（比如对自己、对 V5 等）来隔离 lalala 的影响？

### 问题 6：5 阶段路由是否已经耗尽 hard-coded 的潜力？

**当前 5 阶段**：
1. Opening（开局）
2. Mid-Early（中局前期）
3. Mid-Late（中局后期）
4. Endgame-Early（残局前期）
5. Endgame-Late（残局后期）

**疑问**：
- 这 5 个阶段是否真的各有**本质不同的决策逻辑**？
- 还是只是"参数不同"（阈值、权重）？
- 如果只是参数不同，为什么不用单一的"综合评分器"而非 5 个处理器？

**假设**：
- 真正的差异不在"阶段分界"，而在"游戏状态全景视图"
- 或许应该用**决策树**（if-then-else）而非**参数调优**

**关键问题**：
- hard-coded 能否满足掼蛋的复杂性？还是天然应该用强化学习？
- 为什么 RL 线（Stage 7、GUA-016/017）始终未通过，hard-coded 也卡在 0%？
- 是否应该混合：hard-coded 用于"明确规则"，RL 用于"策略选择"？

### 问题 7：为什么 yf1_m1 与 yf2_m1 的差异（表面无关键差）但决策质量不同？

**GUA-020 结论**：
- 10 局成对样本，PASS 率差 0.92%（54.78% vs 55.70%）
- "无明显一方更差"

**但 ITERATIONS 显示**：
- yf2 近似 PASS 总是偏多（13 vs 7、10 vs 7 等）
- 在不同改动轮次中，yf2 的波动更大

**假设**：
- yf1 与 yf2 的客户端逻辑**确实相同**（共用 `src/decision/`）
- 差异来自于**座位位置的自然差异**（P0 vs P2 在对手压力、队友出牌时序上的差异）

**关键问题**：
- yf1 vs yf2 的差异，是否反映了"座位位置本身的隐性难度差异"？
- 是否应该针对座位位置有不同的策略参数？
- 为什么高手或平台上的 AI 没有这种 yf1/yf2 的不对称性？

## 🟢 工程与流程问题

### 问题 9：为什么项目依赖「人类本机跑局」而无法完全自动化？

**当前流程**：
- Opencode/Cursor 改代码
- 自动化测试通过（19 passed）
- **然后卡住** → 需要人类本机跑 10～50 局
- 人类手工统计、填表、回填 ITERATIONS

**问题**：
- 导致反馈延迟（可能数小时或数天）
- 难以快速迭代（无法一天跑 10 个版本）
- 容易出人工失误（填错数据）

**为什么无法自动化**：
- 离线服务器需要本机 Windows
- 或平台有 rate limit

**关键问题**：
- 能否搭建一个"云评测环境"？
- 能否用"评测镜像"（Docker）来标准化环境？
- 平台是否有 API 来远程提交对局？

### 问题 10：Hermes + Opencode-eng + Kanban 多 Agent 协作为什么卡住（GUA-023）？

**架构**：
- Hermes 总协调 ← 分配任务
- Kanban 看板 ← 任务队列
- opencode-eng 编码 worker ← 执行任务

**问题**：
- opencode-eng 无法收到 tool calls
- 导致 0 tool calls → worker 未 `kanban_complete` 即退出
- 任务卡死

**根因**：
- copilot-acp bridge 与 Kanban worker 不兼容

**关键问题**：
- 多 Agent 协作的真实收益是什么？
- 是否值得修复 GUA-023，还是应该回到"人类手工分派"？
- 如果多 Agent 修不好，是否应该放弃 Kanban 而直接用"对话流"？
