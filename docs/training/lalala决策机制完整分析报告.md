- ✅ **信息提取集中**: 在入口处统一提取关键信息

**关键策略**:

- 统一提取所有玩家的剩余牌数

**对YF的启示**:

### 3. active() - 主动出牌

- ✅ **特殊情况处理**: 下家只剩1张时的特殊策略

**关键策略**:

3. **优先级顺序**: 单张（小）→ 三连对/钢板 → 顺子 → 三带二 → 三张 → 对子 → 单张

## 💡 关键策略总结

### 1. 架构设计

**lalala的架构**:
```
rule_parse() → passive()/active() → 牌型专门方法
```

**特点**:
- 简单直接，没有复杂的多层架构
- 清晰的阶段分离
- 每种牌型有专门的处理方法

**YF当前架构**:
```
decide() → 多层评估 → 候选生成 → 知识增强 → 最终选择
```

**问题**:
- 过于复杂，可能相互抵消
- 没有明确的阶段分离
- 没有针对每种牌型的专门策略

### 2. 残局处理

**lalala的策略**:
- 当剩余牌数≤10时，进入残局模式
- 使用专门的残局处理函数`one_hand()`
- 残局策略优先级最高

**YF的缺失**:
- 没有残局专门处理
- 残局时使用常规策略，可能不够优化

### 3. 手牌结构分析

**lalala的策略**:
- 详细分析手牌结构，识别各种牌型成员
- 避免破坏有价值的组合（对子、三张、炸弹、顺子）
- 使用`combine_handcards()`提取所有牌型

**YF的缺失**:
- 手牌结构分析不够深入
- 可能破坏有价值的组合

### 4. 保护队友逻辑

**lalala的策略**:
- 如果队友是最大动作者，且当前牌值很大，选择PASS
- 如果队友剩余牌数≤4，只出比当前牌大1的牌
- 多种情况下的队友保护策略

**YF的缺失**:
- 保护队友逻辑不够明确
- 可能误伤队友

### 5. 优先级系统

**lalala的策略**:
- 主动出牌：一手出完 → 两手出完 → 单张（小）→ 三连对/钢板 → 顺子 → 三带二 → 三张 → 对子 → 单张
- 被动出牌：单张成员 + 大牌值 → 非炸弹成员 + 大牌值 → 放宽条件 → 使用等级牌 → 使用炸弹

**YF的缺失**:
- 没有明确的优先级系统
- 使用多因素评估，可能不够清晰

### 6. 特殊情况处理

**lalala的策略**:
- 下家只剩1张：不出小单张，优先出多张牌
- PASS次数过多：使用special策略或考虑使用炸弹
- 残局：使用专门策略

**YF的缺失**:
- 特殊情况处理不够完善
- 可能错过关键决策时机
