# 客户端位置分配说明

## 位置分配规则

服务器根据**客户端连接顺序**分配位置：
- **第1个连接** → 0号位
- **第2个连接** → 1号位
- **第3个连接** → 2号位
- **第4个连接** → 3号位

## 队伍分配

- **Team A（一队）**：0号位 + 2号位
- **Team B（二队）**：1号位 + 3号位

## 目标配置

为了确保M1和M2组成一队：
- **0号位**：yf1_m1 (M1) - Team A
- **1号位**：run_lalala_client3 (client3) - Team B
- **2号位**：yf2_m1 (M2) - Team A
- **3号位**：run_lalala_client4 (client4) - Team B

## 客户端连接延迟

各客户端有内置延迟，用于确保连接顺序：

| 客户端 | 延迟时间 | 说明 |
|--------|---------|------|
| yf1_m1.py | 3秒 | 确保第1个连接（0号位） |
| yf2_m1.py | 9秒 | 确保第3个连接（2号位） |
| run_lalala_client3.py | 8秒 | 确保第2个连接（1号位） |
| run_lalala_client4.py | 18秒 | 确保第4个连接（3号位） |

## 启动顺序分析

batch_executor按以下顺序启动客户端（每个间隔3秒）：

1. **t=0秒**：启动 yf1_m1.py
   - 延迟3秒后连接 → **t=3秒连接** → **0号位** ✅

2. **t=3秒**：启动 yf2_m1.py
   - 延迟9秒后连接 → **t=12秒连接** → **2号位** ✅

3. **t=6秒**：启动 run_lalala_client3.py
   - 延迟8秒后连接 → **t=14秒连接** → **1号位** ❌ **错误！应该是第2个连接**

4. **t=9秒**：启动 run_lalala_client4.py
   - 延迟18秒后连接 → **t=27秒连接** → **3号位** ✅

## 问题

当前配置会导致：
- yf1_m1 → 0号位 ✅
- yf2_m1 → 2号位 ✅（但连接时间晚于client3）
- client3 → 1号位 ✅（但连接时间晚于yf2_m1）
- client4 → 3号位 ✅

**实际连接顺序**：
1. t=3秒：yf1_m1 → 0号位 ✅
2. t=12秒：yf2_m1 → 2号位 ✅
3. t=14秒：client3 → 1号位 ✅
4. t=27秒：client4 → 3号位 ✅

## 解决方案

需要调整 `auto_game_runner.py` 中的客户端顺序：

```python
client1: "src/communication/yf1_m1.py",  # 0号位
client2: "src/communication/run_lalala_client3.py",  # 1号位
client3: "src/communication/yf2_m1.py",  # 2号位
client4: "src/communication/run_lalala_client4.py"  # 3号位
```

这样batch_executor的启动顺序会确保：
1. yf1_m1 (延迟3秒) → 第1个连接 → 0号位 ✅
2. client3 (延迟8秒) → 第2个连接 → 1号位 ✅
3. yf2_m1 (延迟9秒) → 第3个连接 → 2号位 ✅
4. client4 (延迟18秒) → 第4个连接 → 3号位 ✅

## 服务器信息捕获

batch_executor会捕获以下服务器信息：
1. 服务器启动输出
2. 游戏开始信号
3. 游戏结束信号
4. **战绩信息**：格式为"达到设定场次, 其中0号位胜利X次，1号位胜利Y次，2号位胜利Z次，3号位胜利W次"
5. 各位置胜利次数统计

工作流（auto_game_runner）会：
- 调用batch_executor运行游戏
- 检查游戏记录数量变化
- **尝试从输出中提取服务器战绩信息**
- 返回运行结果（成功/失败，新增游戏数，服务器信息）

## 验证方法

运行检查脚本：
```bash
python scripts/checks/check_client_positions.py
```

查看batch_executor日志中的服务器输出，确认：
- 各客户端连接顺序
- 各位置胜利次数
- Team A和Team B的胜率
