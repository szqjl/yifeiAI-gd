## 概述

M2 是基于硬编码精确规则（lalala风格）的掼蛋AI决策引擎，与M1的核心区别是去掉分数累积+阈值队友保护，采用内联if-then精确控制。

**目标**：突破70+局0%的队胜率。

**架构**：`RuleBasedDecisionEngineM2` → `StageRouter` → 10个M2专用阶段处理器（`phase_handlers_m2.py`）

### Bug 4 (关键): 炸弹滥用 — 所有处理器无条件选择炸弹 (已修 2026-05-26)

**问题**：`M2OpeningActiveHandler`、`M2OpeningPassiveHandler`、`M2MidEarlyActiveHandler` 等所有阶段处理器在主动/被动出牌时，都通过 `_first_non_pass_index` 不加过滤地选择第一个非PASS动作，而服务端 `action_list` 的排列顺序是 **Bomb > PASS**，导致：

- 主动出牌：第一动就炸自己（yf2_m2 开局 Bomb Q）
- 被动出牌：压对手单张4也炸
- 后果：开局耗光炸弹 > 没大牌 > 出小单张送牌权 > 关键时刻无炸弹可用 > 0%头游

**证据**（第1局游戏记录）：

yf2_m2（P2）决策序列：
```
1. Bomb Q    ← 第一动就炸！浪费4张Q
2. Single 7  ← 炸完出小单
3. Bomb A    ← 第三动又炸！最大炸弹浪费
4-17: ThreeWithTwo J → Single K → Single 4 → Trips 5 → Trips 8 → PASSx3
```

yf1_m2（P0）决策序列：
```
1. Straight 6  ✓
2. ThreeWithTwo 7 ✓
3. Bomb J      ❌ 自己出牌中，炸自己？
4. Single 4    ← 炸完出最小单
5-18: Pair K → Single A → Single R → PASSx6
```

**修复** (2026-05-26)：

| 修改位置 | 改动 |
|---------|------|
| `stage_router.py` | 新增 `_first_non_bomb_index()` 主动出牌跳过炸弹 |
| `stage_router.py` | 新增 `_should_use_bomb_passive()` 判定被动炸弹价值 |
| `M2OpeningActiveHandler.handle()` | 改为 `_first_non_bomb_index` |
| `M2OpeningPassiveHandler` | `_single_passive` / `_pair_passive` / `_other_passive` 全面重写 |
| `M2MidEarlyActiveHandler.handle()` | 改为 `_first_non_bomb_index` |
| `M2MidLateActiveHandler.handle()` | 改为 `_first_non_bomb_index` |
| `M2EndgameEarlyActiveHandler.handle()` | 手牌≤6时允许炸弹冲刺 |
| `M2MidEarlyPassiveHandler._default_passive_action` | 跳过炸弹 |

**新策略原则**：
- 炸弹是防守武器，不是进攻开牌
- 只有高价值场景才用炸弹：对手≤3张、当前牌≥A、连续PASS≥4次、保护残血队友
- 中局及之前主动出牌永远不用炸弹
- 残局手牌≤6时允许炸弹冲刺

### Bug 5 (真正根因): 极端被动 — 无法主动组织进攻 (已定位 2026-05-26)

**问题**：炸弹修复后跑分结果仍为 [0, 3, 0, 3]，0%胜率不变。分析新版游戏记录发现：

| 指标 | yf1_m2 (P0) | yf2_m2 (P2) | 对手 (P1+P3) |
|------|------------|------------|-------------|
| 出牌/总决策 | 14/25 (56%) | 9/25 (36%) | 主动进攻 |
| PASS率 | 40% | **60%** | 低 |
| 平均每局出牌数 | 14 | **9** | 高 |

yf2_m2 **60%时间在PASS**，出牌全是单张/对子等无威胁牌型。对手在组织ThreeWithTwo链、顺子链等主动进攻时，M2全程PASS旁观。

**根因链路**：
1. `M2OpeningPassiveHandler._single_passive()` 找不到更高单张时 → `return 0` (PASS)
2. `M2OpeningPassiveHandler._pair_passive()` 找不到更高对子时 → `return 0` (PASS)
3. `M2OpeningPassiveHandler._other_passive()` 找不到更高同类型时 → `return 0` (PASS)
4. 所有主动处理器（`M2OpeningActiveHandler`等）只会出第一张非炸弹牌 → 出小单/小对 → 对手轻松压住 → M2继续PASS循环
5. **M2完全没有主动进攻路线规划**，没有拆牌策略、引诱策略、送队友概念

**修复**：暂未修复。这需要整体重构出牌策略。

## 炸弹策略对照检查 (`docs/skill/出炸弹要领.txt`)

`docs/skill/出炸弹要领.txt` 是掼蛋的完整炸弹使用指南，涵盖6节202条规则。当前M2的炸弹逻辑对比：

| 分类 | 规则数量 | M2已实现 | 实现率 | 状态 |
|------|---------|---------|--------|------|
| 第一节：配炸技巧 | ~7条 | 0 | 0% | ❌ 完全未实现 |
| 第二节：炸什么牌 | ~6条 | 0 | 0% | ❌ 完全未实现 |
| 第三节：出炸时机 | ~22条 (炸点6+主动6+被动5+不宜6) | ~5条 | ~23% | ⚠️ 部分实现 |
| 第四节：如何用炸 | ~6条 | 0 | 0% | ❌ 完全未实现 |
| 第五节：残局用炸 | ~20条 (逼炸5+骗炸7+闯关5+阻敌20+送搭档2) | ~3条 | ~15% | ⚠️ 部分实现 |
| 第六节：错误用炸 | ~15条 | 0 | 0% | ❌ 完全未实现 |

### 未实现的关键规则

**第三节·炸点**（完全不用的8个炸点）：
1. 预判对手出的牌型会对我方非常不利时 — 应炸
2. 对手牌型已打完 — 应炸后出自己小牌
3. 对手要处理困难牌 — 应炸控制
4. 炸忍耐者 — 对方忍了很久终于出炸，直接盖过
5. 炸敌方主攻 — 不炸助攻
6. 牌型明朗时 — 弄清牌型后及时出炸
7. 对手即将听牌 — 保证对手"听不了牌"
8. 对手再出一手争头游 — 及时动炸

**第三节·不宜出炸**（M2违反最多的规则）：
1. ❌ **牌型不明时不出炸** — M2在开局牌型完全不明时就炸
2. ❌ **明知炸了走不了不出炸** — M2炸完不知道出什么
3. ❌ **对手牌型不是到顶牌点，不是守底者一般不要先炸** — M2乱炸低价值牌
4. ❌ **不能准确判断谁是主攻者，不要急于开炸**

**第五节·残局牌数原则**：
- 敌剩4张：一般不炸（炸不打四）
- 敌剩5张：一般要炸（逢5出对）
- 敌剩6张：钢板要炸
- 这些完全未实现

### 结论

出炸弹要领中的约76条规则中，M2实际只实现了约8条（10%），且实现的不够精确。文档中的规则是掼蛋牌手经验的系统化总结，应该作为M2炸弹策略的完整规范。

- 炸弹使用时机（第几动、主动/被动、当前牌值）
